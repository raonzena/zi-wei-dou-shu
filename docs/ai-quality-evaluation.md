# AI 해석 평가 기준과 실행 방법

- 버전: ai-quality-v1
- 적용 범위: user-consultation-v6 이후의 서버 계산 요약·11개 AI 단계·필수 월별 객체
- 목적: 계산 근거에 충실하고 누락 없이 이해할 수 있는 설명을 검증한다. 점술의 예측 능력을 검증하는 기준이 아니다.

## 고정 사례

실제 사용자 입력 대신 저장소의 합성 입력만 사용한다. 기준 시각도 고정한다.

| ID              | 구분                                 | 반드시 확인할 조건                                                    |
| --------------- | ------------------------------------ | --------------------------------------------------------------------- |
| reference       | 기존 독립 기준 명반에 맞춘 한국 입력 | 2026년 12개월, 사 명궁 무곡·파군, 무곡 화록 자화, 격국 두 구조 불일치 |
| leap            | 같은 명반의 2025년 운한              | 윤6월 1~~15일·16~~29일 포함 14구간                                    |
| late-rat        | 23시 출생                            | 2025년 윤달 두 구간, 본명반과 운한의 23시 정책 혼동 없음              |
| empty-soul      | 2000-01-01 02:00 합성 입력           | 해 명궁 주성 없음, 주성이나 차성을 임의로 만들지 않음                 |
| zi-fu-tong-gong | 2000-01-04 08:00 합성 입력           | 신 명궁 자미·천부 배치 일치, 성패 확정 없음                           |
| zi-fu-jia-ming  | 2000-01-03 20:00 합성 입력           | 인 명궁 천기·태음, 양옆 자미·천부 조건 일치                           |

격국·운한 확장 사례는 현재 엔진과 명시한 규칙의 회귀 사례다. 모든 확장 기능을 독립된 전문가 명반과 대조했다는 뜻은 아니다.

## 자동 검사 — 모두 통과해야 표시 가능

- sections는 2~12단계를 순서대로 포함하고 각 단계의 해석은 비어 있지 않다.
- monthly는 계산된 모든 평달·윤달 구간을 필수 키로 포함한다. 다른 키·날짜·제목 필드를 허용하지 않는다.
- 각 월의 문장은 비어 있지 않다. 키 순서는 신뢰하지 않고 서버의 구간 순서로 표시한다.
- 근거는 서버가 제공한 ID만 사용하고 한 문단 안의 중복을 거부한다. 3·10단계는 대한, 11단계는 올해 유년 근거가 필요하다.
- 내부 ID가 본문에 노출되거나 관찰된 유월 근거 부재 모순이 재현되면 거부한다. 이 문구 검사는 일반적인 의미 검증이 아니다.
- 월별 해석의 완전 중복은 검토 경고로 남긴다. 동일한 조언이 정당할 수도 있어 이것만으로 생산 응답을 거부하지 않는다.
- 오류·거부·중단된 응답은 성공으로 표시하지 않는다. 자동 유료 재시도는 하지 않는다.

## 내용 검토 — 자동 통과와 별도

각 항목을 0~2점으로 기록하고 문제가 있는 문장·근거·수정 방향을 함께 남긴다. 사람의 검토가 없으면 미검토 상태다. Codex의 읽기 검토는 보조 검토로 기록하며 전문가 판정으로 취급하지 않는다.

| 항목          | 0점                                   | 1점                              | 2점                                   |
| ------------- | ------------------------------------- | -------------------------------- | ------------------------------------- |
| 근거 충실도   | 궁·별·사화·시기를 잘못 사용함         | 연결이 모호하거나 일부 근거 부족 | 주요 해석이 해당 근거와 연결됨        |
| 일관성        | 앞뒤 모순·자료 부재 오인              | 표현이 혼동을 줄 수 있음         | 계산 기준과 단계 간 설명이 일관됨     |
| 월별 구체성   | 다른 월을 설명하거나 사실상 누락      | 일반론 위주                      | 해당 구간의 근거와 점검 내용이 구분됨 |
| 반복          | 같은 설명을 대부분 반복               | 일부 불필요한 반복               | 공통점과 차이점을 간결히 설명함       |
| 한국어 가독성 | 내부 코드·외국어·이해하기 어려운 문장 | 설명 부족·어색한 용어            | 일반 사용자가 읽을 수 있는 존댓말     |
| 단정 억제     | 질병·수명·수익·혼인 등 사건을 확정    | 가능성과 확정을 혼동             | 전통 해석과 확인할 행동을 구분함      |

제안 출시 기준: 고정 사례 모두 자동 검사 통과, 실제 응답별 총점 10/12 이상, 근거 충실도·일관성·단정 억제는 각각 2점. 중요한 계산 사실 오류 또는 월 누락은 총점과 무관하게 실패다. 한 사례 한 번 성공만으로 전체 품질을 확정하지 않는다. 이 기준은 팀의 사람 검토를 거쳐 조정할 수 있다.

## 실행과 비용 관리

외부 호출 없이 계약·근거와 고정 사례를 검사한다.

```sh
pnpm test:ai
```

실호출은 아래처럼 명시적으로 켜고 한 사례만 지정한다. .env.local의 서버 전용 키를 사용한다. 실행 한 번당 외부 요청은 최대 1회이며, 일반 pnpm test와 pnpm eval:ai는 유료 검사를 건너뛴다.

```sh
ZIWEI_LIVE_EVAL=1 ZIWEI_EVAL_CASE=reference pnpm eval:ai
```

모델·프롬프트 버전·사례·토큰 사용량·지연·구조 검사·응답은 gitignore된 work/ai-evaluations에 저장한다. API 키와 요청 헤더는 기록하지 않는다. 실제 사용자 데이터를 이 도구에 추가하지 않는다. 결과의 semanticReview는 pending으로 시작한다. 구조 검사 실패는 이미 받은 응답으로 재현하고, 수정 검증에 필요한 경우에만 추가 요청한다. 모델 비교·AI 심사자 자동 호출은 이번 범위에 포함하지 않는다.
