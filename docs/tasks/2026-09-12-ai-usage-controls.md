# AI 일시 중지와 호출 운영 제어

- 작성일·최종 갱신일: 2026-09-12
- 상태: 운영 AI 중지 배포 완료. 호출 제어 로컬 구현·검증 완료, 운영 Supabase 연결 대기.

## 작업 개요

사용자 요청에 따라 운영의 `AI_EXPLANATION_ENABLED=false`를 먼저 배포했다. 다음으로 AI 요청의 중복·과도한 호출을 막고, 생성 시간·실패·토큰 사용량·추정 비용을 확인할 수 있도록 한다. 실제 AI 호출은 하지 않는다.

## 요구사항

[운영·접근성 기준](../requirements.md#5-운영접근성-기준)의 중복 방지, 호출 제한, 비용·실패 관측과 REQ-01의 입력 시점 안내를 다룬다. AI를 중지해도 입력·명반 계산·기본 풀이를 제공해야 한다. 결과 저장·공유는 이번 작업에 포함하지 않는다.

## 결정과 근거

- Vercel 인스턴스마다 따로 보관하는 카운터는 전체 한도를 지키지 못한다. 이미 설치한 Supabase SDK와 PostgreSQL RPC를 사용하고, 짧은 트랜잭션의 advisory lock으로 조회·예약·정산을 직렬화한다. AI 응답을 기다리는 동안 DB 잠금을 유지하지 않는다.
- 초기값은 접속 IP당 최근 1시간 3회, 서비스 전체 한국 날짜 기준 하루 20회, 하루 추정 비용 2달러다. 같은 IP에서 같은 명반·모델·프롬프트 버전으로 재요청하면 10분 동안 차단한다. 예약에 성공한 실패 요청도 횟수에 포함한다.
- 요청을 허용할 때 40센트를 먼저 예약한다. mini의 확인된 입력 한도와 출력 16,000토큰 및 가격을 고려한 보수적 값이다. 확인된 토큰 사용량으로 정산하며, 연결 중단·시간 초과·기록 실패 등으로 비용을 알 수 없으면 예약액을 유지한다. 동시 요청 5건만으로 기본 예산을 예약할 수 있고, 정산 후 남은 예산이 있으면 추가 요청을 허용한다.
- 가격은 `gpt-5.4-mini-2026-03-17`의 입력 100만 토큰당 $0.75, 캐시 입력 $0.075, 출력 $4.50을 적용한다. 소수 마이크로달러는 올림한다. 모델·가격·출력 한도를 바꿀 때 SQL의 모델 허용값·예약액과 TypeScript의 비용식을 함께 검토해야 한다. 이 예산은 앱의 추정 사용량 제어이며 OpenAI 계정의 청구 상한이 아니다.
- Vercel에서는 플랫폼의 `x-vercel-forwarded-for`만 사용한다. 헤더가 없거나 유효한 IP가 아니면 호출하지 않는다. 로컬 개발은 하나의 공통 식별값을 사용한다. IP는 사용자 신원을 보장하지 않으므로 공유 네트워크의 사용자가 한도를 함께 쓰거나, 주소 변경으로 IP별 제한을 벗어날 수 있다. 전체 예산·횟수 제한은 별도로 유지한다.
- IP·명반을 서버 비밀키의 HMAC으로 변환한다. DB에는 식별값과 운영 수치만 저장하고 원본 IP·생년월일·명반·해석은 저장하지 않는다. 일반 로그에는 식별 해시도 남기지 않는다. 해시는 완전한 익명 정보로 간주하지 않는다.
- `ai_private.requests`는 비공개 스키마·RLS로 보호한다. anon/authenticated는 표·RPC에 접근하지 못한다. service_role은 제한된 `security definer` RPC만 호출하며, 함수의 search_path를 비워 둔다.
- 30일이 지난 운영 기록은 pg_cron으로 매일 삭제한다. AI를 중지해도 삭제 작업은 계속 돈다. 삭제 주기 때문에 실제 보관은 최대 약 31일이다. 로그 보관은 Vercel의 별도 정책을 따르며 로그에 IP·명반·해석을 넣지 않는다.
- DB·키·한도 설정에 문제가 있으면 AI를 호출하지 않고 기본 풀이를 반환한다. 유효한 결과를 받았지만 정산이 실패한 경우 결과는 전달하고 예약액은 유지한다.

## 변경 내용과 영향

- `request.server.ts`: 플래그·설정 확인 → 원자적 예약 → 생성 → 운영 로그·정산을 연결한다. 계산 액션은 이 경로를 사용한다.
- `controls/`: IP 처리, HMAC, Supabase RPC, 사용량 검증과 비용 계산을 분리한다.
- `explain.server.ts`: SDK가 반환한 사용량을 전달한다. 의미 검증 실패도 확인된 비용에 포함한다.
- `supabase/migrations/20260912000000_ai_usage_controls.sql`: 운영 기록·예약·정산·집계·자동 삭제를 만든다.
- `pnpm report:ai`: 최근 30일의 날짜·모델·프롬프트 버전별 시도·완료·검증 실패·타임아웃·제공자 오류·미정산 건수와 완료율·실패율, 평균·p95 생성 시간, 토큰과 전체·건당 평균 추정 비용을 출력한다. 사용량이 없는 건은 비용 평균에서 제외하고 별도 집계한다. 거절 요청은 Vercel의 `ai_admission` 로그에서 확인한다. 자동 경보는 아직 없다.
- `pnpm test:ai-db`: 다른 프로젝트 DB나 운영 자격 증명을 사용하지 않는 일회용 Docker DB에서 검증한다. CI의 배포 선행 검사에도 추가한다.
- 입력 안내에 운영 식별값·사용량의 저장과 삭제 주기를 추가한다. 입력·결과 원문을 저장하지 않는다는 기존 안내는 유지한다.

## 운영 연결 절차

1. 운영 Supabase 프로젝트에서 [Cron 확장](https://supabase.com/docs/guides/cron/install)을 활성화한다.
2. 해당 프로젝트에 위 SQL migration을 적용한다. 원격에는 아직 적용하지 않았다.
3. 로컬 `.env.local`과 Vercel Production에 `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `AI_USAGE_HMAC_SECRET`를 설정한다. HMAC 키 생성 명령은 `.env.example`에 있다. secret 키에는 `NEXT_PUBLIC_` 접두사를 붙이지 않는다. 선택적으로 세 한도 환경변수를 조정한다.
4. `pnpm report:ai`로 서버 전용 RPC 연결을 확인한다. Cron 작업의 활성 상태도 확인한다. 현재 없는 운영 연결은 이 절차를 마쳐야 검증할 수 있다.
5. **이번 요청에서는 `AI_EXPLANATION_ENABLED=false`를 유지한다.** 품질 검증과 운영 연결 확인을 마친 뒤 별도 재개 결정이 있을 때만 켠다.

HMAC 키는 재배포마다 바꾸지 않는다. 키를 변경하면 기존 IP별 제한·중복 식별이 초기화되지만 전체 일별 한도는 유지된다. Supabase 설정이나 migration이 누락된 상태에서 플래그를 켜도 AI 호출은 차단된다.

## 검증

- 운영 AI 중지 배포: `dpl_MLzBiM62y5wSCRkZHxmg9QtCo7KK`, 상태 READY. 공개 주소의 HTTP 200과 `includeAi` 입력값·OpenAI 전송 안내가 없는 것을 확인했다.
- `pnpm check`: 포맷·ESLint·타입 검사 통과. 테스트 220개 통과, 유료 실호출 평가 1개는 의도적으로 건너뛰었다.
- `pnpm build`: Next.js 운영 빌드 통과.
- `pnpm test:ai-db`: Supabase PostgreSQL 17.6의 일회용 DB에서 동시 중복 8건 중 1건 허용, IP별·전체 횟수·예약 예산 한도, 성공적 정산·사용량 불명·검증 실패 비용, 정산 멱등성, 한국 날짜 경계, 집계 수치, 보관 기간, RLS·RPC 권한, Cron 등록을 검증했다. 테스트 컨테이너는 종료·삭제했다.
- 최초 DB 검사에서 초기화용 임시 서버를 준비 완료로 인식하는 문제가 나왔다. TCP 준비 상태를 기다리도록 수정한 뒤 재실행하여 통과했다. 포맷·린트에서 발견한 스크립트 오류도 수정했다.
- 최종 공개 사이트 재확인: HTTP 200, AI 요청용 hidden input과 OpenAI 전송 안내 없음.
- 이번 호출 제어 코드는 아직 운영 배포하지 않았다. 운영에 배포된 변경은 AI 비활성화이며, 원격 DB 연결을 구현 완료로 간주하지 않는다.
- 실제 AI 호출 0회. 운영 Supabase 연결·원격 migration·유료 생성의 전체 흐름은 자격 증명이 없어 미검증이다.

## 요구사항 대조

입력·명반·기본 풀이, 출생 정보의 비공개 처리와 서버 플래그를 유지한다. 운영 기록 보관은 결과 저장과 구분하여 입력 안내와 requirements.md에 반영한다. 운영 연결 전까지 호출 제한·관측의 배포 수용 완료로 표시하지 않는다. 요구사항 수행 불가를 이유로 기능을 삭제한 항목은 없다.

## 남은 문제와 추후 개선점

운영 Supabase 연결이 필요하다. AI는 현재 중지 상태이며 전체 의미 품질 검증은 별도 작업이다. 결과 저장·공유·새로고침 복원도 미구현 상태를 유지한다. 초기 트래픽·오탐·비용 관측 후 한도 조정을 검토할 수 있다. 현재 리포트는 수동 조회이며 자동 경보는 후속 필요성을 보고 결정한다.
