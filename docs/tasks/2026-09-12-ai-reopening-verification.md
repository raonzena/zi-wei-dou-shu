# AI 재개 전 운영·의미 검증

- 작성일·최종 갱신일: 2026-09-12
- 상태: 완료 — 운영 제어 검증과 2회 품질 평가 완료, 의미 품질 보완·AI 재개는 보류

> 후속 정정: 사용자는 건강을 포함한 가능성 해석을 허용한다고 명확히 했다. 아래 건강 추측의 일괄 금지·위반 판정은 에이전트가 요구사항을 과도하게 해석한 당시 기록이며 현재 기준으로 적용하지 않는다. 금전 근거 연결 문제는 별도로 남는다. [수정 작업](2026-09-12-reading-inference-and-evidence.md)을 따른다.

## 작업 개요와 요구사항

사용자가 요청한 우선순위 1번인 AI 재개 전 검증을 수행했다. 관련 기준은 requirements.md의 5절 AI 명반 해석, 6절 운영·개인정보·배포, 8절 수용 시나리오다. 운영 예약·차단·정산과 현재 일곱 분야 해석의 정확성을 확인한다. 결과 저장·공유나 AI 활성화는 범위에 포함하지 않는다. 유료 호출은 최대 2회로 제한했다.

## 결정과 근거

최신 출력 계약은 본명반만 사용하지만 `groundedInput`에는 이전 12단계의 유년 안내와 전체 운한 자료가 남아 있었다. 현재 요구사항에 맞춰 외부 입력을 본명반·생년사화·궁간 사화·검증 범위의 격국으로 한정했다. 시기 데이터는 상세 명반에 유지한다. 중복 식별도 실제 전송 자료를 기준으로 바꿨다.

첫 실제 평가에서 근거 ID 중복과 신궁을 건강 개념으로 설명하는 오류를 확인했다. 근거 ID 중복 금지, 신궁과 질액궁의 구분, 별로 신체 상태를 추정하지 않는 지침을 추가했다. 입력에도 신궁의 실제 위치와 용어집 정의를 포함했다. 최종 프롬프트 버전은 `concise-consultation-v3`다. 모델은 변경하지 않았다.

원래 일반 사례와 명궁 주성 없음 사례를 한 번씩 평가하려 했으나 첫 실패의 수정 효과를 확인하기 위해 두 번째 호출도 같은 기준 명반에 사용했다. 비용 제한을 지키기 위해 다른 명반의 유료 평가는 보류했다.

## 변경 내용과 영향

- `grounded-input.ts`: 본명반 입력을 명시적으로 구성하고 신궁 설명을 추가했다.
- `request.server.ts`: 제외된 시기 자료가 바뀌어도 같은 전송 입력을 중복으로 식별한다.
- 입력 화면: 외부 전송 안내를 실제 입력 범위에 맞췄다.
- 프롬프트·테스트: 중복 근거, 신궁 오해를 보완하고 본명반만 전송되는지 검증한다.
- 실평가 도구: 응답 메시지만 저장하며 암호화된 추론 데이터는 저장하지 않는다.
- `scripts/verify-ai-operations.mjs`: 명시적 실행 플래그로 운영 RPC를 검사한다. OpenAI를 호출하지 않으며 시험 기록 1건은 `ops-verification-v1`로 구분한다. 기록은 정상 보관 정책을 따른다.

## 검증 결과

- 기존 문서 변경을 `3c5cdb5`로 커밋했다. push하지 않았다.
- Node.js 24에서 `pnpm check` 통과: 포맷·린트·타입, 222개 테스트 통과, 유료 평가 1개 기본 건너뜀.
- `pnpm build` 통과.
- `pnpm test:ai-db` 통과: 동시 중복·횟수·예산, 알려진/알 수 없는 비용, 멱등 정산, KST 날짜, 권한·보관 기간.
- 운영 Supabase의 공개 키로 `ai_usage_summary` 호출 시 HTTP 401 / PostgreSQL 42501로 접근 거부 확인.
- 사용자가 로컬 서버 키를 설정한 후 `ZIWEI_VERIFY_OPERATIONS=1 node scripts/verify-ai-operations.mjs` 통과: 예약·중복·시간당·예산 차단, 0토큰 정산, 재정산 거절, 집계 확인. 시험 감사 행 1건, AI 호출 0회, 비용 0달러다. 개별 RPC에 시험 한도를 사용했으며 운영 설정은 변경하지 않았다.
- 운영 페이지가 정상 응답하고 AI 입력 항목을 노출하지 않음을 확인했다. 운영 장애를 의도적으로 발생시키지 않았으며 장애·동시성은 모의 테스트와 격리 DB에서 검증했다.

### 실제 AI 평가

모델은 `gpt-5.4-mini-2026-03-17`이며 공개 기준 명반을 사용했다. 자동 재시도 없이 총 2회 호출했다. 비용은 저장된 토큰과 현재 코드의 단가로 계산한 추정치이며 청구서 실측은 아니다.

| 평가    | 프롬프트 | 입력 / 캐시 / 출력 토큰 | 자동 검증           | 수동 검토                                 | 추정 비용 |
| ------- | -------- | ----------------------- | ------------------- | ----------------------------------------- | --------- |
| 첫 번째 | v2       | 13,107 / 0 / 3,315      | 중복 근거 ID로 거부 | 신궁을 신체 건강으로 오해, 회복 속도 추측 | $0.024748 |
| 두 번째 | v3       | 13,376 / 3,840 / 2,754  | 통과, 17.245초      | 개선됐으나 재개 기준 미충족               | $0.019833 |

합계 약 **$0.044581**이다. 원본 응답과 수동 검토는 git에서 제외한 `work/ai-evaluations/reference-1789215139380.json`, `reference-1789215524388.json`에 보관했다. 이 직접 평가의 비용은 운영 예약 경로를 거치지 않았으므로 Supabase 집계에 포함되지 않는다.

두 번째 응답은 궁·별 위치와 근거 ID가 맞고 일곱 분야를 갖췄으며 시기별 예측이 없었다. 하지만 다음 문제가 남았다.

- 건강 분야에서 천량을 근거로 급하게 무너지지 않는 체질이나 피로가 늦게 나타나는 양상을 추측한다. 앞에 단정하지 않는다는 안내가 있어도 근거 없는 신체 추론이다.
- 돈 분야에서 질액궁 천량을 지출 관리의 근거로 연결하지만 관계를 뒷받침하는 설명이 부족하다. ID가 존재한다는 사실만으로 해석의 타당성을 보장할 수 없다.
- 신궁을 건강 궁으로 직접 설명하는 오류는 사라졌지만 ‘몸궁’이라는 표현이 남았다. 설명 없는 궁·별 이름과 소통·기준 관련 조언의 반복도 확인했다.
- 실제 문장에 생년사화·궁간 사화를 사용하지 않아 둘을 구분하는 능력은 검증하지 못했다.

### 후속 확인: 문제가 된 문장과 검증 한계

사용자 요청으로 저장된 v3 응답을 다시 확인했다. 추가 AI 호출은 하지 않았다.

- 건강: “급하게 무너지는 타입이라기보다”, “평소엔 버티더라도 휴식이 늦어지면 피로가 뒤늦게 느껴질 수 있습니다.”는 천량 배치에서 개인의 신체 반응을 추론한다. 가능성 표현이나 의료진 상담 안내를 붙여도 현재 건강 해석 범위를 벗어난다. 일반적인 수면·휴식 관리 제안으로 제한해야 한다.
- 돈: “반대로 질액궁의 천량은 생활의 기준을 세우고 균형을 지키려는 힘을 보탭니다. 그래서 … 지출 기준을 정하고 장기적으로 관리하는 방식”은 질액궁의 별을 금전 관리 결론으로 연결한다. 실제 배치는 기준 fixture와 일치하지만 이 응답에는 해당 연결을 뒷받침하는 관계·규칙이 없다. 다른 궁을 참조하는 것 자체가 항상 틀렸다는 판정이 아니라, 제시된 근거만으로 이 결론을 검증할 수 없다는 판정이다.
- `validateAiExplanation`은 구조·순서·허용 ID·중복·사용자 문장 형식·사화 표현을 검사한다. 일반 문장의 신체 추론과 분야별 해석 타당성을 판정하는 검사는 없다. 따라서 실제 ID가 있는 부적절한 결론도 자동 검증을 통과할 수 있다.

이번 후속 확인은 기존 프롬프트에 금지 규칙이 이미 있지만 응답이 이를 따르지 않은 사례임을 확인한 것이다. 새 프롬프트나 검증 코드는 추가하지 않았다. 관련 요구사항을 변경하거나 완화하지 않았다. 저장 응답·기준 fixture·검증 코드의 읽기 대조만 수행했으므로 런타임 테스트는 반복하지 않는다.

## 요구사항 대조

현재 본명반 해석 요구사항과 달랐던 전송 입력을 복구했다. 필수 일곱 분야와 상세 명반의 운한 자료는 유지한다. 구조 통과를 의미적 정확성으로 간주하지 않는 기준에 따라 두 번째 결과도 재개 승인으로 처리하지 않았다. 요구사항을 낮추거나 대체하지 않았으며 미해결 품질 상태를 requirements.md에 반영했다. 운영 AI는 비활성 상태로 유지하고 배포하지 않았다.

## 남은 문제와 추후 개선점

다음 품질 작업에서는 분야별로 사용할 근거의 관련성과 건강 조언의 허용 범위를 명확히 하는 방법을 검토한다. 구조 검사만으로 잡히지 않는 의미 오류에 대한 별도 검증 방식도 필요하다. 이는 제안이며 아직 구현하지 않았다. 명궁 주성 없음·사화 구분 등 추가 사례를 평가하고 확인된 오류를 해소하기 전에는 운영 AI 재개를 승인하지 않는다. 추가 유료 호출은 이번 범위에서 수행하지 않는다.
