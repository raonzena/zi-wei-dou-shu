# 로딩 화면 하단과 데이터 보관 정책 점검

- 작성일: 2026-09-14
- 최종 갱신일: 2026-09-14
- 상태: 구현·로컬 코드 검증 완료 · DB CI 대기

## 작업 개요

로딩 중 개인정보 및 쿠키 안내 링크로 이동할 수 있는 문제를 없앤다. `star_content`의 버전 보관 방식과 `saved_results`의 30일 만료·삭제 구현도 현재 `main`과 운영 적용 기록을 기준으로 확인한다.

## 요구사항

- REQ-02: 명반을 준비하는 동안 공통 하단과 개인정보 안내 링크를 표시하지 않는다.
- 별 설명의 출처·번역·검수·발행 이력을 잃지 않으면서 불필요한 데이터만 정리할 수 있는 보관 원칙을 확인한다.
- REQ-06: 저장 결과는 생성 후 30일이 지나면 조회할 수 없어야 하며 정기 작업이 만료 행을 삭제해야 한다.

## 결정과 근거

공통 하단은 루트 레이아웃에 있으므로 입력 컴포넌트의 기존 `hidden` 처리만으로는 로딩 중에 사라지지 않았다. 로딩 상태를 DOM 속성으로 표시하고 해당 상태가 있는 동안 공통 하단을 `display: none`으로 숨긴다. 링크가 화면과 접근성 트리에서 빠지므로 사용자가 계산 도중 개인정보 화면으로 이동할 수 없다.

사용자가 말한 `start_content`는 현재 스키마의 `star_content`로 확인했다. 이 테이블은 발행본을 직접 수정하지 않고 새 버전을 발행하며 이전 발행본을 `archived`로 보존한다. 콘텐츠 수와 편집 빈도가 낮고 각 행에 원문 출처와 검수 기록이 있으므로, 검수·발행 이력은 모두 유지한다. 방치된 초안은 90일을 기준으로 사람이 확인한 뒤 정리하는 방식을 권장하며 자동 삭제는 이번 작업에 추가하지 않는다.

`saved_results`에는 생성 시점부터 30일 뒤의 `expires_at`이 기록된다. 서버 조회와 갱신은 현재 시각보다 만료일이 뒤인 행만 허용하고, `purge-expired-saved-results` 작업은 매시간 15분에 만료 행을 삭제한다. 운영 적용 기록에는 해당 Cron 작업이 활성 상태라고 남아 있다.

## 변경 내용과 영향

- 로딩 영역에 명시적인 페이지 상태를 추가하고 공통 하단이 해당 상태에서 보이지 않게 했다.
- 요구사항과 화면 흐름에서 개인정보 안내 접근 범위의 로딩 화면 예외를 반영했다.
- 별 설명 콘텐츠 관리 문서에 발행 이력 유지와 오래된 미사용 초안의 수동 정리 권고를 기록했다.
- 격리 DB 검증에서 저장 결과 만료 Cron의 작업 이름·주기·활성 상태를 확인하도록 보강했다.
- `star_content`와 `saved_results`의 스키마나 운영 데이터는 변경하지 않았다.

## 검증

- `corepack pnpm format:check` 통과
- `corepack pnpm lint` 통과
- `corepack pnpm typecheck` 통과
- `corepack pnpm build` 통과
- `corepack pnpm exec vitest run --maxWorkers=1`에서 테스트 312개가 통과하고 실호출 평가 1개가 제외됐다. 테스트 요약이 나온 뒤 실행 프로세스가 종료되지 않아 직접 중단했다.
- `corepack pnpm test:result-db`는 현재 실행 환경에 Docker가 없어 `spawnSync docker ENOENT`로 실행하지 못했다. GitHub Actions의 Docker 환경에서 확인해야 한다.

별도 UI 문자열 테스트는 추가하지 않았다. 운영 빌드가 vanilla-extract의 로딩 상태 선택자를 정상 생성하는 것을 확인했다. 브라우저 시각 검증은 배포 미리보기에서 수행한다.

## 요구사항 대조

REQ-02의 로딩 화면과 REQ-06의 30일 보관 기준을 현재 구현에 대조했다. 로딩 화면의 공통 하단 노출은 사용자 요청과 충돌하므로 최신 요구사항으로 교체했다. 저장 결과의 만료·삭제 구현은 기존 요구사항과 일치한다.

## 남은 문제와 추후 개선점

- 운영 `saved_results` Cron의 현재 활성 상태를 이번 작업에서 다시 조회하지는 않았다. 2026-09-13 운영 적용 당시의 확인 기록과 현재 마이그레이션을 근거로 판단했다.
- `star_content` 초안 자동 삭제는 추가하지 않았다. 초안이 실제로 누적될 때 운영자가 먼저 대상과 필요 여부를 확인해야 한다.
