# 결과 저장과 ID 링크 복원

- 작성일: 2026-09-13
- 상태: 완료 (DB 적용·로컬 구현, 앱 배포 전)

> 후속 사용자 요청으로 수동 삭제 기능과 결과 하단 관리 안내를 제거했다. 아래 삭제 검증은 제거 전 이력이며 현재 동작은 후속 변경 절을 따른다.

## 작업 개요

기존 변경을 a8c503f로 커밋한 뒤, Supabase에 결과를 저장하고 /result/[id]에서 복원한다. 최초 커밋 검증은 pnpm check(255개 통과, 유료 실평가 1개 제외)와 build 통과다.

## 요구사항

사용자는 링크를 아는 누구나 열람하도록 확정했다. UUID를 URL 식별자로 사용하고 결과 열람과 삭제 권한을 분리한다. 원본 출생 정보는 저장하지 않는다. 공개 범위와 30일 보관을 입력 전에 고지한다. 공개 공유 버튼·별도 공유 해제는 후속 범위다.

## 결정과 근거

Supabase의 jsonb에 계산 결과·기본 풀이·계산 안내·AI 결과·별 설명 버전을 스냅샷으로 저장한다. Next.js 설치 문서의 동적 params, cookies와 notFound API를 확인했다. 읽기와 쓰기는 서버만 수행하며 anon/authenticated 테이블 권한은 차단한다. 공개 UUID와 HttpOnly 소유 쿠키를 분리하고 DB에는 쿠키의 SHA-256 값만 둔다. UUID는 목록 조회가 불가능한 공개 링크 식별자이며 인증 비밀이 아니다.

조회는 만료일을 검사하고 매시간 만료 결과를 삭제한다. 결과 페이지는 검색 색인을 금지하고 캐시를 사용하지 않는다. 삭제는 소유 쿠키와 일치하는 결과에만 적용한다. 브라우저 쿠키를 지우면 삭제 권한도 사라진다고 고지한다.

## 변경 내용과 영향

입력 → 계산·저장 → /result/[id] 이동으로 변경한다. 새로고침과 다른 브라우저 열람은 저장된 결과를 조회하며 계산 엔진·AI를 호출하지 않는다. 원본 출생 정보는 저장하지 않아 수정 버튼은 새 입력으로 연결한다. 저장 당시 AI 결과는 보존하며 소유자만 실패한 AI 해석을 재시도할 수 있다. 종합 풀이·궁별 안내의 공통 문구와 화면 템플릿은 배포된 버전을 사용한다.

## 검증

- Supabase 운영 프로젝트에 saved_results와 만료 정리 작업을 적용했다. 기존 환경에는 CLI migration history가 없어 이전 작업과 같은 Management API db query 방식으로 SQL을 적용했다.
- RLS 활성화, anon select 금지, authenticated insert 금지, service_role select 허용, 만료 정리 스케줄 활성화를 확인했다.
- 브라우저에서 가상 출생 정보로 생성 → UUID 경로 이동 → 상세 탭 → 새로고침 복원을 확인했다. 쿠키 없는 HTTP 요청도 200으로 결과를 읽으며 삭제 UI·소유 해시는 노출되지 않았다. noindex도 확인했다.
- 생성 브라우저에서 시험 결과를 삭제한 뒤 기존 UUID와 잘못된 UUID 모두 404·결과 없음으로 응답했다. 시험 결과는 삭제했다.
- 결과 저장·권한·실패·AI 호출 순서 테스트 10개 통과. 한 실행에서 시험 명반을 매번 생성하던 테스트가 시간 제한에 걸려, 변경하지 않는 시험 데이터를 한 번 준비하도록 수정한 뒤 통과했다.
- AI 실호출은 하지 않았다. 30일 실시간 경과와 cron의 다음 실행 시각까지 기다리는 검증은 수행하지 않았다. 최종 pnpm check는 테스트 265개 통과·유료 실평가 1개 제외로 통과했고 pnpm build에서 /result/[id] 동적 경로 생성도 확인했다. git diff --check도 통과했다.

## 요구사항 대조

기존 ‘공유 전에 공개 확인, 별도 공유 토큰’은 향후 공유 기능 설계안이었다. 이번 사용자 결정으로 결과 ID 자체를 공개 조회 링크로 사용하며, 별도 토큰을 요구하지 않는다. 입력 화면에서 공개 범위를 먼저 알린다. 원본 출생 정보 비저장, 권한 비공개, 재계산 없는 복원은 유지한다.

## 남은 문제와 추후 개선점

생성 브라우저를 잃어버린 경우 권한 복구, 공유 버튼, 만료 전 연장과 별도 공유 해제는 이번 범위에 포함하지 않는다. 링크를 북마크해 보관할 수 있다.

## 후속 변경: 수동 삭제와 결과 관리 안내 제거

- 사용자 요청에 따라 결과 하단 보관·재입력 안내와 삭제 영역 전체를 제거했다. 입력 화면의 30일 보관·공개 범위 안내는 유지한다.
- 삭제 서버 액션, 저장소 삭제 함수, 클라이언트 상태와 삭제 전용 테스트·모킹을 제거했다. 소유 쿠키는 AI 재시도 권한 확인에 계속 사용한다.
- 서버 역할의 DELETE 권한을 회수하는 추가 마이그레이션을 적용했다. postgres가 실행하는 만료 자동 정리는 유지한다.
- 요구사항과 화면 흐름을 최신 요청에 맞췄다. 이번 제거 범위에 미결정 사항은 없다.
- 후속 검증: 관련 테스트 10개, 타입 검사, git diff --check 통과. 운영 DB에서 service_role DELETE 권한이 false이고 만료 정리 작업은 postgres 권한으로 활성화된 것을 확인했다. 브라우저 시각 검증과 전체 빌드는 재실행하지 않았다.
