# 쉬운 풀이와 전문 근거 설명 분리

- 작성일·최종 갱신일: 2026-09-12
- 상태: 완료 — 구현·검증 및 1회 실평가 완료, 별칭 검사·인용 정리 보완 필요

## 작업 개요와 요구사항

사용자가 일반 사용자용 본문과 펼쳐 보는 궁·별 근거 설명을 분리하는 방향을 승인했다. requirements.md AI 해석, screen-flow.md 결과 화면 기준을 갱신한다. 제목·문단·조언·요약에서 전문 용어를 강제로 반복하지 않고, 궁 연결의 사용 이유는 접힌 근거에서 확인할 수 있어야 한다.

## 결정과 근거

기존 text/reason 문자 일치 검사는 사용자가 이해하기 쉬운 본문에 전문 용어를 강제로 넣게 만들었다. 이를 제거하고 문단별 `{text, evidence: [{id, reason}]}` 대응은 유지한다. reason은 별도의 공개 근거 설명이다. 빈 설명·알 수 없는 ID·설명에서 빠진 궁·별·사화 출발/도착 검사는 유지한다. 단어가 있다는 사실만으로 해석 타당성을 승인하지 않는다.

React 표시 모델까지 문단 객체를 그대로 유지해 대응 정보를 잃지 않는다. 기존 텍스트·블록 ID 목록으로 평탄화하는 단계를 삭제했다. provider의 옛 입력 형식을 받는 호환 처리는 추가하지 않는다. 기존 native details/summary를 사용해 기본 접힘과 키보드 접근을 유지하고 새로운 상태 관리·라이브러리는 추가하지 않는다. 설치된 Next.js use-client 문서와 React·접근성 지침을 확인했다.

## 변경과 영향

- 본문에서는 쉬운 성향→생활 모습→조언을 설명하고, 궁·별 이름과 연결 이유는 reason으로 분리하도록 프롬프트를 수정했다. 제목에도 전문 용어를 강제하지 않는다. grounded-passages-v2를 사용하며 모델·호출 한도는 유지한다.
- ‘풀이 근거’를 펼치면 제목·문단 번호·조언 번호·마무리별로 EvidenceReference와 reason을 함께 표시한다. AI 원문은 React 텍스트로 렌더링한다.
- reason 길이는 제목 길이와 분리해 최대 1,200자다. 짧은 제목 때문에 상세 설명이 잘리지 않게 한다.
- 같은 문단의 중복 ID는 합치되 서로 다른 reason은 첫 등장 순서로 모두 보존한다. 설명 없는 중복은 검증 전에 지우지 않는다. 서로 다른 문단의 같은 근거는 각각의 사용 이유를 유지한다.
- 기존 10px 근거 글씨와 작은 여백을 유지한다. 본문과 다른 reason을 허용하는 테스트로 이전 문자 일치 강제 테스트를 교체한다.

## 검증

Node.js 24에서 `pnpm check` 통과: 포맷·린트·타입·238개 테스트(유료 평가 1개 기본 건너뜀). `pnpm build` 통과. 도메인·provider 통합·HTML 렌더 테스트로 별도 설명 허용, 누락 거부, 기본 접힘과 상세 내용 위치를 확인했다. HTML 렌더 검사로 reason이 details 안에만 있고 open 속성이 없는지 확인했다. 실제 브라우저의 시각·키보드 조작은 이번 범위에서 재검사하지 않았다. 추가 AI 호출과 배포는 하지 않았다.

## 요구사항 대조와 남은 작업

종료 전 대조에서 사용자가 승인한 방향으로 요구사항·화면 흐름·프롬프트·검증·UI를 맞췄다. 이는 수행 불가에 따른 우회가 아니라 표시 방식과 검증 기준 변경이다. 본문과 근거의 의미적 대응은 별도 평가가 필요하다. 모델의 실제 가독성·준수율·비용은 이번 모의 검사로 보장하지 않는다. 실제 응답에서 문제가 생기면 요청대로 해당 원문을 함께 보고한다.

## 후속 실제 응답 1회 검증

사용자 요청으로 동일 reference 명반을 grounded-passages-v2로 1회 호출했다. HTTP 200, 29.531초, 계약 검사 통과 후 근거 검사에서 invalid-response로 차단돼 실평가 테스트는 실패했다. 입력 16,375토큰(캐시 0), 출력 5,977토큰으로 코드 단가 기준 추정 **$0.039178**이다. 원문과 수동 평가는 git 제외 `work/ai-evaluations/reference-1789219829238.json`에 저장했다. 직접 평가라 운영 Supabase 집계에 포함되지 않는다.

### 개선과 남은 문제

본문은 궁·별 이름 대신 쉬운 성향·생활 조언을 쓰고, 전문적 설명은 reason에 분리됐다. 그러나 전체 검증 통과는 아니다.

1. 핵심 성향 제목은 palace:묘를 인용하면서 reason에 부처궁 대신 신궁이라고 썼다. 이 명반은 신궁이 부처궁에 있으므로 의미상 잘못된 궁이라고 단정할 수 없다. 현재 검증기는 부처·부처궁을 찾으며 이 명반의 신궁 별칭을 인정하지 않아 오탐했다. 여러 문단에서도 palace 인용의 reason에 별 이름만 있어 궁 이름 검사에 걸리는 사례가 있다.
2. 내면 제목은 matched=false인 자부동궁을 ‘직접적인 성향 단정에는 쓰지 않았다’고 설명하면서 evidence에 넣었다. 이는 실제 사용한 성립 구조만 인용한다는 규칙과 맞지 않는다. 부정 설명의 내용 자체가 허위인 것은 아니다.
3. 금전 제목의 명궁→질액궁 천량 연결은 ‘관리와 균형 감각이 중요’하다는 추상적 설명에 머문다. 다른 궁을 쓴 것 자체가 오류는 아니나 왜 금전 조언의 근거인지 추가 의미 검토가 필요하다.
4. 마무리의 일부 reason은 쉼표로 끝나는 미완성 구절이다. 단일 ID별 설명으로 충분한지 보완 필요하다.

## 근거 후보 정리와 설명 역할 분리

- 상태: 완료 — 후보·설명 분리 및 1회 실평가 완료, 의미 품질 보완 필요
- 사용자 요청: 서버가 근거 후보·배치 표시를 책임지고 AI는 해석 연결·조언 연결을 작성하도록 수정 후 실검증한다.
- 미성립 격국을 groundedInput과 응답 enum에서 제외한다. 상세 명반의 격국 검사표는 유지한다. palaces.aliases에 실제 bodyPalaceBranch와 일치하는 궁에만 신궁을 추가한다.
- reason을 interpretationLink(배치→성향/상황), adviceLink(성향→조언)로 교체한다. 조언 없는 문단은 null을 허용하며 조언 목록은 모든 인용에 필수다. 일반 문단에 조언이 있는지는 현재 코드가 의미적으로 판별하지 못하므로 프롬프트·수동 검토로 확인한다.
- 이름 포함 검사를 제거한다. 배치 정보는 기존 chart-facts의 서버 계산 출발·도착·별·화종을 EvidenceReference에서 표시한다. 별도 AI 사실 설명을 요구하지 않는다. 사실 값은 ID의 존재와 서버 자료로 확인하며 자연어의 모든 사실 주장을 자동 검증한다고 주장하지 않는다.
- 중복 ID는 합치면서 서로 다른 해석·조언 설명을 각각 보존한다. grounded-passages-v3로 변경한다. 기존 reason 형식은 수용하지 않는다.
- 관련 테스트를 새 수용 기준으로 교체하고 불성립 격국 후보 제외·조언 누락·별칭 범위를 검사한다. 코드 검사 후 reference 1회 실평가를 수행하며 문제 원문을 함께 보고한다.

### grounded-passages-v3 검증 결과

Node.js 24에서 `pnpm check` 통과(237개 테스트, 유료 평가 기본 1개 건너뜀), `pnpm build` 통과. 최초 린트 실패는 테스트에서 사용하지 않은 별칭 변수를 제거한 뒤 재검사해 해결했다. 후보 필터·nullable 조언 규칙에 맞춰 이전 이름 포함 테스트를 교체해 전체 개수가 달라졌다.

동일 reference 명반으로 1회 호출: HTTP 200, ready, 29.981초, 구조·근거 검사와 실평가 테스트 통과. 입력 16,408토큰(캐시 0), 출력 5,946토큰이며 코드 단가 기준 **$0.039063**이다. 직접 호출이므로 운영 Supabase 집계에는 포함되지 않는다. 기록은 `work/ai-evaluations/reference-1789220272489.json`에 있다.

자동 검증 개선은 확인했다. 미성립 격국을 인용하지 않고 신궁 명칭이 오탐으로 차단되지 않았다. 모든 조언 목록 인용에 adviceLink가 있다. 본문과 기술 설명도 분리됐다. 다만 의미 품질은 전체 통과로 승인하지 않는다.

금전 마지막 조언의 원문:

```json
{
  "text": "재정은 속도보다 지속성을 먼저 보는 방식이 더 어울립니다.",
  "evidence": [
    {
      "id": "star:자:major:천량",
      "interpretationLink": "천량의 화과는 안정과 보존 쪽에 무게가 있어, 빠른 회전보다 꾸준한 관리와 점검이 맞습니다.",
      "adviceLink": "지키는 힘이 강한 구조라서, 장기적으로 유지 가능한 방식이 더 잘 맞습니다."
    }
  ]
}
```

두 필드는 채웠지만 질액궁의 별을 금전 조언에 쓰는 이유가 여전히 일반적인 안정·보존 뜻의 반복에 머문다. 다른 궁의 사용 자체가 오류라거나 전통 해석이 틀렸다는 판정은 아니다.

돈의 일반 문단 원문:

```json
{
  "text": "돈은 감으로 쓰기보다 목적을 세워 다루는 편이 잘 맞아 보입니다. 들어오는 흐름보다 지키고 정리하는 방식에서 강점이 나타나기 쉬우며, 큰 결정을 할 때는 특히 기준이 분명한 편일 수 있습니다.",
  "evidence": [
    {
      "id": "palace:축",
      "interpretationLink": "재백의 염정·칠살은 지출과 자산 관리에 단호함과 변동성이 함께 작동할 수 있음을 보여 줍니다.",
      "adviceLink": null
    },
    {
      "id": "palace:사",
      "interpretationLink": "무곡은 실리를 따지고 구조를 보는 성향이어서, 돈을 벌고 관리할 때 계산이 분명하게 들어갑니다.",
      "adviceLink": null
    },
    {
      "id": "star:자:major:천량",
      "interpretationLink": "천량의 화과는 보수적으로 보관하고 안정성을 챙기려는 성향으로 읽혀, 돈을 지키는 판단에 힘을 보탭니다.",

```

목적을 세워 다루라는 조언이 있지만 adviceLink는 모두 null이다. 일반 문단에서 조언을 판별하는 것은 현재 자동 검사 범위가 아니므로 프롬프트만으로 완전히 지켜지지 않았다. 건강 섹션에는 증상 지속 시 의료진 상담 안내도 빠졌다. 건강의 가능성 해석을 금지한 것은 아니다.

요구사항 대조: 서버 후보·실제 별칭·배치 표시, 두 설명 역할 분리와 기계적 이름 검사 제거는 반영됐다. 응답 의미와 일반 문단의 조언 누락은 남아 있다. 사용자가 요청한 수정과 1회 검증을 마쳤으며 검사 규칙을 결과에 맞춰 낮추거나 추가 호출하지 않았다. 커밋·배포·운영 AI 활성화는 하지 않았다.
