# 정규화 결과와 iztro 명반 계산 연결

- 작성일: 2026-09-11
- 최종 갱신일: 2026-09-11
- 상태: 서버 내부 연결 완료 / 독립 대조에서 불일치 확인 / 공개 UI 연결 보류

## 작업 개요

검증된 출생 입력에서 실제 iztro 계산과 서비스 명반 데이터 반환까지 서버 내부 흐름을 연결한다. 공개 API·UI·해석·저장·공유는 이번 범위에 없다.

## 요구사항

REQ-01·03·04·10과 ADR-0003을 따른다. 한국 음력·양력 입력 동등성, 고정 엔진 정책, 출생 정보와 명반 데이터 구분, 실제 12궁·주성·보조성·사화 데이터 전달이 이번 범위다. 독립적인 전체 명반 정확성 검증 없이 출시 완료로 처리하지 않는다.

## 결정과 근거

기존 bySolar와 설치된 타입·공식 예제를 확인한다. 서비스 데이터는 필요한 필드만 새 객체로 반환해 엔진 기능 객체와 원본 개인정보가 UI 경계를 넘지 않게 한다. 전역 설정 오염은 다른 정책의 결과를 정상 반환하지 않도록 감지한다. 새 라이브러리나 다중 엔진 추상화는 추가하지 않는다.

## 변경 내용과 영향

- `calculate-chart.server.ts`: unknown 출생 입력을 normalizeBirth로 검증한 뒤 고정 정책의 bySolar에 전달한다. 서비스 명반·비공개 정규화 정보·실제 설치 엔진 버전을 구분해 반환한다.
- `chart.ts`: 12궁의 위치·이름·간지·신궁 여부, 별 이름·14주성 여부·밝기·사화를 담는 서비스 타입과 Zod 검증을 정의했다. 12궁 중복, 14주성 수와 중복, 4종 사화, 명궁·신궁 참조 일관성을 검사한다.
- 기능 객체나 rawDates 전체 직렬화를 사용하지 않고 필요한 필드만 투영한다. chart에는 출생 날짜·성별·시각을 포함하지 않는다. 전체 반환의 birth는 비공개이며 공유 API로 그대로 반환해서는 안 된다.
- 사화가 없는 별의 엔진 값은 빈 문자열 또는 undefined일 수 있어 null로 정규화했다. 밝기가 없는 경우도 null이다. 한국어 엔진의 밝기 값은 [+1] 같은 원문 표기이며 UI의 숫자 운세 점수가 아니다. 설명·표시 문구는 후속 UI에서 검토한다.
- 설정은 서버 모듈 초기화에서 고정한다. 계산 직전에 기본 설정·사화·밝기 사용자 정의표 오염을 검사하고, 계산은 언어 지정부터 투영까지 await 없이 동기로 수행한다. 플러그인 등록은 제공하지 않으며 다른 코드의 직접 등록도 허용하는 설계가 아니다.
- 엔진 예외·구조 검증 실패·설정 오염은 개인정보가 없는 calculation_failed 오류로 반환한다. 입력 검증 실패는 기존 오류 코드를 보존하고 엔진을 호출하지 않는다.

새 의존성·API·DB·화면은 추가하지 않았다. 반환 필드는 초기 화면 연결을 위한 데이터 계약이며 상세 UI의 최종 표시 항목을 사용자 확정한 것은 아니다.

## 검증

Node.js 24.21.0에서 pnpm check가 통과했다. 기존 53개에 통합 테스트 21개를 추가하여 전체 74개다. pnpm build와 최종 문서 포맷·상대 링크·git diff --check도 통과했다.

- 공식 2000-8-16 예제의 명궁·신궁·오행국·일부 주성 배치를 한국어 투영 결과와 대조했다. 업스트림 예제 회귀 검증이며 독립 정답 검증은 아니다.
- 2012·2017년 한국 음력과 양력 입력의 전체 계산 반환 동등성을 확인했다.
- DST 보정으로 전날 늦은 자시가 되는 입력이 날짜 추가 없이 정확히 한 번 bySolar에 전달됨을 확인했다. 월말·연말 시각도 전달 계약을 검증했다.
- 1900년 1월 1·30·31일의 결과 구조가 유효함을 확인했다. 해당 기간의 전체 별 배치 정확성을 독립 검증한 것은 아니다.
- 2024년 입춘 전후에는 사화가 유지되고 엔진 음력 새해 경계에서 바뀌는 동작을 확인했다.
- 2023년 윤2월 16일에 해당하는 4월 6일의 명궁 지지가 00시에는 진, 23시에는 묘가 되는 동작을 특성 테스트로 기록했다. 엔진 출력으로 기대값을 정한 재현 테스트이며 올바른 유파 규칙임을 입증하지 않는다.
- 잘못된 입력의 엔진 호출 차단, 예외 메시지 비노출, 불완전 명반 거부, 설정 오염 거부, 반환 객체 독립성, 언어가 다른 선행 호출 및 교차 요청 이후 결정성을 확인했다.

테스트의 교차 요청은 같은 프로세스에서 Promise 작업으로 순서를 섞은 검증이다. 동기 구간의 계약을 검증하며 여러 서버 프로세스·공개 API 부하 검증을 수행한 것은 아니다. 사화 기본표의 공식 문서 링크가 404여서 해당 링크를 독립 정답 근거로 사용하지 않았다.

## 요구사항 대조

REQ-01·03·04·10 및 ADR-0003과 대조했다. 한국 음력 변환, 고정 정책, 실제 엔진 데이터, 간편·상세에 공유할 명반 구조를 유지한다. 이유 없는 차이와 수행 불가로 축소한 요구사항은 없다. ADR의 독립 기준 명반 검증 전 공개 연결 제한을 유지한다. 현재 함수는 서버 내부 개발·테스트 경로이며 공개 API나 결과 화면에 연결하지 않았다. 간편·상세 UI·해석·용어·공유의 수용 기준을 완료 처리하지 않는다.

## 남은 문제와 추후 개선점

윤달과 늦은 자시 조합 및 초기 지원 연도의 독립 기준 명반 검증이 남아 있다. 그 결과가 정책과 충돌하면 예외를 숨기거나 날짜를 조작하지 않고 요구사항·정책 문서에 근거를 기록해 수정해야 한다. 이후 입력 UI·요청 경로, 명반 UI와 기본 설명을 연결한다. 설정 오류 관측은 향후 서버 관측 설계에서 개인정보 없는 오류 코드로 연결한다.
