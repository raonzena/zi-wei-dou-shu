# 윤달 후반·늦은 자시의 라이브러리 처리 비교

- 작성일·최종 갱신일: 2026-09-11
- 상태: 조사 완료 / 초기 자시 예외 포함 iztro 채택 확정 / 추후 개선 희망 기록

## 작업 개요와 요구사항

사용자는 화성·령성 및 사화는 iztro를 따르기로 확정했다. 남은 23시 윤달 후반 보정 제외는 다른 라이브러리를 조사한 뒤 결정한다. REQ-01·10, 계산 품질 4절, OPEN-02와 ADR-0003에 해당한다. 다른 라이브러리의 구현을 학술적 정답이나 독립 감수로 취급하지 않는다.

## 조사 방법

공식 저장소에서 파일을 읽고 Git tree SHA로 버전을 고정했다. 새 의존성은 설치하지 않았다. 내려받은 소스는 gitignored work/leap-research에서 검토했다. 독립 코드인지와 독립 규칙인지 구분한다. 검색 결과에 나온 과거 구조를 현재 소스로 오인하지 않는다.

## 경계 사례

2023년 윤2월 날짜를 대상으로 안성(별 배치)에 사용하는 월을 비교했다. 아래 숫자는 민간 생일의 음력 월 표기가 아니라 배치용 월이다.

| 입력 음력·시각         | iztro 실제 실행 | ziwei-chart 실제 실행 | ziwei_core 소스에서 추론  |
| ---------------------- | --------------- | --------------------- | ------------------------- |
| 윤2월 15일 00시 (4/5)  | 2               | 2                     | 2                         |
| 윤2월 15일 23시        | 2               | 2                     | 다음 날 16일이므로 3      |
| 윤2월 16일 00시 (4/6)  | 3               | 3                     | 3                         |
| 윤2월 16일 23시        | 2               | 2                     | 다음 날 17일이므로 3      |
| 윤2월 29일 00시 (4/19) | 3               | 3                     | 3                         |
| 윤2월 29일 23시        | 2               | 2                     | 다음 날 평3월 1일이므로 3 |

ziwei-chart의 원본 모듈 파일을 수정 없이 별도 CommonJS 디렉터리에 배치하여 解析生辰을 호출하고, 설치된 iztro의 fixLunarMonthIndex 결과와 비교했다. 6건에서 두 구현이 일치했다. 전체 명반·전체 라이브러리 테스트를 실행한 것은 아니다. ziwei_core 열은 실행값으로 표시하지 않는다. 검토한 calendar_test.dart는 JS fixture 대조이며 이번 윤달 6건의 독립 기대값 검증으로 삼지 않았다.

## 결정과 근거

### 사용자 확정

화성·령성과 사화는 iztro 2.6.1 기본 규칙을 따른다. CUST 자료와 다른 두 항목은 미해결 오류에서 **채택 규칙과 비교 자료의 설명된 차이**로 정리한다. 원문 기대값을 iztro 출력으로 덮어쓰지 않는다. 해당 테스트는 채택 정책 회귀 검사로 분리하고 독립 자료 일치로 집계하지 않는다.

### 3번 권장안 — 초기 버전은 iztro 예외 유지

비교 구현에 단일한 합의는 없다. 동일한 예외를 구현한 프로젝트가 있어도 iztro 기반 사양·대조이므로 다수결 근거가 아니다. ziwei_core의 날짜 우선 방식은 명확한 대안이지만 이를 채택하려면 월말·연말·주성의 날짜와 월 배치를 함께 확인해야 한다.

초기 iztro 사용 및 추후 필요한 기능의 자체 구현이라는 기존 방향을 고려하면, 초기에는 **일 처리와 월 처리가 별도이고 23시에는 윤달 후반 월 보정을 제외한다**는 정확한 계약으로 기존 엔진을 유지하는 것을 권장한다. 이 예외가 전통적으로 옳다고 인증하는 것은 아니다. 사용자가 3번까지 확정했다고 기록하지 않는다. 승인 전에는 기존 설정과 보류 상태를 유지한다.

대안은 논리 날짜를 먼저 다음 날로 이동한 뒤 월·일·연도 전체를 일관되게 도출하는 방식이다. `timeIndex !== 12`만 삭제하면 15일 23시나 월말 처리가 ziwei_core와 같아지지 않는다. 입력을 다음 날 00시로 바꾸는 방법도 연도·월 처리까지 달라질 수 있으므로 임시 우회로 추가하지 않는다.

## 변경과 영향

계산 코드와 패키지는 변경하지 않았다. 화령·사화 테스트의 의미를 채택 정책 회귀로 분리하고 기존 독립 대조 문서·요구사항·ADR·작업 목록을 갱신했다. 윤달 예외는 제안 단계이며 아직 공개 연결 제한을 해제하지 않는다.

## 검증과 요구사항 대조

Node.js 24에서 비교 6건을 실행했다. 테스트 분류 변경 후 프로젝트 테스트 96개, 문서 포맷 및 git diff --check가 통과했다. 제품 실행 로직 변경이 없어 빌드는 반복하지 않는다. REQ-01·10과 화면·해석·공유 요구사항을 유지했다. 화령·사화 결정은 사용자 승인된 구체화이며 기능 축소가 아니다. 한국 음력 입력 변환과 시간 정규화도 변경하지 않았다.

## 남은 문제와 착수 조건

3번 권장안의 채택을 결정한 뒤 정확한 정책 문구·경계 테스트를 확정한다. 다른 규칙을 선택하면 전체 날짜 경계 영향과 정책 버전 변경을 함께 설계한다. 명반 표시 항목의 나머지 독립 검증은 이 결정과 별개로 남아 있다.

## 최종 사용자 결정

초기 버전은 윤달 후반의 23시 월 보정 제외까지 iztro 2.6.1을 따른다. 사용자 확정에 따라 앞선 예외 승인 대기는 해소한다. 별 배치용 월과 늦은 자시의 일 처리를 별도로 적용하는 현재 엔진 규칙을 정확히 안내한다. 사용자는 추후 이 처리가 개선되기를 원한다. 날짜를 먼저 넘겨 월·일·연도를 일관되게 도출하는 방향을 후속 검토 대상으로 남기되 구체 알고리즘·일정은 미확정이다. 변경 시 경계 전체 검증과 계산 정책 버전 갱신이 필요하다. 현재 동작의 전통적 정확성 인증이나 전체 출시 검증 완료를 뜻하지 않는다. 이번 예외를 이유로 한 개발 연결 보류는 해제한다.
