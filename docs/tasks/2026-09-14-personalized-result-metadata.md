# 이름을 반영한 결과 공유 제목

- 작성일: 2026-09-14
- 최종 갱신일: 2026-09-14
- 상태: 구현·로컬 검증 완료

## 작업 개요

출생 정보 입력 화면에서 이름 또는 닉네임을 함께 받고, 저장된 결과 링크의 Open Graph 제목에 이를 반영한다. 공유받은 사람이 링크의 주인과 내용을 바로 이해할 수 있게 하되, 이름이 공개 링크와 함께 노출된다는 사실을 입력 전에 안내한다.

## 요구사항

- REQ-01: 이름 또는 닉네임을 필수 입력값으로 받으며 클라이언트와 서버에서 검증한다.
- REQ-06: 이름을 저장 결과와 중복 판별에 포함하고, 링크 미리보기 제목에 표시한다.
- 기존 저장 결과는 이름이 없어도 계속 읽을 수 있어야 한다.

## 결정과 근거

- 이름은 명반 계산 입력과 분리한다. 계산 엔진에는 전달하지 않고 결과의 공개 표시 정보로만 저장한다.
- 이름이 다르면 별도의 결과를 생성한다. 이름을 중복 판별에서 제외하면 같은 출생 정보로 만든 이전 결과의 이름이 재사용될 수 있기 때문이다.
- 공유 제목은 `○○님의 명반은 어떻게 나왔을까요?`로 표시한다. 이름이 없는 기존 결과는 일반 제목을 사용한다.
- Open Graph 메타데이터는 Next.js의 서버 `generateMetadata`에서 저장 결과를 읽어 생성한다.

## 변경 내용과 영향

- 입력 화면에 20자 이내의 이름 또는 닉네임 필드를 추가하고 클라이언트와 서버에서 같은 규칙으로 검증한다.
- 이름을 계산 입력과 분리하여 iztro와 OpenAI에는 전달하지 않는다.
- 저장 스냅샷에 이름을 추가하되 선택 필드로 두어 기존 저장 결과를 계속 읽는다.
- 이름을 HMAC 중복 판별의 입력에 포함하여 다른 이름의 결과가 재사용되지 않게 한다.
- 결과 경로의 Open Graph·Twitter·문서 제목과 모바일 공유 제목을 개인화한다.
- 입력 안내, 개인정보 및 쿠키 안내, 요구사항과 화면 흐름에 이름의 저장·공개 범위를 반영한다.

## 검증

- Prettier, ESLint, Next.js 타입 생성, TypeScript 검사가 통과했다.
- 변경 관련 테스트 46개가 통과했다.
- 전체 테스트에서 311개가 통과하고 실호출 평가 1개가 제외됐다. 기존 iztro 교차 요청 테스트 1개가 20초를 넘겼지만 해당 파일을 단독으로 다시 실행했을 때 21개가 모두 통과했다.
- Next.js 16.3.4 운영 빌드가 통과했고 `/result/[id]`가 동적 경로로 생성되는 것을 확인했다.

## 요구사항 대조

REQ-01과 REQ-06의 입력, 검증, 저장, 공개 안내, 결과 재사용, 공유 제목 기준을 구현과 대조했다. 이름이 없는 기존 결과의 일반 제목과 읽기 호환성도 유지한다.

## 남은 문제와 추후 개선점

실제 공유 서비스의 Open Graph 캐시는 배포된 새 결과 링크로 확인해야 한다. 카카오톡처럼 이전에 공유한 URL의 메타데이터를 캐시하는 서비스에서는 새로 생성한 결과 URL을 사용하거나 해당 서비스의 캐시 갱신 절차가 필요할 수 있다.
