# 이름 입력과 결과 중복 방지 검토

- 작성일: 2026-09-13
- 상태: 검토 완료 · 구현 미확정

## 작업과 관련 요구사항

사용자가 이름 입력과 같은 입력의 저장 결과 재사용, 조회 비용을 질문했다. REQ-06의 공개 링크·소유 쿠키·30일 만료, 원본 출생 정보 미저장 정책을 기준으로 검토한다.

## 확인과 제안

현재 createSavedResult는 계산 후 매번 새 UUID 행을 저장한다. 이름은 계산에 쓰이지 않으므로 표시 목적의 선택 항목으로 분리하는 안을 제안한다. 같은 사람 확인을 이름만으로 판단하지 않는다. 우선 동일 소유 쿠키 안에서 정규화 입력·기준 시기·엔진/풀이/콘텐츠 버전·AI 설정이 같은 유효 결과를 재사용하는 안이 단순하다. 중복 키는 서버 HMAC으로 만들고 인덱스로 조회하며 동시 삽입은 DB 유일성 제약과 원자적 처리로 막는다. 이름을 저장 결과에 표시한다면 이름 변경 시 처리와 공개 링크 노출 정책도 확정해야 한다.

## 비용과 미결정

PostgreSQL B-tree는 동등 조회를 지원한다. 인덱스 조회로 기존 큰 payload 쓰기와 계산·AI 호출을 줄일 수 있으나 중복이 없는 요청에는 조회 비용이 추가된다. 실제 비용·지연 개선은 중복률과 데이터 규모에 따라 달라지며 측정하지 않았다. 모든 방문자가 같은 행을 쓰는 방식은 현재 단일 owner_hash와 개인화 이름 구조에 맞지 않아 권한 설계가 필요하다. 만료 결과는 재사용하지 않고 재조회로 30일을 연장하지 않는 안을 제안한다. 개인정보 파생 HMAC도 익명 정보로 단정하지 않는다.

## 요구사항 대조와 검증

소스 및 PostgreSQL 공식 문서만 확인했다. 구현·DB 변경·부하 시험은 하지 않았으며 위 내용은 제안이다. 이름 수집과 저장, 공개 표시, 재사용 범위는 사용자 결정 후 요구사항에 반영해야 한다.
