# 사용자 프롬프트 기반 12단계 본명반 해석

- 작성일: 2026-09-11
- 상태: 구현·모의 검증 / 키 설정 확인, API 크레딧 부족으로 생성 품질 평가 대기

## 작업 개요와 요구사항

사용자가 첨부한 상세 상담 프롬프트를 AI 호출에 적용하도록 요청했다. REQ-01·02·03·05·07과 OPEN-05에 따라 호출 근거·출력 구조·입력 안내·결과 화면을 함께 변경했다. 기존의 주성별 짧은 문장 재서술을 유지하는 변경이 아니라, 사용자 요청에 따른 본명반 해석 확장이다.

## 프롬프트 적용

`src/server/interpretation/consultation-prompt.ts`에 첨부 원문 전체를 보존했다. 원문의 원칙과 12단계 분석 순서를 삭제하거나 요약하지 않았다. 원문 뒤에 서비스의 실제 입력과 JSON 출력 계약을 적용하는 규칙을 명시적으로 덧붙였다. 버전은 `user-consultation-v1`이다.

원문은 캡처본을 전제하지만 현재 서비스에는 이미지 입력이 없다. 따라서 서버가 계산한 본명반 JSON을 직접 근거로 삼으며 이미지를 판독했다고 주장하지 않도록 했다. 원본 출생 정보는 외부 전송 제외라는 기존 개인정보 원칙을 유지한다.

## 근거 데이터

12궁의 궁명·궁간·궁지, 명궁·신궁·오행국, 기존 표시 범위인 14주성·보조성 18개와 생년사화를 전달한다. 보조성의 이름이 같은 경우 분류까지 구분한다. 밝기와 나머지 성요는 기존 검증 범위 밖이므로 전달하지 않는다.

삼방사정은 각 궁의 지지 위치를 기준으로 본궁·두 삼합궁·대궁의 ID를 서버에서 구성한다. iztro의 궁 설명과 巳→酉·丑·亥, 申→子·辰·寅 예시를 확인했다. 이를 성요 재배치나 시기 계산에 사용하지 않는다.

대한·유년·유월, 명주·신주, 별의 밝기, 자화·비화, 격국 판정과 과거 경험은 미제공 목록으로 전달한다. 미제공을 ‘그런 현상이 없다’거나 이미지의 ‘판독 불가’와 혼동하지 않도록 한다. 노복과 교우궁의 대응 관계도 전달한다.

## 응답과 화면

12단계 순서를 검증하고 각 문단은 근거 ID → 쉬운 용어 뜻 → 일상 해석 → 점검할 질문·행동으로 표시한다. 문단은 최대 6개이며 충분한 근거가 있으면 원문대로 3~6문단을 요청한다. 근거 없는 분량 채우기는 금지한다.

현재 모든 해석은 제한된 자료를 사용하므로 ‘제한된 분석’ 또는 ‘자료 필요’ 상태만 허용한다. 평생의 큰 흐름·대한·유년인 3·10·11단계에는 분석 문단이 없어야 하며 필요한 자료를 설명해야 한다. 없는 시기 자료를 제공받은 것처럼 생성하면 응답을 거부한다. 다른 단계는 자료 부족 시 분석하지 않을 수 있다.

단계 중복·누락·순서 오류, 미지원·중복 근거 ID를 거부한다. 단, 문장이 실제로 해당 근거에 충실한지까지 이 검사로 보장할 수는 없다. 모델 문장은 해석이며 서버 계산 사실이나 전문가 검증 결과로 취급하지 않는다.

화면은 단계별 펼치기를 제공하고 첫 판독 요약을 기본으로 연다. 12궁 표는 모델이 생성한 표 대신 서버 근거를 그대로 표시한다. 각 문단의 궁·별은 기존 용어 팝오버로 연결하며 모델이 사용한 전문용어 뜻도 별도 항목으로 표시한다. 표는 작은 화면에서 내부 가로 스크롤을 사용한다.

## 호출 설정과 영향

기존 모델과 Responses API, `store: false`, 자동 재시도 0회를 유지한다. 상세 프롬프트에 맞춰 최대 출력 16,000토큰과 90초 요청 제한으로 변경했다. 12단계 전체를 반환하지 못한 응답은 성공으로 표시하지 않는다. 요청 시간이 늘 수 있으므로 배포 환경 제한을 확인해야 한다.

입력의 외부 전송 안내를 주성별 문장에서 본명반 데이터로 수정했다. 주성이 없는 명궁도 다른 궁의 근거로 가능한 범위를 분석한다. 더 이상 ‘unsupported’로 외부 호출을 생략하는 구형 분기는 유지하지 않는다. 규칙 기반 기본 풀이 자체는 그대로 제공한다.

## 검증

첨부 프롬프트가 요청 instructions에 포함되는지, 12궁·32개 표시 별·4개 생년사화, 신궁과 삼방사정, 원본 불변성을 검사한다. 미검증 밝기·원본 출생 정보가 전송되지 않는지 확인한다. 단계 누락·중복·순서와 시기 자료 없는 분석 거부, 명궁 주성 없음의 요청, 기존 API 오류·시간 초과 처리도 검사한다.

실제 OpenAI 키가 없어 모델 응답의 한국어 품질·원문 12단계 준수·내용상 근거 충실성·시간·비용은 미검증이다. 모의 응답은 표시·검증 경로용이며 실제 해석 결과로 저장하거나 배포하지 않는다. 공개 출시 전에 실제 사례 평가와 요청·사용량 제한이 필요하다.

Node.js 24에서 테스트 142개·lint·타입 검사·운영 빌드가 통과했다. 실행 시 원문 문자열과 첨부 파일이 정확히 같은지도 대조했다. 모의 API 응답으로 실제 브라우저에서 12개 단계 순서, 12궁 표의 12개 행, 단계 펼치기와 대한·유년 자료 필요 표시를 확인했다. 변경 파일 포맷과 `git diff --check`도 통과했다. 모의 서버는 종료하며 서비스 데이터로 저장하지 않는다.

## 요구사항 대조와 후속 작업

이전 ‘검토된 기본 문장만 AI가 재서술’ 정책은 사용자의 명시적 상세 프롬프트 요청으로 본명반 해석까지 확장했다. requirements.md와 ADR-0004에 변경 이유·방향과 미검증 범위를 기록했다. 입력·계산 정책·공유·저장 요구사항을 삭제하거나 축소하지 않았다.

현재 엔진의 대한·유년 산출·정규화 정책과 독립 검증이 없으므로 이 단계들을 구현 완료로 취급하지 않는다. 후속으로 해당 계산 데이터와 정책을 검증해 전달 범위를 넓힐 수 있다. 실제 API 키 설정 후에는 각 단계의 근거 연결, 상반된 신호·한계 설명, 진단·재정 단정 금지, 3~6문단의 실질적 내용과 시간 초과를 평가한다.

## 실제 API 연결 확인 후속 기록

사용자가 키 설정을 알린 뒤 서버를 재시작하고 검증용 출생 정보로 브라우저에서 AI 해석을 요청했다. `.env.local`에 키가 있고 Git 제외 대상임을 확인했으며 키 값은 출력하지 않았다. 실제 요청은 HTTP 429로 실패했고 화면에는 기존 명반·기본 풀이와 AI 오류 안내가 유지됐다.

원인 확인용 최소 요청에서도 HTTP 429와 `credit_balance_exhausted`를 확인했다. 공식 문서에 따르면 API 선불 크레딧 잔액이 없는 상태다. 추가 반복 호출은 중단했다. 키 설정은 확인했지만 정상 생성·응답 품질·생성 소요 시간 검증은 완료하지 못했다.

현재 화면은 모든 429를 일시적인 요청 제한으로 안내하므로 크레딧 부족도 재시도 대상으로 표시하는 한계가 확인됐다. 결제·사용량 제한과 일시적인 속도 제한을 구분하는 오류 처리가 후속 개선 항목이다. 이번 확인에서는 제품 코드를 변경하지 않았다. 요구사항을 축소하거나 계산 정책을 바꾸지 않았으며 실제 생성 검증은 크레딧 충전 후 진행한다.

참고: [OpenAI API 사용량·지출 제한 문제 해결](https://help.openai.com/en/articles/6614457)

충전 이후의 실호출, user-consultation-v2 적용 규칙 보완, 비용 측정과 품질 한계는 [실제 AI 검증 기록](2026-09-11-ai-live-verification.md)을 따른다. 앞선 크레딧 부족은 해당 확인 시점의 기록이다.
