# 출생 정보 입력과 실제 명반 미리보기

- 작성일: 2026-09-11
- 상태: 입력·서버 계산·명반 미리보기 연결 완료 / 전체 결과 서비스 미완료

## 작업 개요와 요구사항

REQ-01·02·03·10의 첫 연결 단계로 입력 → 서버 검증·계산 → 명반 미리보기를 구현한다. 저장·개인화 해석·공유는 후속 범위이며 출시 완성 화면으로 취급하지 않는다.

## 결정과 근거

설치된 Next.js forms 가이드의 네이티브 form·Server Action·서버 스키마 검증 패턴을 사용한다. 입력은 브라우저 메모리에 유지하며 URL·저장소에 기록하지 않는다. 서버는 기존 계산 함수를 재사용하고 비공개 정규화 정보는 응답에서 제외한다. 개인화 해석 대신 기본 읽는 법임을 명확히 표시한다.

## 변경·검증·요구사항 대조

- BirthForm: 날짜·달력·윤달·24시간 시각·성별, 필드별 오류와 오류 요약 포커스, 제출 잠금, 입력값 유지. 빈 숫자 문자열을 0으로 변환하지 않는다. 시각의 기본값을 임의 지정하지 않는다.
- calculatePreview: FormData를 서버에서 다시 파싱한 후 기존 정규화·계산 호출. 익명·무상태 연산이며 저장된 자원 조회·수정 권한이 없다. 응답은 chart만 반환하여 비공개 정규화 birth를 노출하지 않는다. POST를 지정하여 hydration 이전 기본 제출도 URL에 개인정보를 넣지 않게 한다.
- 로딩: 실제 요청 중 전용 화면 상태만 표시하고 가짜 진행률·최소 대기를 추가하지 않는다. 네트워크 오류는 재시도 가능한 안내로 반환한다.
- 명반: 고정 지지의 4×4 둘레에 12궁과 14주성을 표시한다. 명궁·신궁, 오행국과 공통 읽는 법을 제공한다. 개인화 해석인 것처럼 표시하지 않는다.
- 입력 유지에는 네이티브 form DOM과 화면의 React 상태만 필요하여 Jotai에 복제하지 않았다. 전역 상태 수요가 생길 때 설치된 Jotai를 사용한다.
- 실제 엔진을 Next 서버 번들에 연결하며 드러난 package.json named import 경고를 default import로 수정했다.

검증: pnpm check의 포맷·ESLint·타입·103개 테스트가 통과했다. 7개 추가 테스트는 빈 시각, 중복 필드, 실제 날짜 오류·역사적 누락 시각, 비공개 정보 제외, 한국 음력/양력 동등성을 검증한다. 브라우저에서 빈 입력 오류·2월 30일 서버 오류·정상 계산·12궁 표시·입력 복귀와 값 유지·오류 및 결과 포커스를 확인했다. 390px에서 명반과 문서 너비가 맞고 가로 넘침이 없음을 확인했다. 로딩은 계산이 빨라 지속 화면 캡처를 하지 못했으며 임의 지연을 넣지 않았다. 서버 연결 실패·요청 중단·느린 네트워크는 브라우저 재현하지 않았다.

REQ-01·02·03·10과 대조했다. 입력 수집 범위·서버 검증·같은 생일의 계산 일관성을 유지했다. 이번 미리보기는 개발 단계의 실제 계산 연결이다. 저장과 생성 작업 없이 reportId 라우트를 임시 생성하지 않았다. REQ-02의 장시간 중단 처리·서버 작업 복원, REQ-03의 개인화 해석, REQ-04~07의 상세·탭·공유·툴팁을 완료 처리하지 않는다. 기능 수행 불가에 따른 축소나 대체 구현이 아니라 후속 미구현 범위다. 동작하는 입력/계산 흐름 위에 순차적으로 연결한다.

## 후속 개선

저장·소유권·해석 정책 확정 후 결과 라우트·새로고침 복원·공유를 연결한다. 이번 메모리 상태를 영속 결과 저장의 대안으로 취급하지 않는다.
