# 문단별 본문·근거·연결 설명 검증

- 작성일·최종 갱신일: 2026-09-12
- 상태: 완료 — 구현·모의 검증 완료, 새 구조 1회 실평가 실패, 커밋 보류

> 현재 기준: 사용자가 쉬운 풀이와 펼쳐 보는 근거 설명을 분리하도록 승인했다. 아래 문자 일치 검사와 본문에 전문 용어를 요구하는 방식은 [후속 작업](2026-09-12-reading-and-evidence-disclosure.md)에서 제거했다.

## 작업 개요와 요구사항

사용자가 본문과 근거를 함께 생성하고 문장·문단별로 사용 근거와 연결 이유를 대응시키며, 설명 없는 인용을 검출하도록 요청했다. requirements.md AI 명반 해석의 공통 기준에 적용한다. 제목·전체 요약·7개 분야·조언 목록·마무리를 모두 포함한다. 추가 유료 호출·배포·커밋은 이번 범위가 아니다.

## 결정과 근거

현재 스키마는 본문 배열과 섹션별 evidenceIds를 따로 받아 두 값의 대응을 검증할 수 없었다. 설치된 Zod·OpenAI SDK의 strict object/array 스키마를 사용해 각 문단을 `{text, evidence: [{id, reason}]}`로 생성한다. reason은 사용자 text에 실제 포함된 연속 구절이며 검토 메모나 숨겨진 추론 요청이 아니다. 서술된 연결 이유 자체를 근거와 연결한다.

새 provider 계약만 수용한다. 이전 섹션 evidenceIds 입력의 호환 경로는 없다. 검증 뒤 화면에 필요한 텍스트·블록별 근거 목록을 도출하는 것은 provider 응답을 표시 모델로 변환하는 책임이다. 화면에서 사용하는 ValidatedExplanation은 유지하며 이유는 이미 본문에 들어 있으므로 별도 설명을 중복 표시하지 않는다.

이름 검사만으로 해석이 타당한지 판정할 수는 없다. 현재 데이터의 실제 궁 이름·제공된 별칭과 별 이름이 대응하는지 확인하는 구조 검증이다. 이름이 포함돼 있어도 연결 이유가 설득력 없으면 별도 의미 검토 대상이다. 자동 의미 심사 모델을 추가하지 않고 비용·지연을 늘리는 추가 호출도 도입하지 않는다.

## 변경 내용과 영향

- 전체 text 단위에 허용 ID와 10자 이상 reason을 요구한다. reason은 같은 text의 구절이어야 한다.
- 인용한 궁은 실제 이름 또는 제공된 별칭, 별은 실제 이름이 그 reason에 있어야 한다. 사화는 실제 출발·도착 궁과 별이 필요하다. 격국은 matched=true이고 이름이 설명에 있어야 한다.
- 각 인용을 검증한 다음 근거 ID를 첫 등장 순서로 집계·중복 제거한다. 설명 없는 중복 인용을 제거로 숨기지 않는다.
- 제목·조언·마무리도 같은 계약을 사용한다. 프롬프트는 grounded-passages-v1로 변경했다. 모델과 출력 토큰 한도·재시도 정책은 유지한다.
- 표시 컴포넌트는 검증된 본문과 집계된 근거를 그대로 사용한다. 원본의 문단별 대응은 opt-in 평가 자료에서 확인할 수 있다.

## 검증

Node.js 24에서 `pnpm check` 통과: 포맷·린트·타입·236개 테스트, 기본 유료 평가 1개 건너뜀. `pnpm build` 통과. 첫 전체 검사의 타입 오류는 이전 테스트 2개가 옛 응답 구조를 사용한 것이어서 새 구조로 수정 후 재검사했다. 새 출력 형식에서 JSON Schema 생성, 미사용 인용·빈 설명·다른 문단의 설명·알 수 없는 ID·옛 목록·사화 누락·모든 text 범위와 중복 처리를 확인했다. 문자열 선언을 복제하는 테스트는 만들지 않았다.

## 요구사항 대조와 남은 작업

종료 전 코드·프롬프트·문서를 요구사항과 대조했다. 본문과 근거를 함께 생성하고 이유를 문단에 대응시키는 확정 요구사항을 구현했다. 이유 없이 달라진 항목이나 수행 불가에 따른 요구사항 변경은 없다. 사용자 화면 흐름을 바꾸지 않고 본문에 설명을 담는다. 규칙 준수 여부와 해석 타당성은 구분한다. 후속 1회 실평가에서 새 구조 생성은 확인했으나 본문·설명 구절의 일치 요구를 지키지 못했다. 자세한 결과는 아래에 기록한다. 규칙을 통과하기 위해 이름만 나열하는 응답까지 의미적으로 승인하지 않는다.

## 후속 실제 응답 평가와 조건부 커밋

사용자가 실제 응답 확인 후 문제없으면 커밋하도록 요청해 같은 reference 명반으로 1회 호출했다. 모델은 유지하고 grounded-passages-v1을 사용했다. HTTP 200, 25.780초, 출력 계약 검사는 통과했지만 근거 대응 검사는 실패해 invalid-response로 차단됐다. 따라서 `pnpm eval:ai`의 ready 기대 테스트도 실패했다. 재시도하지 않았다.

총 38개 text 객체의 62개 인용 중 54개 reason이 해당 text에 그대로 포함되지 않았다. 첫 전체 요약은 “명궁의 무곡과 파군은…”인데 reason은 “명궁에 무곡과 파군이 함께 있어…”로 바꾸어 썼다. 제목·조언·마무리에도 다른 문단의 구절을 붙이거나 별도로 요약한 설명을 넣었다. 이는 현재 구조가 요구하는 문단별 구절 대응 미준수이며, 표현 차이만으로 해석 의미 자체가 틀렸다고 판단한 것은 아니다.

새 검증이 실제 불일치를 차단하는 것은 확인했다. 다만 검증 강화와 모델의 준수율 개선은 별개다. 금전 본문은 빠른 판단에서 기준 관리로, 전택궁의 생활 기반에서 돈과 생활 계획을 함께 보라는 설명으로 이어졌고 질액궁 천량을 재정 조언에 직결하는 문장은 없었다. 그러나 전체 대응 기준을 충족하지 않아 결과를 승인하지 않았다. 아직 이름 검사·의미 평가 전체를 통과한 결과는 아니다.

입력 16,354토큰(캐시 0), 출력 4,392토큰, 코드 단가 기준 약 **$0.032030**이다. 직접 평가라 Supabase 운영 집계에 포함되지 않는다. 원문·수동 검토는 git 제외 파일 `work/ai-evaluations/reference-1789218585967.json`에 보관했다.

요구사항 대조: 본문에 실제 포함된 연결 설명을 요구하는 현재 기준을 낮추거나 응답을 임의로 고치지 않았다. 사용자 조건에 따라 커밋을 보류했다. 이번 턴의 제품 코드 변경은 없고 추가 유료 호출·배포도 하지 않았다. 다음 보완은 모델이 본문 구절을 정확히 대응시키게 하는 생성 방식 검토이며, 다른 표현을 허용하는 정책 변경이 필요하면 현재 기준과 구분해야 한다. 문서 변경 후 포맷·diff 검사를 수행하고, 직전 통과한 전체 검사·빌드는 코드 변경이 없어 반복하지 않았다.
