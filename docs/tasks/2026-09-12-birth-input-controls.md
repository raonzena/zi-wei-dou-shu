# 출생 정보 입력과 홈 이동 개선

- 작성일: 2026-09-12
- 최종 갱신일: 2026-09-12
- 상태: 완료 (후속 요청으로 시각 모름 선택 제거)

## 작업 개요

Brand 홈 링크, 날짜·시각 목록의 클릭 영역 확대, 입력 자릿수 제한, 출생 시각 모름 선택을 다룬다.

## 요구사항

[요구사항](../requirements.md)의 출생 정보 입력 절과 사용자 추가 요청을 따른다. 연도는 4자리, 월·일·시·분은 2자리까지 받는다. 시각 미상 명반은 기존 요구사항대로 제공하지 않는다. 범위 확인 질문에 답변이 없는 상태에서 기존 정책을 유지한다고 안내하고, 모름 선택과 계산 보류를 구현했다. 시간대별 후보 명반은 확정하거나 구현하지 않았다.

## 결정과 근거

설치된 Base UI 1.8.0의 `openOnInputClick`과 InputGroup의 `handleInputPress`가 입력 영역 클릭과 포커스를 처리한다. 별도의 클릭 이벤트를 겹쳐 구현하지 않는다. native text input의 maxLength와 제어된 값의 길이 제한을 함께 적용하고 서버도 원본 문자열 길이를 확인한다. Brand는 Next Link의 onNavigate에서 /로 문서 이동하도록 만들어 같은 URL에 남은 결과도 초기화한다. prefetch는 사용하지 않는다. 새 탭 열기 등 링크의 기본 동작은 유지한다.

## 변경 내용과 영향

- Brand 홈 링크와 키보드 포커스 표시를 추가했다.
- Base UI의 openOnInputClick으로 입력과 InputGroup을 누르면 목록이 열린다.
- 연도 4자리, 나머지 2자리 제한을 입력창과 서버에 적용했다. 기존 최소·최대 범위 검증은 유지한다.
- 시각 모름 체크박스를 추가했다. 시·분과 제출 버튼을 비활성화하고 이유를 안내한다. 해제하면 기존 값을 다시 편집할 수 있다. 서버는 모름 값이 있는 요청과 변조·중복 값을 거부한다.
- 기존 풀이·DB·AI 작업의 변경은 그대로 유지했다.

## 검증

- pnpm check 통과: 포맷·ESLint·타입 검사, 테스트 256개 통과, 유료 실평가 1개 건너뜀.
- 초기 검사에서 일반 a 태그가 Next Link 규칙에 걸려 Link와 공식 onNavigate API로 수정했다. 검사 예외를 추가하지 않았다.
- 브라우저에서 입력 클릭으로 목록 열기, 다섯 필드의 초과 자릿수 제한, 시각 모름 비활성화와 해제 시 기존 값 유지, 정상 계산, 결과에서 홈 이동과 초기화를 확인했다.
- 서버 테스트로 숫자로는 유효한 초과 길이 문자열, 0으로 시작하는 정상 두 자리 값, 모름 요청·변조·중복을 확인했다.
- pnpm build 통과.
- AI 호출은 하지 않았다. 터치 기기 실물 검증은 수행하지 않았다.

## 요구사항 대조

요구사항과 화면 흐름에 홈 이동·자릿수·시각 모름 조작을 기록했다. 기존 날짜 범위, 역사적 시간 보정, 시각 미상 계산 금지 정책과 일치한다.

## 남은 문제와 추후 개선점

시각 미상으로도 결과를 제공하려면 시간대별 비교 등 계산 정책의 별도 결정이 필요하다. 이번 작업은 이를 제공하지 않는다.

## 후속 변경: 시각 모름 선택 제거

- 사용자 결정: 시각 미상으로 명반 풀이를 제공할 수 없으므로 해당 선택을 제거한다.
- 체크박스, 상태, 조건부 입력·제출 비활성화, 전용 서버 처리와 테스트를 제거했다. 시·분 필수 검증과 빈 값을 자정으로 변환하지 않는 기존 검증은 유지한다.
- 화면에는 시각 입력이 필요한 이유만 안내한다. 홈 링크, 목록 클릭 영역, 자릿수 제한은 유지한다.
- requirements.md와 screen-flow.md를 최신 결정에 맞췄다. 위 시각 모름 구현·검증 기록은 제거 전 이력이다.
- 후속 검증: 입력·서버 경계 테스트 24개와 타입 검사 통과. 관련 소스에 시각 모름 상태·선택이 남아 있지 않은 것을 확인했고 git diff --check도 통과했다. 이번 제거 후 브라우저 검증과 전체 빌드는 재실행하지 않았다.
- 남은 사항: 시각 미상 명반은 제공하지 않는다. 이번 제거 범위의 미결정 사항은 없다.
