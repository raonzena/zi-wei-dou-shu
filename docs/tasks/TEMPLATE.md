# 작업 제목

- 작성일: YYYY-MM-DD
- 최종 갱신일: YYYY-MM-DD
- 상태: 진행 중 / 완료 / 보류 (하나를 선택하고 범위를 명시)

## 작업 개요

해결할 문제, 목적, 이번 작업 범위와 완료 기준을 작성한다.

## 요구사항

관련 requirements.md의 ID 또는 절을 연결하고 이번 작업에서 충족할 수용 기준을 기술한다. 사용자 추가 지시, 설계안, 미결정 사항을 구분한다.

## 결정과 근거

결정한 내용과 이유, 확인한 근거를 작성한다. 실제 비교한 대안이 있다면 선택·제외 이유를 기록한다. 상세 아키텍처 결정은 ADR을 연결한다.

## 변경 내용과 영향

실제로 변경한 파일·모듈과 동작을 기술한다. 데이터·API·사용자 경험 등 영향을 받는 항목만 설명한다.

## 검증

실행한 명령 또는 확인 방법과 결과를 기록한다. 수행하지 못한 검증과 이유, 결과 해석의 한계도 명시한다.

## 요구사항 대조

관련 요구사항과 결과를 비교하고 일치 여부, 수정한 차이, 남은 미구현 항목을 기록한다. 수행 불가로 방향을 변경했다면 requirements.md의 이유·변경 방향 기록을 연결한다.

## 남은 문제와 추후 개선점

확인된 문제, 다음 행동과 착수 조건을 기록한다. 확정 후속 작업과 제안을 구분한다. 개선점이 없다면 없다고 명시한다.

## 참고 자료

관련 코드·요구사항·ADR·공식 문서를 연결한다. 외부 문서는 확인한 버전이나 날짜가 판단에 중요하면 함께 기록한다.
