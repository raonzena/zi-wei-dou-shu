# Google AdSense 광고 수익화

- 작성일: 2026-09-13
- 최종 갱신일: 2026-09-14
- 상태: 구현·코드 검증 완료 / AdSense 계정 연결 전

## 작업 개요

결과 풀이를 방해하지 않는 위치에 Google AdSense 광고 한 개를 표시할 수 있도록 연동 구조를 추가한다. 게시자 설정 전에는 외부 광고 코드와 빈 광고 영역을 만들지 않고, 설정 후에는 사이트 확인과 광고 게재에 필요한 메타 태그·ads.txt·반응형 광고 단위를 제공하는 것을 완료 기준으로 삼는다.

## 요구사항

- REQ-11: 결과 풀이 하단에서 명확히 구분한 광고로 운영 수익을 낼 수 있어야 한다.
- 출생 정보 입력, 로딩·오류 화면과 탭·공유·다시 보기 버튼 주변에는 광고를 표시하지 않는다.
- 광고 활성화 여부와 관계없이 모든 화면에서 개인정보 및 쿠키 안내를 확인할 수 있어야 한다.
- AdSense 계정 승인과 실제 식별자 등록은 외부 운영 작업으로 구분한다.

## 결정과 근거

- 사용자는 광고를 붙여 수익을 내는 기능을 요청했다. 별도 광고 사업자를 지정하지 않아 웹 콘텐츠 광고에 일반적으로 사용하는 Google AdSense를 선택했다.
- 결과 콘텐츠가 끝난 뒤 행동 버튼보다 앞에 광고 한 개만 배치한다. 출생 정보 입력과 주요 조작 영역에는 광고를 두지 않으므로 실수로 광고를 누를 가능성과 풀이 흐름의 방해를 줄인다.
- `NEXT_PUBLIC_GOOGLE_ADSENSE_CLIENT_ID`와 `NEXT_PUBLIC_GOOGLE_ADSENSE_RESULT_SLOT_ID`를 공개 설정으로 사용한다. 두 값이 모두 유효할 때만 결과 경로에서 스크립트와 광고 단위를 생성한다.
- 게시자 ID만 있어도 AdSense 사이트 확인을 진행할 수 있도록 확인용 메타 태그와 루트 ads.txt는 광고 단위 설정과 분리한다.
- Google 공식 문서는 AdSense 승인 전에는 광고를 표시할 수 없다고 안내한다. 또한 개인정보 처리방침에서 제3자의 광고 쿠키·IP 주소·웹 비콘 사용과 맞춤 광고 설정 방법을 안내해야 하며, EEA·영국·스위스 사용자에게 광고를 제공할 때는 Google 인증 CMP 요건을 확인해야 한다.
- 저장된 결과 URL이 외부 광고 요청의 리퍼러로 전달되지 않도록 결과 페이지 정책을 `strict-origin`으로 설정한다. Google 개인정보 메시지가 동작하는 데 필요한 출처 정보는 유지한다.

## 변경 내용과 영향

- `src/features/ads/`: 광고 설정 검증, 결과 광고 단위와 스타일을 추가한다.
- `src/app/result/layout.tsx`: 결과 경로에서만 AdSense 스크립트를 불러온다.
- `src/app/ads.txt/route.ts`: 유효한 게시자 ID를 Google ads.txt 항목으로 제공한다.
- `src/app/privacy/`: 출생 정보, 결과 보관, 운영 기록, 광고 쿠키와 외부 서비스 사용을 설명한다.
- 공통 하단에 개인정보 및 쿠키 안내 링크를 추가한다.
- 결과 페이지의 외부 리퍼러에는 경로를 제외하고 출처만 제공한다.
- 환경변수 예시, README, 현재 요구사항과 화면 흐름을 함께 갱신한다.

## 검증

- 광고 설정, 렌더링과 `/ads.txt` 단위 테스트 7개가 통과했다.
- Prettier, ESLint, Next.js 라우트 타입 생성과 TypeScript 검사가 통과했다.
- 전체 테스트는 단일 워커에서 307개가 통과하고 실호출 평가 1개가 제외됐다. 기본 병렬 실행은 이 환경에서 여러 iztro 계산이 동시에 5초 제한을 넘겨 23개가 실패했으나, 같은 테스트를 단일 워커로 다시 실행했을 때 모두 통과했다.
- 더미 형식의 게시자 ID와 결과 광고 단위 ID를 설정한 Next.js 운영 빌드가 통과했다. `/ads.txt`, `/privacy`, `/result/[id]` 경로가 배포 산출물에 포함됐다.
- 로컬 브라우저 시각 검증은 브라우저 환경이 로컬 주소를 차단해 수행하지 못했다.
- 실제 광고 요청과 노출은 AdSense 사이트 승인과 운영 식별자 등록 전이므로 검증하지 못했다.

## 요구사항 대조

광고 코드와 개인정보 안내는 REQ-11의 구현 범위와 일치한다. 설정이 없는 현재 환경에서는 광고 요청과 빈 영역이 생기지 않는다. AdSense 계정 승인, 광고 단위 발급, 대상 지역별 동의 관리 설정과 운영 환경변수 등록은 코드에서 대신할 수 없는 외부 작업으로 남긴다.

## 남은 문제와 추후 개선점

- AdSense 계정에서 운영 사이트를 추가하고 승인을 요청해야 한다.
- 승인 뒤 결과용 반응형 디스플레이 광고 단위를 만들고 두 공개 식별자를 Vercel Production에 등록해야 한다.
- EEA·영국·스위스 방문자를 포함해 서비스할 경우 AdSense 개인정보 메시지에서 Google CMP를 설정해야 한다.
- 실제 트래픽에서 광고 노출, 레이아웃 안정성, 풀이 이탈률을 확인한 뒤 광고 수나 위치를 다시 판단한다. 추가 광고는 현재 확정 범위가 아니다.
