# 실제 AI 해석 검증과 오류 분류 보완

- 작성일: 2026-09-11
- 상태: 연결·오류 처리 검증 완료 / 해석 품질 추가 검토 필요

## 작업 개요와 요구사항

사용자가 기존 작업 커밋 후 실제 AI 해석 검증과 오류 처리 보완을 승인했다. REQ-02·03·05·07에 따라 실제 생성과 근거·한국어·시간·비용을 확인하고, 결제·사용량 제한을 일시적인 오류와 구분한다. 유료 호출은 필요한 경우에만 수행한다.

## 결정과 근거

OpenAI 공식 오류 문서와 설치된 SDK의 APIError.code/type을 확인했다. HTTP 429만으로 분류하지 않고 크레딧·조직/프로젝트 지출·조직 사용량 제한과 insufficient_quota 유형을 재시도 불가 상태로 처리한다. 일반 사용자에게 서비스 운영자의 확인이 필요함을 알린다. 원본 제공자 오류와 키는 전달하지 않는다. 기존 retryable UI를 사용하므로 별도 상태 계층은 추가하지 않는다.

## 검증 계획

오류는 모의 fetch로 검증하고 실제 요청은 우선 한 번만 수행한다. 같은 응답으로 구조·내용·usage를 확인한다. 실제 생성 결과 한 건을 전체 품질 검증으로 확대 해석하지 않는다.

## 실제 검증 결과와 수정

실제 OpenAI 호출은 두 번만 수행했다. 첫 응답을 분석한 뒤 수정 효과를 확인하기 위해 두 번째 호출을 사용했다. 나머지 검증은 모의 응답 또는 같은 응답의 로컬 재생으로 수행한다. 일반 테스트에 실제 호출 파일을 남기지 않는다.

| 요청    | 입력 토큰 | 캐시 입력 | 출력 토큰 |     시간 |  계산 비용 | 결과           |
| ------- | --------: | --------: | --------: | -------: | ---------: | -------------- |
| 최초    |     7,766 |         0 |     7,199 | 48.945초 |  $0.038220 | 구조 검증 거부 |
| 수정 후 |     8,606 |         0 |     7,236 | 48.171초 | $0.0390165 | 정상 응답      |

두 요청 모두 HTTP 200, 추론 토큰 0이었다. 총 계산 비용은 $0.0772365다. 공식 표준 단가인 입력 $0.75/100만 토큰, 출력 $4.50/100만 토큰을 적용했으며 청구서의 세금·반올림을 포함한 금액은 아니다. 시간은 서버 함수 호출부터 응답 검증까지의 로컬 측정이며 모든 사용자의 예상 시간으로 일반화할 수 없다.

최초 응답은 12개 번호와 JSON 스키마를 만족했지만 근거 ID 중복, 팔좌의 잘못된 분류, 7단계 결혼 누락으로 인한 주제 이동, 11단계 시기 자료 없는 분석이 발견됐다. 기존 검증기가 이를 거부했다. 일부 문장에는 한국어 외 단어도 섞였다.

검증을 느슨하게 바꾸지 않았다. 생성 스키마의 근거 ID를 실제 입력 ID의 enum으로 제한하고, 서비스 적용 규칙에 12단계 번호와 주제를 명시했다. 연애와 결혼을 합치지 않도록 하고 중복 근거·언어 혼용을 금지했다. 사용자 첨부 원문은 유지하며 적용 규칙의 버전은 user-consultation-v2로 올렸다.

두 번째 응답은 12단계 순서와 주제가 맞고, 3·10·11단계에는 분석 문단이 없었다. 근거 ID가 모두 허용 목록에 속하며 문단 내 중복도 없었다. 명궁 무곡·파군, 신궁 묘, 관록 자미·탐랑, 재백 염정·칠살과 삼방사정의 위치 서술을 입력과 대조했다. 한국어 존댓말로 작성됐으며 건강 진단·수명·구체적인 재정 사건의 확정 예측은 발견하지 못했다.

## 품질 한계와 후속 개선

한 건의 구조 통과는 해석 품질 전체의 통과가 아니다. 건강·인간관계 항목은 각각 2문단으로 요청의 조건부 3~6문단보다 짧다. ‘천괴는 예민한 긴장 반응’, ‘천이가 좋아’ 같은 해석에는 근거 설명과 전통 해석 출처 대조가 더 필요하다. 일부 문장의 단정적인 어투와 반복 표현도 편집 검토 대상으로 남긴다. 이런 의미적 판단은 ID 검사만으로 보장되지 않는다. 호출 최소화 요청에 따라 품질 비교를 위한 추가 생성은 하지 않았다.

## 요구사항 대조

REQ-02의 원인별 안내에 맞춰 재시도로 해결할 수 없는 한도 오류 안내를 복구했다. REQ-03·05·07의 명반 하단 해석, 탭 재사용, 용어 설명은 유지한다. 사용자 프롬프트 원문·계산 정책·표시 범위를 축소하지 않았다. 시기 해석, 다양한 사례의 독립 품질 검토와 출시 수용 기준은 여전히 미완료다.

## 최종 검증과 캡처

오류·요청 스키마 검증을 포함한 테스트 149개, lint, 운영 빌드가 통과했다. 로컬 재생 서버를 사용하는 브라우저에서 한도 오류 문구와 재시도 버튼 0개, 실제 생성 응답의 12단계 표시와 전체 펼치기를 확인했다. 이는 브라우저에서 OpenAI를 다시 호출한 검증이 아니라 실제 서버 함수의 응답을 재사용한 UI 검증이다.

사용자의 추가 요청으로 당시 화면, AI 선택 입력 화면, 12단계를 펼친 결과 화면을 JPEG로 저장했다. 산출물은 Codex 작업 outputs에 있으며 서비스 저장·공유 기능을 추가한 것은 아니다. 임시 실제 호출 테스트는 일반 테스트 검색 범위에서 제거했고 모의 서버는 검증 후 종료한다.

커밋 전 전체 check는 작업 외 .agents 문서 42개의 포맷 문제로 실패했다. 이번 변경 파일만 포맷을 검사하며 해당 파일들을 임의 수정하거나 검사에서 제외하지 않는다.
