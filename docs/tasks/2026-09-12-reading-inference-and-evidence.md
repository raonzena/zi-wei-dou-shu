# 가능성 해석 기준과 분야별 근거 연결 수정

- 작성일·최종 갱신일: 2026-09-12
- 상태: 완료 — 합의한 v5 지침 반영·재평가 완료, 전체 응답 품질 보완 필요

## 작업 개요와 요구사항

사용자는 건강을 포함한 가능성 해석을 허용하고, 금전 해석의 근거 연결 부족 원인 파악과 수정을 요청했다. requirements.md 5절 AI 해석 기준을 명확히 한다. 운영 활성화·배포는 범위에 포함하지 않는다. 후속 요청에 따라 같은 명반의 유료 재평가 1회를 수행했다.

## 원인과 결정

저장된 v3 응답은 질액궁 천량의 일반적인 의미를 지출 관리 성향으로 연결했다. 별 배치는 맞지만 해당 문장은 금전 분야와의 연결을 설명하지 않았다. 모델 내부 원인을 확정한 것은 아니다. 모든 궁을 제공하면서 관련 궁을 함께 읽으라는 지시만 두고, 분야별 중심 궁과 추가 근거의 관련성을 설명하는 기준을 두지 않은 점을 확인했다. 검증기는 ID·구조·사화 표현을 검사하므로 이런 의미적 비약을 차단하지 않는다.

이미 전송하는 relatedPalaceIds·flyingTransformations를 사용하도록 지시한다. 새로운 계산법이나 해석표는 만들지 않는다. 자연어 타당성을 정규식만으로 판단할 수 없으므로 임의의 단어 차단은 추가하지 않았다. 프롬프트 수정만으로 재발 방지를 보장하지 않는다.

## 변경 내용과 영향

- 건강을 포함한 가능성 해석 허용을 요구사항과 프롬프트에 명시했다. 체질·피로·회복 추측 일괄 금지와 일반 관리 조언만 허용하는 제한을 제거했다. 신궁과 질액궁의 구분은 유지한다.
- 금전은 재백궁을 중심으로 읽고 다른 궁은 실제 관계와 관련성을 설명하도록 했다. 질액궁 천량의 일반적 뜻만으로 지출 성향을 도출한 실패 예시를 넣었다. 사화 사용 시 연결 ID를 인용한다.
- 프롬프트는 concise-consultation-v4로 변경했다. 모델·호출 횟수·응답 스키마는 유지한다.
- 이전 검증 문서에 건강 해석 판정 정정을 표시했다. 당시 실제 응답과 검사 결과는 역사적 기록으로 유지한다.

## 검증

Node.js 24에서 `pnpm test:ai` 41개 테스트 통과. 변경 파일 Prettier 검사와 `git diff --check` 통과. 현재 소스·요구사항·화면 흐름에서 추측 일괄 금지 문구가 남지 않았는지 검색했다. 문자열 지침 변경이므로 선언을 복제하는 테스트는 추가하지 않았다. 프롬프트 수정 시 유료 호출은 하지 않았으며, 아래 후속 요청에서 1회 수행했다. 빌드는 이번 프롬프트·문서 변경 후 반복하지 않았다.

### 후속 실제 응답 비교

사용자가 실제 개선 여부 확인을 요청해 같은 reference 명반을 v4로 1회 호출했다. 자동 재시도 없이 HTTP 200, ready, 구조·근거 ID 검증 통과, 21.340초다. 입력 13,736토큰(캐시 3,840), 출력 3,226토큰으로 코드 단가 기준 약 $0.022227이다. 직접 평가이므로 운영 Supabase 집계에는 포함되지 않는다. 평가 파일은 git 제외 경로 `work/ai-evaluations/reference-1789216387072.json`이다.

- 개선: 질액궁 천량의 '균형'을 금전 관리로 바로 연결한 기존 문장은 사라지고 재백궁 염정·칠살을 중심으로 썼다. 건강의 가능성 표현은 사용자가 확정한 기준에서 위반으로 판정하지 않는다.
- 미해결: “재백궁으로 들어오는 연결이 여러 군데 보이기 때문에 … 규칙으로 관리할수록 안정감”이라는 문장은 연결의 내용·영향을 설명하지 않는다. 존재하는 연결의 수만으로 지출 관리 결론이 입증되지는 않는다.
- 인용 오류: 돈 분야의 사화 ID 4개 중 `flying:사:3`은 명궁→부처궁 문곡 화기, `flying:신:0`은 전택궁→질액궁 천량 화록이다. 둘은 재백궁 유입이 아니다. `flying:술:0`은 노복궁→재백궁 염정 화록, `flying:자:3`은 질액궁→재백궁 염정 화기로 실제 연결이다. 기존 fixture의 궁·별 배치와 설치된 iztro의 getMutagensByHeavenlyStem, projectFlyingTransformations의 ID 순서를 대조했다.
- 자동 검증 한계: 내부 ID는 모두 존재하고 본문은 구체적인 사화 출발·도착을 명시하지 않아 현재 검증을 통과했다. 의미 품질은 개선 필요로 기록했다.

따라서 이번 단일 사례에서 이전 문장의 제거는 확인했지만 근거 연결 문제 해결을 승인하지 않는다. 추가 호출이나 후속 코드 변경은 하지 않았다. 다음 보완에서는 문장에 사용한 연결과 실제 인용 관계를 맞추는 검증이 필요하다. 다른 명반으로의 일반화는 검증하지 않았다.

## 요구사항 대조와 남은 작업

사용자가 확정한 가능성 해석 허용을 반영했다. 수행 불가나 요구사항 완화가 아니라 에이전트가 과도하게 적용한 제한을 바로잡았다. 후속 실평가에서도 분야별 연결 오류가 남아 운영 AI는 비활성 유지한다.

## 합의한 설명 기준 반영과 v5 재평가

- 상태: 완료 — 금전 설명 개선 확인, 전체 응답 검증 실패
- 사용자가 궁 연결의 사용 이유, 근거→경향→조언 설명, 본문과 인용 근거의 대응을 요구사항으로 확정했다. requirements.md와 프롬프트에 반영하고 v5로 올렸다. 모델과 응답 구조는 유지한다.
- 이전 v4 평가의 '인용 오류' 판정은 정정한다. 섹션 전체 인용 중 다른 궁으로 향하는 연결이 있다는 사실만으로 오류는 아니다. 재백궁 유입이 실제로 2개 있어 '여러 군데'라는 설명도 사실과 다르다고 단정할 수 없다. 확인된 문제는 나머지 인용의 용도와 조언까지 이어지는 설명이 불명확하다는 점이다.
- 같은 기준 명반으로 유료 호출 1회만 수행해 실제 출력의 개선 여부를 확인한다. 자동 구조 검사와 수동 의미 검토를 구분한다. 운영 활성화·배포는 하지 않는다.

### v5 실제 검증 결과

- `pnpm test:ai`: Node.js 24에서 모의 테스트 41개 통과. 변경 파일 포맷과 `git diff --check` 통과.
- `ZIWEI_LIVE_EVAL=1 ZIWEI_EVAL_CASE=reference pnpm eval:ai`: 1회 호출, HTTP 200, 15.921초. 구조 검사는 통과했으나 커리어의 `star:유:major:탐랑` ID 중복으로 `invalid-response`가 되어 실평가 테스트는 실패했다. 정상 사용자 결과로 제공하지 않았다. 재시도하지 않았다.
- 입력 13,882토큰(캐시 4,352), 출력 3,211토큰. 저장된 사용량과 코드 단가로 약 **$0.021924**다. 운영 예약 경로 밖의 직접 평가이므로 Supabase 집계에 포함되지 않는다.
- 기록: git 제외 파일 `work/ai-evaluations/reference-1789217166882.json`에 원문과 수동 검토를 저장했다.

금전 분야는 이전보다 설명이 구체적이다. “재백궁에 염정과 칠살 → 빠르게 판단하는 경향 → 지출 선택도 빨라질 가능성 → 지출 기준·재확인”의 연결이 문단과 목록에 드러났다. 명궁 무곡과 관록궁 자미·탐랑을 함께 사용하는 이유도 “일의 성과, 책임 범위, 사람을 다루는 위치”와 돈이 연결된다고 설명한다. 재백궁 축의 삼합궁은 사·유이므로 제공된 관련 궁과 일치한다. 금전 근거 7개는 모두 본문에서 언급한 궁·별과 대응한다. v4의 설명 없는 사화 목록과 '연결이 많으니'라는 문장은 사라졌다. 사화를 이번 금전 응답에서 사용하지 않았으므로 사화 연결 설명의 개선은 검증하지 못했다.

전체 응답에서는 본문에 사용하지 않은 근거가 남았다. 커리어 삼태·천관, 내면 우필·천월, 건강 천괴, 가족·대인관계 함지 등은 인용 목록에 있지만 본문 설명에 대응하지 않는다. 건강의 가능성 표현은 허용된 기준에서 위반으로 판정하지 않는다.

요구사항 대조 결과, 이번 단일 사례에서 금전 설명의 개선은 확인했지만 근거 중복과 사용하지 않은 인용이 남아 전체 응답은 미통과다. 프롬프트·요구사항 반영과 실제 평가 작업은 완료했으며 제품 품질이 완성됐다고 보고하지 않는다. 코드 검증기를 낮추거나 응답을 임의로 수정하지 않았고 운영 AI는 비활성 유지한다. 다음 보완 대상으로 근거 목록의 본문 대응·중복 처리를 기록한다. 새로운 유료 호출이나 배포는 하지 않는다.

## 전체 설명 공통 적용 범위 명시

사용자 요청으로 공통 기준의 범위를 전체 요약·일곱 분야의 제목/문단/조언 목록·마무리로 명시했다. 기존 요구사항은 금전만으로 제한하지 않았지만 프롬프트의 첫 문장과 예시가 금전 중심이라 공통 범위가 불명확했다. 금전 중심 문장·예시를 공통 문장으로 교체하고 v6로 변경했다. 요약에서도 해석·조언의 이유를 간결히 드러내도록 했다. 출력 구조·모델은 유지한다.

사용자가 질문한 v5 커리어 중복은 evidenceIds 배열의 `star:유:major:탐랑`이 3번째와 6번째에 반복된 것이다. 같은 별의 성향과 화권을 여러 번 설명하는 것은 가능하지만 블록의 근거 목록에는 같은 ID를 한 번만 넣는 현재 검증 규칙이 있다. 의미 오류나 본문 중복이 아니라 근거 목록의 중복이며 서버가 전체 응답을 invalid-response로 처리했다. 이번 요청에서는 중복 처리 정책이나 검증 코드를 바꾸지 않는다.

검증: Node.js 24의 `pnpm test:ai` 41개 통과, 변경 파일 Prettier와 `git diff --check` 통과. 요구사항 대조: 확정한 공통 적용 범위를 문서·프롬프트에 반영했고 금전 전용 지침으로 남기지 않았다. 추가 유료 평가·배포는 수행하지 않았으므로 v6 실제 응답 준수 여부는 미검증이다. 프롬프트 문자열 변경이므로 빌드는 반복하지 않았다.
