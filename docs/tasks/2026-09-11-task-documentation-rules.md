# 작업별 기술 문서 작성 규칙

- 작성일: 2026-09-11
- 최종 갱신일: 2026-09-11
- 상태: 완료 — 문서 작성 규칙·템플릿·목록 구성

## 작업 개요

작업의 목적과 판단 근거, 검증 결과를 대화 밖에서도 확인할 수 있도록 작업별 기술 문서 작성 방식을 정했다. 이번 범위는 규칙, 템플릿, 문서 목록 및 이 작업의 기록이다.

## 요구사항

사용자는 각 작업의 기술 문서를 페이지별로 작성하고, 작업 설명·요구사항·결정과 근거·추후 개선점을 포함하도록 지시했다. 이전 지시인 [요구사항 9절](../requirements.md#9-작업-종료-전-점검과-변경-기록)의 종료 전 대조도 문서에 포함한다.

완료 기준은 AGENTS.md에 지속 적용 규칙을 추가하고, 작업당 독립 페이지를 작성할 수 있는 구조와 필수 항목을 제공하는 것이다. 제품 기능 변경은 이번 범위에 없다.

## 결정과 근거

- 기존 프로젝트 문서와 동일한 Markdown을 사용하고 `docs/tasks/`에 작업당 한 파일을 둔다. 현재 저장소에서 검토·버전 관리할 수 있으며 별도 문서 도구가 필요하지 않다.
- 같은 작업의 후속 진행은 기존 문서를 갱신한다. 목적이 다른 작업은 별도 페이지로 구분한다.
- 사용자가 지정한 항목 외에 작업 상태, 실제 변경 내용과 영향, 검증 결과, 요구사항 대조, 참고 자료를 필수 항목으로 추가했다. 결정이 실제 결과에 어떻게 반영됐는지 확인하고, 검증하지 않은 내용을 완료한 것으로 오해하지 않도록 하기 위해서다.
- 요구사항은 requirements.md에, 아키텍처 결정은 ADR에 계속 기록한다. 작업 문서는 해당 원본을 연결하되 요구사항 변경 기록을 대신하지 않는다.
- 근거는 이번 사용자 지시와 기존 AGENTS.md·요구사항·ADR의 문서 구조다. 외부 라이브러리나 제품 동작에 관한 새 기술 선택은 없다.

## 변경 내용과 영향

- `AGENTS.md`: 작업별 문서 위치·작성 시점·필수 내용·완료 조건을 규정했다.
- `docs/tasks/TEMPLATE.md`: 필수 항목을 재사용할 수 있는 작성 구조를 제공했다.
- `docs/tasks/README.md`: 작업 페이지 목록과 상태를 관리한다.
- 루트 `README.md`: 작업별 기술 문서 목록으로 진입할 수 있게 연결했다.
- 이 페이지: 새 규칙에 따라 이번 작업을 기록했다.

앱 코드·데이터·API·실행 의존성에는 변경이 없다.

## 검증

변경 문서의 Prettier 검사와 `git diff --check`, 새 문서의 상대 링크 대상 존재 여부를 확인했다. 모두 통과했다. 문서 작성 시에는 앱 테스트와 운영 빌드를 재실행하지 않았다. 이후 누적 변경의 커밋 전 검증으로 Node.js 24.21.0에서 `pnpm check`(테스트 13개 포함)와 `pnpm build`를 실행하여 모두 통과했다. 계산 엔진 평가와 문서 규칙을 목적별 커밋으로 분리한다.

## 요구사항 대조

사용자가 요청한 작업 설명, 요구사항, 결정·근거, 개선점이 규칙과 템플릿에 모두 포함되어 있다. requirements.md의 종료 전 대조 절차도 필수 항목으로 연결했다. 제품 REQ-01~10의 범위나 수용 기준을 변경하지 않았으며 수행 불가에 따른 방향 변경은 없다.

## 남은 문제와 추후 개선점

다음 작업부터 같은 구조로 작업 페이지를 작성하고 종료 전에 실제 검증 결과와 목록 상태를 갱신한다. 이전 초기 설정·계산 엔진 평가 기록은 기존 ADR에 남아 있다. 과거 작업을 새 형식으로 소급 작성하는 작업은 이번에 수행하지 않았다. 별도 문서 자동화 도입 필요성은 현재 확인되지 않았다.
