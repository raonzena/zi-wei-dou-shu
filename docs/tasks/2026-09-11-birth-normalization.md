# 출생 정보 검증과 날짜·시간 정규화

- 작성일: 2026-09-11
- 최종 갱신일: 2026-09-11
- 상태: 구현 완료 — 검증·정규화 모듈 / UI·API·명반 배치 미연결

이 문서는 정규화 모듈을 구현했을 당시의 기록이다. 당시 미연결이었던 명반 계산과 입력 화면은 후속 작업에서 연결했다. 현재 화면 흐름은 [입력·미리보기 작업](2026-09-11-birth-input-preview.md)을 참고한다.

## 작업 개요

확정한 ziwei-v1 정책에 따라 한국 음력·양력 입력을 검증하고, 역사적 Asia/Seoul 시각을 계산용 고정 UTC+09:00 시각으로 변환한다. UI·API·명반 배치 연결은 후속 범위다.

## 요구사항

REQ-01·10과 ADR-0003을 따른다. 완료 기준은 같은 생일을 양력과 음력으로 입력했을 때 동일한 결과를 얻는 것이다. 1900년 이후의 지원 범위를 검사하고, 미래의 출생 순간과 잘못된 날짜·윤달·시각을 거부해야 한다. DST로 인해 중복되거나 존재하지 않는 시각도 거부한다.

## 결정과 근거

설치 의존성을 확인했으며 한국 달력 변환과 시진 매핑은 기존 API를 재사용한다. 기존 의존성에는 엄격한 스키마 검증과 명시적인 시간 중복·누락 거부 API가 없어 Zod와 Temporal polyfill의 공식 API를 확인해 추가한다. Temporal은 disambiguation reject를 제공하고 런타임 IANA 시간대 데이터를 사용한다. 브라우저 시간대 데이터 차이를 방지하기 위해 정규화는 서버 책임으로 둔다.

## 변경 내용과 영향

- `src/domain/birth/birth-input.ts`: Zod로 달력별 입력 스키마를 정의하고 엄격하게 검증한다. 양력의 윤달 플래그, 누락된 시각, 숫자 문자열의 암묵 변환, 요청 시간대 덮어쓰기를 허용하지 않는다.
- `src/domain/birth/normalize-birth.server.ts`: unknown 입력을 검증하고 한국 달력을 변환한다. Asia/Seoul의 모호하거나 존재하지 않는 시각을 거부하고 미래 순간인지 검사한다. 이후 UTC+09:00으로 정규화한 뒤 기존 util.timeToIndex를 호출한다. 고정 오류 코드와 한국어 메시지를 반환하며 입력 개인정보를 로그에 출력하지 않는다.
- 서버 결과는 원래 양력 생일·한국 음력, 실제 순간, 원래 오프셋, 계산용 날짜·시각, 엔진 날짜·시진, 정책·시간대 데이터 버전을 구분한다. 공유 응답으로 직접 사용하지 않는다.
- `normalize-birth.test.ts`: 40개 입력·달력·시간 경계 테스트를 추가했다.
- @js-temporal/polyfill 0.5.1과 zod 4.6.2를 추가하고, 실제 정규화에서 사용하는 iztro·korean-lunar-calendar를 실행 의존성으로 이동했다.

날짜 경계는 입력 음력 연도가 아니라 변환된 양력 생일로 검사한다. 한국 음력 1899년에 속하는 양력 1900년 1월 생일도 지원한다. 역사적 초 단위 오프셋을 버리지 않는다. 늦은 자시 날짜 변경은 정규화에서 하지 않고 이후 엔진에 맡긴다.

## 검증

Node.js 24.21.0 기준 pnpm check가 통과했다(전체 53개 테스트: 기존 13개 + 정규화 40개). `pnpm build` 운영 빌드도 통과했다. 문서 포맷·상대 링크·git diff --check를 최종 확인했다.

- KASI의 2012년 음력 4월 8일과 패키지 공식 2017년 윤5월 예제를 사용해 한국 음력·양력 입력의 정규화 전체 결과가 같음을 확인했다. 후자는 독립 기관 정답이 아니라 패키지 예제 회귀 검증이다.
- IANA tz asia의 ROK·Asia/Seoul 기록을 기준으로 1954년 중복 시각, 1961년 누락 시각, 1988년 DST 누락·중복 시각이 거부됨을 검증했다.
- 1900-01-01 23:45의 +08:27:52를 계산용 다음 날 00:17:08로 변환하고, 1988-06-01 00:30의 +10:00을 전날 23:30으로 변환하는 사례를 검증했다.
- 그레고리력 1900년 평년·2000년 윤년, 1900-01-01 하한, 미래 날짜·당일 미래 시각, 시진 경계와 원래 순간 보존을 검증했다.

역사적 사례는 IANA 규칙과의 일관성 검증이다. 대한민국 모든 지역의 1900년 이후 실제 출생 기록 정확성이나 독립 명반 배치 정확성 검증을 완료한 것은 아니다. 서버 런타임의 시간대 데이터 버전은 결과에 기록하며, 데이터 버전 변경 시 경계 테스트를 재검증한다.

## 요구사항 대조

REQ-01의 형식·달력별 날짜 검증과 REQ-10·ADR-0003의 시간 정책을 대조했다. 임의의 시각을 입력하거나 DST의 모호한 시각을 자동 보정하지 않는다. 자시의 날짜를 중복으로 이동하지도 않는다. 이유 없는 차이 또는 수행 불가로 축소한 기능은 없다. 클라이언트·서버 입력 검증의 실제 화면·요청 연결, 지역 지원 안내, 필드별 오류 UI는 후속 미구현이며 수용 완료로 표시하지 않는다.

## 남은 문제와 추후 개선점

독립적인 전체 명반 검증과 실제 입력 UI·API 연결이 필요하다. Temporal의 시간대 해석은 서버 런타임 데이터에 의존하므로 브라우저 계산을 최종 계산 결과의 기준으로 사용하지 않는다. 한국 달력 패키지는 2050년까지 지원하므로 그 이후 서비스 지원에는 별도 데이터 검증·갱신이 필요하며 현재 미래 생일은 지원하지 않는다.

오래된 lunar-lite 주석은 1900-01-31 이후 범위를 언급하지만 현재 solar2lunar 구현은 lunar-typescript로 위임한다. 정규화 단계에서 1900년 1월을 임의 제외하지 않았다. 엔진 연결 단계에서는 그 기간의 실제 별 배치까지 별도 검증해야 한다.
