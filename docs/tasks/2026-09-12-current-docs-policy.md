# 현재 기준 문서 운영 방식

- 작성일: 2026-09-12
- 최종 갱신일: 2026-09-12
- 상태: 완료 — 기준 문서 정리와 작성 규칙 반영

## 작업 개요

`docs/requirements.md`와 `docs/screen-flow.md`에 날짜별 작업 기록과 서로 충돌하는 과거 결정이 누적되어 AI와 개발자가 현재 기준을 다시 해석해야 하는 문제를 확인한다. 두 파일은 현재 유효한 기준만 제공하도록 정리하고, 변경 이력은 작업 문서·ADR·Git에 보존한다.

완료 기준은 기준 문서에서 폐기된 흐름을 제거하고, 이후 작업에서도 충돌하는 결정을 이어 붙이지 않도록 루트 작업 규칙에 명시하는 것이다.

## 요구사항

- `requirements.md`에는 현재 유효한 요구사항, 수용 기준, 미구현·미결정 상태만 둔다.
- `screen-flow.md`에는 현재 유효한 화면 동작과 명확히 구분한 후속 설계만 둔다.
- 새 결정이 기존 내용과 충돌하면 기존 절을 직접 갱신하고 과거 내용은 기준 문서에 남기지 않는다.
- 변경 이유와 과거 상태는 작업 문서, ADR, Git 이력에서 확인할 수 있어야 한다.
- 기존 확정 요구사항을 문서 정리를 이유로 축소하지 않는다.

## 결정과 근거

정리 전 두 기준 문서는 합계 69,017바이트, 7,023단어, 608줄이었다. `requirements.md`의 9절에 날짜별 기록이 30개 넘게 이어졌고, `screen-flow.md`도 현재 동작 뒤에 날짜별 후속 흐름을 누적했다.

정리 후에는 합계 23,736바이트, 2,591단어, 340줄이 되어 문서 크기는 약 66%, 단어 수는 약 63% 줄었다.

다음과 같은 실제 충돌을 확인했다.

- AI 설명을 사용자가 선택한다는 과거 흐름과 기본 생성한다는 현재 흐름
- 12단계·월별 AI 출력과 전체 요약·일곱 분야·한 줄 요약의 현재 출력
- 기본 풀이에 성찰 질문을 표시한다는 과거 흐름과 제거했다는 현재 동작
- 명반 판독 요약을 간편 화면에도 표시하는 과거 흐름과 상세 화면에만 표시하는 현재 동작

파일을 읽는 시간 자체보다 현재 결정을 고르기 위한 추가 문맥과 충돌 해소가 더 큰 문제다. 날짜 순서를 해석 규칙으로 두면 중간 절을 놓치거나 폐기된 요구를 구현할 위험도 있다. 따라서 기준 문서는 현재 상태의 단일 출처로 유지하고, 시간 순서 기록은 목적에 맞는 별도 문서로 분리한다.

## 변경 내용과 영향

- `AGENTS.md`에 기준 문서에는 현재 유효한 결정만 기록하고, 충돌 시 기존 문장을 최신 결정으로 교체하도록 명시했다.
- `docs/requirements.md`를 현재 제품 목표, 수용 기준, 계산·해석·운영 정책, 미구현·미결정 범위 중심으로 다시 구성했다.
- `docs/screen-flow.md`를 현재 구현 흐름, 후속 경로 설계, 간편·상세·AI 화면, 오류와 공유 흐름 중심으로 다시 구성했다.
- 날짜별 변경 이력을 제거하되 확정 요구사항, 현재 운영 제한, 미구현 저장·공유 범위는 유지했다.
- 작업 이력은 기존 `docs/tasks/`, `docs/decisions/`, Git 커밋에 그대로 남는다.

## 검증

- 변경 전후 파일 크기·단어·줄 수를 측정한다.
- 날짜 제목과 폐기된 AI 선택·12단계·월별 출력·성찰 질문 문구가 기준 문서에 남지 않았는지 검색한다.
- 문서 링크와 Markdown 포맷을 검사한다.
- 코드 동작은 변경하지 않으므로 애플리케이션 테스트와 빌드는 이번 추가 커밋의 필수 검증 범위가 아니다. 같은 PR의 코드 변경은 앞선 CI에서 별도로 검증한다.

측정 결과는 69,017바이트·7,023단어·608줄에서 23,736바이트·2,591단어·340줄로 감소했다. 날짜 제목과 폐기된 현재 동작 문구 검색은 통과했고, 변경 문서의 Prettier 검사도 통과했다.

## 요구사항 대조

REQ-01~10과 계산 정책, AI 운영 비활성 상태, 호출 제한, 저장·공유 미구현 범위를 새 기준 문서에 유지했다. 기존 요구사항을 축소하거나 구현 상태를 완료로 바꾸지 않았다. 서로 충돌하던 과거 흐름만 제거하고 최신 결정은 관련 절에 직접 반영했다.

## 남은 문제와 추후 개선점

기존 작업 문서와 ADR은 당시 상태를 보존하므로 서로 다른 시점의 표현이 존재할 수 있다. 이는 이력 문서의 목적에 맞으며, 현재 동작을 판단할 때는 `requirements.md`와 `screen-flow.md`를 우선한다.
