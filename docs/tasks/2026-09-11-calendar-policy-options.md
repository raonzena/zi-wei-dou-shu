# 한국 음력 입력과 명반 계산 달력의 정책 검토

- 작성일: 2026-09-11
- 최종 갱신일: 2026-09-11
- 상태: 검토 완료 / 달력 정책 사용자 선택 대기

이 문서는 달력 정책을 선택하기 전의 비교 기록이다. 후속 작업에서 초기 iztro 사용을 확정했으며, 현재 정책은 [ADR-0003](../decisions/0003-engine-and-calculation-policy.md)을 따른다.

## 작업 개요

한국·중국 음력 차이에 대한 해결 방안을 비교하고 계산 정책 결정에 필요한 선택지를 제시한다. 엔진 연결이나 전체 계산 정책 확정은 이번 검토의 완료 범위가 아니다.

## 요구사항

REQ-01의 출생 정보 입력, REQ-10의 한국 출생자 지원, 요구사항 4절 계산 품질과 OPEN-02에 해당한다. 조사 당시에는 한국 출생자 지원을 확정했지만, 명반을 한국 음력의 월·일로 배치할지는 확정하지 않았다. 사용자는 이번에 해결 방안을 통해 계산 정책을 정하도록 요청했다.

## 결정과 근거

### A안 — 한국 달력으로 입력을 해석하고 iztro 달력으로 명반 계산

한국 음력 입력 → 한국 달력 변환·검증 → 실제 양력 생일 → iztro.bySolar 순서로 처리한다. 양력 입력도 검증 후 같은 진입점을 사용한다. 한국 음력 값을 iztro.byLunar에 직접 전달하지 않는다.

생일과 출생 시각, 성별이 같다면 양력과 음력 중 어느 달력을 선택해 입력하더라도 같은 결과가 나와야 한다. 음력 생일 표시는 한국 달력 값으로 제공하고, 명반 계산용 음력이 필요하면 별도 기준을 명시한다. iztro의 lunarDate를 한국 음력 생일로 표시하지 않는다.

일반 사용자 입력 지원과 기존 엔진 활용을 목표로 할 때 권장하는 설계안이다. 날짜를 위조하거나 엔진을 부분 수정하지 않고 일관된 계산 규칙을 유지한다. 다만 한국 음력의 월·일로 배치한 명반과 일치한다는 보장은 없다. 이 선택이 자미두수의 유일한 정답이라는 근거도 없다.

### B안 — 한국 음력의 월·일을 명반 배치에도 사용

한국 달력에서 산출한 연·월·일·윤달과 확정한 간지·시각 규칙을 계산 엔진이 일관된 기준으로 사용하도록 한다. 현재 iztro 2.6.1의 공개 옵션에는 한국 달력 주입 기능이 없다.

설치 소스에서 astro.js뿐 아니라 utils/index.js, star/location.js 등이 달력 함수를 호출한다. 따라서 입력 변환이나 출력 lunarDate 교체만으로 해결할 수 없다. 유지보수할 소스 포크에서 달력 의존부를 분리하거나, 해당 달력을 지원하는 엔진을 검증해 선택해야 한다. 그런 엔진을 이번 조사에서 확보했다고 주장하지 않는다.

포크는 현재 기능에 필요한 본명반 경로를 일관되게 변경하고 독립 기준 명반으로 검증해야 한다. 패키지 업데이트 추적과 검증 책임이 프로젝트에 생긴다. 특정 한국식 기준 명반과 일치하는 것이 제품 목표일 때 선택할 방향이다.

### 공통으로 필요한 정책

- 입력 달력과 배치 달력의 책임을 구분한다.
- 윤달의 존재 여부 검증과 윤달을 배치상 어느 월로 취급할지 결정하는 규칙은 서로 다르다.
- 지원 연도, 역사적 표준시·서머타임, 진태양시 적용, 자시 날짜 경계, 윤달 배치, 사화 규칙은 별도 결정한다. 달력 변환 성공만으로 이 정책들이 검증됐다고 간주하지 않는다.
- 한국 달력을 중국 달력으로 바꾸는 것을 출생 시각에서 한 시간을 빼는 처리와 동일시하지 않는다.
- 채택 엔진 버전과 계산 정책 버전을 결과에 남겨 재현할 수 있게 하는 설계안이다. 저장 스키마는 아직 구현하지 않는다.

## 변경 내용과 영향

이 작업 문서와 목록을 추가하고, requirements.md의 미결정 정책에 입력·명반 계산 달력을 명시했다. 이전 평가의 운영 채택 보류는 유지하되 해결 불가로 오해하지 않도록 두 방향을 연결했다. 의존성과 앱 코드는 변경하지 않았다.

## 검증

설치된 iztro 2.6.1의 bySolar/byLunar 및 달력 호출부와 공식 설정 문서를 확인했다. Node 실행으로 한국 음력 2012-4-8 평달을 korean-lunar-calendar 0.4.0으로 양력 2012-5-28로 변환하고, 동일 시각 인덱스 2·male·fixLeap true·ko-KR 조건에서 양력 직접 입력과 명반 전체 직렬화 결과가 같음을 확인했다. 엔진 내부 음력은 2012-4-8 윤달이었다.

이 실험은 A안의 입력 일관성을 확인하며, 독립적인 별 배치 정확성이나 B안 구현 검증이 아니다. B안의 포크 구현과 역사적 시각 처리는 수행하지 않았다. 변경 문서 포맷과 상대 링크, git diff --check를 검사한다. 앱 코드 변경이 없어 테스트·빌드는 재실행하지 않는다.

## 요구사항 대조

한국 출생자 지원과 음력 입력을 제거하지 않았다. A·B 모두 설계안으로 기록했으며 사용자 승인 없이 계산 달력을 확정하지 않았다. 요구사항 수행 불가에 따른 기능 축소는 없다. 이전 평가의 한국 음력 기반 배치 미지원과 A안의 한국 음력 입력 지원은 서로 다른 조건이다.

## 남은 문제와 추후 개선점

먼저 A·B 중 명반 계산 기준을 선택한다. 이후 지원 연도·시간·자시·윤달·사화 정책과 독립 명반 검증을 완료해야 운영 채택할 수 있다. A안을 선택하면 한국 음력 입력과 양력 입력의 동등성을 2012·2017년 차이 사례, 윤달·연도 경계까지 자동 테스트로 확대한다. B안을 선택하면 달력 의존부 수정 범위와 기준 명반을 먼저 확보한다.
