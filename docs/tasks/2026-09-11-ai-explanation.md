# 규칙 근거를 풀어 쓰는 AI 설명 연결

- 작성일: 2026-09-11
- 상태: 코드 연결·모의 API·브라우저 검증 완료 / API 키 설정과 실호출 품질 평가 대기

## 작업 개요

사용자가 AI 설명까지 요청했다. 기존 규칙 기반 기본 풀이를 유지하고, 선택한 경우 OpenAI가 그 의미를 쉬운 한국어로 풀어 쓰도록 연결했다. AI가 명반이나 새로운 운세를 계산하는 구조는 아니다.

## 요구사항과 결정

REQ-01·02·03·05·07과 OPEN-05, [ADR-0004](../decisions/0004-rule-based-interpretation.md)를 따른다. 입력에서 AI 선택과 전송 항목·외부 처리 안내를 제공한다. 선택 여부는 기본적으로 미선택이며 AI 없이도 기본 풀이를 볼 수 있다.

OpenAI 공식 SDK `openai@7.15.0`과 `server-only@0.0.1`을 추가했다. 설치된 Zod와 SDK의 `zodTextFormat`을 사용해 별도 AI 추상화 라이브러리는 추가하지 않았다. 모델은 Responses와 Structured Outputs를 지원하는 `gpt-5.4-mini-2026-03-17`을 선정했다. 초기에 검토한 GPT-5 mini 스냅샷은 공식 페이지에 deprecated로 표시되어 채택하지 않았다. 이 선택은 실제 한국어 품질 비교 결과가 아니라 문서 기반 구현 결정이다.

## 데이터와 처리 흐름

입력 검증 → 명반 계산 → 기본 풀이 선택 → AI 선택 시 설명 요청 → 간편 결과로 이어진다. AI 전송 데이터는 규칙 ID·주성 이름·기본 의미만 명시적으로 추려 구성한다. 출생 날짜·시각·성별, 명궁 위치·전체 명반, 성찰 질문과 사용자 자유 입력은 제외한다. 프롬프트에는 계산·새로운 판단·동궁 종합·건강·재물·연애·시기 예측을 추가하지 않도록 명시했다.

25초 제한, 최대 출력 1,800토큰, reasoning none, `store: false`, SDK 자동 재시도 0회를 적용한다. 도구 호출·검색·이전 대화 연결은 사용하지 않는다. `store: false`를 제공자 측 모든 데이터 무보관으로 안내하지 않는다.

서버 전용 모듈은 API 키를 읽고 클라이언트 모듈은 결과 타입만 참조한다. Vitest에서만 server-only 패키지의 공식 빈 진입점을 사용한다. 앱 빌드의 서버·클라이언트 경계 검사는 유지한다.

## 응답 검증과 화면 동작

문단 수·문자 길이와 규칙 ID를 검사한다. 미지원 ID, 누락·중복, 미완료·거절·파싱 실패는 성공으로 표시하지 않는다. API 오류 원문·요청 본문·키는 브라우저나 일반 로그로 전달하지 않는다. 성공 결과에 모델·프롬프트·규칙 버전을 포함한다.

AI 설명은 기본 풀이 다음에 표시하고 각 문단에 원래 규칙 문장을 함께 제공한다. React의 텍스트 렌더링을 사용하며 모델 응답을 HTML로 실행하지 않는다. 원래 별 이름은 기존 용어 Popover에 연결한다.

실패하면 기본 풀이와 실패 안내를 유지한다. 일시적인 오류는 명시적 재시도를 제공하고, 키 미설정·권한 오류는 반복 재시도를 유도하지 않는다. 재시도는 보관한 직전 FormData를 서버에서 다시 검증·계산해 신뢰할 수 있는 근거로 요청한다. 화면에서는 AI 결과만 교체한다. 재시도 중 입력 수정·중복 재시도를 막고 탭 이동은 허용한다. 성공한 AI 설명은 탭 이동으로 재생성하지 않는다.

주성이 없는 명궁에는 규칙 근거가 없으므로 API를 호출하지 않는다. 주성 둘은 각각 설명하며 조합 해석 지원으로 간주하지 않는다.

## 검증

실제 SDK의 fetch 전송을 모사한 테스트에서 전송 필드 제한과 모델·토큰·저장 설정, 성공 응답, 근거 누락·중복·미지원, 거절·미완료, HTTP 401·429·500과 25초 중단을 확인했다. 선택하지 않은 호출과 잘못된 선택 값도 검사한다. API 테스트에는 가짜 키와 명시적인 테스트 응답만 사용했다.

별도 로컬 검증 서버에서 첫 요청에 503, 재시도에 검증용 JSON을 반환하도록 설정했다. 실제 브라우저에서 AI 선택 → 생성 실패 안내 → 재시도 → 문단·근거 표시를 확인했다. 상세·간편 왕복 후 설명이 같음을 확인했다. 생성 문구에는 ‘연동 검증용 응답’을 표시했다. 해당 임시 서버는 종료하며 일반 실행 환경이나 저장소에 모의 응답을 남기지 않는다.

키가 없어 실제 OpenAI 호출·계정 모델 접근·한국어 생성 품질·응답 지연·비용은 검증하지 못했다. 구조·ID 검사로 의미적 근거 충실성까지 보장하지 않는다. 모바일 실기기와 스크린리더도 이번에 검증하지 않았다.

Node.js 24에서 139개 테스트·lint·타입 검사·운영 빌드가 통과했다. 변경 파일 포맷과 `git diff --check`도 확인했다. 전체 `pnpm check`는 별도로 추가된 `.agents/` 파일 42개의 기존 포맷 문제로 실패했으며 해당 파일·검사 설정은 변경하지 않았다.

일반 실행 환경에서는 키 미설정 안내와 기본 풀이가 함께 표시되는 것을 확인했다. 모의 API·별도 앱 서버는 종료했고 일반 서버는 실제 키 없이 실행 중이다.

## 요구사항 대조

입력 안내·실제 대기·명반 아래 AI 설명·근거·용어 설명·탭 재사용과 실패 복구를 연결했다. requirements.md와 screen-flow.md에 선택 흐름과 외부 처리 변경을 기록했다. 기존 계산 정책·표시 별은 유지한다. 일반 규칙 풀이를 AI 성공으로 대신 표시하지 않는다. 키 부재로 실호출을 검증하지 못한 부분을 완료로 처리하지 않는다.

## 실행과 남은 작업

프로젝트 `.env.local`에 `OPENAI_API_KEY`를 설정하고 서버를 다시 시작한다. 실제 호출에는 API 계정 권한과 요금이 적용된다. 키를 문서·커밋·채팅에 기재하지 않는다.

키 설정 후 다음 사례를 실제 모델로 평가한다.

- 단일 주성: 기본 의미와 확신 수준을 유지하는가.
- 무곡·파군 동궁: 별별 설명만 하고 종합 성향을 만들어내지 않는가.
- 주성 없는 명궁: 외부 요청 없이 미지원 안내를 하는가.
- 성공·재시도·탭 이동: 같은 결과를 표시하고 예상 횟수만 호출하는가.
- 문장 검토: 새로운 운세·시기·직업 추천·진단·전문용어를 추가하지 않는가.

실제 응답을 사례별로 검토해 프롬프트나 모델 변경 여부를 결정한다. 의미 검증을 정규식이나 ID 검사만으로 해결했다고 간주하지 않는다.

공개 출시 전에는 호출자별 요청 제한·전체 사용량 통제, 배포 환경의 요청 시간 제한과 장시간 작업 복구를 구현·검증해야 한다. 현재 클라이언트 중복 클릭 방지와 요청별 토큰 제한은 서버 전체 비용 상한을 보장하지 않는다. 결과 저장·공유와 종합·주제별 해석도 기존 후속 작업이다.
