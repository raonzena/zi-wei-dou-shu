# 날짜·시각 입력 범위와 목록 선택

- 작성일: 2026-09-11
- 상태: 구현·브라우저 검증 완료

## 작업 개요와 요구사항

사용자 요청에 따라 REQ-01 입력에서 연도·월·일·시·분의 범위를 구체화하고 직접 입력과 목록 선택을 함께 제공한다. 양력/음력 라벨과 한국 음력 안내, 남성 기본값을 적용한다.

## 결정과 근거

기존 의존성에 입력형 목록 컴포넌트가 없어 네이티브 datalist를 먼저 검토했다. 현재 인앱 브라우저에서 펼침·선택을 확인하지 못해 최종 구현에서는 제거했다. Base UI 1.8.0의 Autocomplete를 채택하고 vanilla-extract로 스타일링한다. 공식 문서에 따라 자유 입력을 유지하는 Autocomplete를 사용하며 범위에 없는 텍스트는 공통 파서에서 거부한다. 팝업·키보드·포커스 동작을 직접 재구현하지 않는다. 새 의존성은 정확한 버전으로 고정했다.

- 양력 연도: 1900–현재 한국 연도. 음력 연도: 1899–현재 한국 연도. 음력 1899년 일부가 양력 1900년에 해당하여 기존 지원 범위를 유지한다. 현재 연도 내 미래 날짜·순간 여부는 기존 서버 정규화에서 검사한다.
- 월: 1–12. 일: 양력 월 길이·윤년, 한국 음력 월 길이·윤달에 따라 1–28/29/30/31. 아직 월·연도를 입력하지 않은 상태에서는 가능한 최대 범위만 제안한다. 존재하지 않는 윤달은 기존 서버 검증에서 거부한다.
- 시: 0–23, 분: 0–59. 빈 값은 여전히 임의의 0으로 바꾸지 않는다.
- 범위를 바꿨을 때 기존 일을 임의로 말일로 바꾸지 않는다. 유효하지 않은 직접 입력은 제출 시 해당 필드에 정확한 범위 오류를 표시한다.
- '음력' 라벨 아래에 한국 음력 기준이라는 안내를 항상 표시한다. 사용자가 허용한 하단 안내안을 채택하여 툴팁을 열어야 알 수 있는 정보로 만들지 않았다.
- 남성을 최초 기본 선택하되 사용자가 여성으로 변경할 수 있다. 입력 수정 시 선택값을 유지한다.

## 변경 내용과 영향

input-ranges.ts를 목록·범위 안내·공통 파서에서 재사용한다. 설치된 korean-lunar-calendar로 음력 월 길이를 확인한다. number-choice.tsx의 입력형 목록을 birth-form에 연결하고 연도·월·윤달 변경에 맞춰 일 목록을 갱신한다. 계산 엔진과 정규화 정책은 변경하지 않는다.

## 검증

pnpm check의 포맷·ESLint·타입·112개 테스트가 통과했다. 추가 9개 테스트는 범위 밖 입력의 서버 거부, 윤년, 양력 월말, 한국 음력 평달·윤달 길이, 음력 1899년 지원을 확인한다. 2월 30일 오류는 기존 날짜 단위 안내에서 일 필드의 1~29 범위 안내로 구체화했다.

## 요구사항 대조

REQ-01·10의 양쪽 검증과 지원 범위를 유지하고 사용자 요청한 입력 UX·표기·성별 기본값을 반영했다. 필수 시각에 임의 기본값을 넣지 않는다. 사용자 요청에 따른 UX 구체화이며 기능 수행 불가에 따른 축소는 없다. 해석·상세·공유 등 후속 작업은 별개로 유지한다.

## 추후 개선과 미검증

목록의 키보드·포커스는 Base UI가 관리하며 보조기술의 실사용 검증은 별도로 필요하다. 이번 확인 환경 외의 Safari·Firefox·모바일 실기기/스크린리더는 추가 검증 대상이다. 지원 브라우저에서 목록 선택 문제가 재현되면 해당 환경의 이벤트·포커스를 재현해 수정한다.

## 하단 범위 표시 제거

사용자 요청으로 입력칸 하단의 숫자 범위 텍스트를 제거했다. placeholder·선택 목록·클라이언트/서버 범위 검증과 오류 문구는 유지한다. 삭제한 텍스트의 aria-describedby 참조와 미사용 스타일도 제거했다. REQ-01과 대조하여 표시 중복만 줄였으며 검증 범위 변경은 없다. 단순 표시 수정으로 새 테스트는 추가하지 않는다.

후속 검증: 문서·코드 포맷 검사, git diff --check, 프로덕션 빌드가 통과했다. 브라우저에서 하단 1900~2026 텍스트 제거와 연도 placeholder 유지를 확인했다.
