# 결과 공유와 링크 복사

- 작성일: 2026-09-13
- 상태: 완료 (앱 배포 전)

## 작업 개요

기존 결과 저장·방문자 버튼 변경을 93b57d4로 커밋했다. 커밋 전 pnpm check(265개 통과, 유료 실평가 1개 제외), build, diff 검사를 통과했다. 이어 결과 공유 UI를 구현한다.

## 요구사항

REQ-06에 따라 종합 풀이·상세 명반에서 저장된 ID 링크와 현재 보기를 공유한다. 개인정보와 소유 자격 증명은 공유하지 않는다. 공개 결과 링크와 30일 보관 정책은 유지한다.

## 결정과 근거

설치된 React·vanilla-extract와 웹 표준 API를 사용한다. MDN의 Navigator.share와 Clipboard.writeText 문서를 확인했다. 기기 공유는 사용자 클릭에서 호출하며 취소(AbortError)를 실패와 구분한다. 공유가 지원되지 않으면 복사하고, 권한 오류는 선택 가능한 링크로 안내한다. 별도 공유 토큰이나 서버 API는 필요하지 않다.

## 변경 내용과 영향

두 보기의 공통 하단에 ‘결과 공유’, ‘링크 복사’를 추가했다. URL은 현재 origin과 저장된 결과 ID로 새로 구성하고 상세 보기만 쿼리에 포함한다. 복사 완료는 status로 안내하고, 직접 복사할 입력에는 라벨·읽기 전용·포커스 시 선택을 적용했다. 중복 클릭을 막고 탭이 바뀌면 이전 탭의 복사 안내를 숨긴다. 공유 취소는 클립보드를 변경하지 않는다.

## 검증

- pnpm check 통과: 테스트 270개 통과, 유료 실평가 1개 제외. 포맷·ESLint·타입 검사 통과.
- pnpm build와 git diff --check 통과.
- 새 테스트 5개로 두 보기의 URL, 불필요한 쿼리·해시 제거, 공유 payload, 취소 시 복사 금지, 미지원 시 복사, 권한 거절 시 직접 복사 안내를 검증했다.
- 브라우저에서 가상 출생 정보로 결과를 만들고 종합 풀이·상세 명반의 링크 복사 성공 안내와 탭 전환 시 이전 안내가 숨겨지는 것을 확인했다.
- 시험 결과는 운영 DB에서 관리 작업으로 정리했다. 사용자 수동 삭제 기능을 복원하지 않았다.
- 기기의 공유 대상 앱에 실제로 전송하지 않았으며 AI 호출도 하지 않았다. 네이티브 공유 취소·권한 거절은 자동 테스트로 검증했고 실제 기기의 공유창 조작은 수행하지 않았다.

## 요구사항 대조

기존 공개 조회와 방문자 버튼, 개인정보 비노출, 재계산 없는 복원을 유지한다. 공유 버튼 미구현 표기를 갱신했다.

## 남은 문제와 추후 개선점

기기의 실제 공유 대상 앱으로의 전달은 환경에 따라 달라진다. 별도 공유 해제·이미지 공유는 이번 범위에 포함하지 않는다.

## 후속 변경: 공유 버튼 통합

사용자 요청으로 별도 ‘링크 복사’ 버튼을 제거하고 ‘결과 공유’ 하나로 통합했다. 데스크탑에서는 공유 API가 있어도 바로 복사한다. Android·iOS 모바일과 태블릿은 기존 기기 공유를 유지한다. Macintosh UA와 멀티터치가 함께 있는 환경은 데스크탑 모드 iPad로 분류한다. 화면 너비나 마우스 연결 여부는 공유 방식에 영향을 주지 않는다. Windows 터치 노트북은 데스크탑으로 분류한다.

MDN은 UA 판별의 한계를 설명하고 기능 검출을 권장한다. 이번에는 사용자가 기기에 따른 서로 다른 동작을 요청했으므로 기기 분류에만 UA·터치 정보를 사용한다. 실제 공유·클립보드 사용 가능 여부는 기존 API 검사로 판단한다. 별도 앱 브리지는 추가하지 않는다. UA를 변경한 앱이나 브라우저의 기기 분류는 정확하지 않을 수 있다.

복사 토스트, 공유 취소, 직접 복사 안내, 현재 보기 URL 정책은 유지한다. REQ-06과 화면 흐름의 두 버튼 안내를 단일 버튼 동작으로 갱신했다. 앞 절의 두 버튼·인라인 성공 안내는 최초 구현 기록이며, 현재 성공 안내는 토스트다.

검증: pnpm check 통과(279개 통과, 유료 실평가 1개 제외). Windows·터치 Windows·Mac·Linux·iPhone·iPad·데스크탑 모드 iPad·Android WebView·Android 태블릿의 9개 분기에서 실제 공유 또는 복사 함수 호출을 검사했다. 기존 공유 취소·권한 거절·URL 검사도 통과했다. git diff --check 통과. 이번 변경은 실제 브라우저·태블릿·모바일 앱에서 재검증하지 않았으며 AI 호출과 배포는 수행하지 않았다. 요구사항과 구현을 대조해 단일 버튼 및 기기별 동작을 확인했다.

참고: https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Browser_detection_using_the_user_agent , https://developer.mozilla.org/en-US/docs/Web/API/Navigator/maxTouchPoints

## 후속 변경: 하단 버튼 크기와 배치

사용자 요청에 따라 결과 공유·명반 다시 보기(방문자는 나도 확인해보기)에 공통 버튼 스타일을 적용한다. 높이는 3.25rem으로 통일한다. 두 열의 같은 너비 grid를 사용하고, 모바일 640px 이하에서는 한 열로 쌓는다. 최초의 모바일 한 줄 방향은 후속 사용자 지시인 두 줄 배치로 변경했다. 복사 오류 안내가 길어져도 옆 버튼 높이가 늘어나지 않도록 상단 정렬한다. 사용하지 않는 back 스타일과 공유 영역의 상단 마진을 제거했다.

검증: pnpm build(TypeScript 포함), 변경 파일 ESLint, Prettier, git diff --check 통과. 두 버튼이 동일한 CSS 클래스를 사용하고 640px 이하에서 한 열로 전환되는 것을 코드로 확인했다. 이번 배치는 실제 브라우저에서 시각 검증하지 않았다. 관련 요구사항 REQ-06과 화면 흐름에 최종 반응형 배치를 기록하고 구현과 대조했다. 공유 처리와 이동 동작은 변경하지 않았다.

## 커밋 전 최종 확인

공유·토스트·반응형 버튼 변경을 함께 검토하고 pnpm check를 다시 실행했다. 포맷·린트·타입 검사와 테스트 279개가 통과했으며 유료 실평가 1개는 제외했다. 최종 코드의 pnpm build는 직전 버튼 배치 작업에서 통과했다. REQ-06과 화면 흐름을 대조했고 미반영 변경은 없다. 실제 모바일 기기의 네이티브 공유와 최종 버튼 배치의 시각 검증은 남아 있다. 이번 요청은 로컬 커밋까지이며 원격 푸시는 포함하지 않는다.
