# 요구사항 명세

최종 갱신일: 2026-09-12

상태: 사용자 확정 요구사항 + 구현 설계안

관련 문서: [화면 흐름](screen-flow.md), [기술 선택 기록](decisions/0001-technology-stack.md), [작업 기록](tasks/README.md)

이 문서는 현재 유효한 요구사항과 결정만 설명한다. 변경 전 상태와 결정 근거는 작업 문서, ADR, Git 이력에서 확인한다.

## 1. 제품 목표

자미두수에 익숙하지 않은 일반 사용자가 출생 정보를 입력해 간소화된 명반과 쉬운 한국어 해석을 확인하고, 필요하면 상세 명반을 탐색할 수 있도록 한다. 명반 계산과 자연어 해석의 책임을 분리한다.

첫 방문의 핵심 흐름은 **출생 정보 입력 → 계산·해석 준비 → 간편 결과 → 상세 명반**이다. 결과 저장과 공유는 목표 범위에 포함하지만 아직 구현하지 않았다.

## 3. 화면별 수용 기준

### REQ-01 — 출생 정보 입력

- 생년월일, 양력·한국 음력, 음력 윤달 여부, 출생 시각, 계산에 필요한 성별을 입력받는다.
- 양력 연도는 1900년부터 현재 한국 연도까지, 음력 연도는 양력 1900년 생일 입력을 위해 1899년부터 지원한다.
- 날짜·시각은 목록 선택과 직접 입력을 모두 지원한다. 성별은 남성을 기본 선택하고 출생 시각에는 기본값을 두지 않는다.
- 클라이언트와 서버에서 존재하지 않는 날짜, 지원 범위 밖 입력, 유효하지 않은 윤달, 미래 출생 순간을 검증한다.
- 대한민국의 역사적 표준시와 서머타임을 반영한다. 진태양시 보정은 적용하지 않으며 모호하거나 존재하지 않는 시각을 임의 계산하지 않는다.
- 출생 시각 미상 명반은 제공하지 않고 입력이 필요한 이유를 안내한다.
- 제출 중 중복 제출을 방지하고, 실패 후 입력 화면으로 돌아오면 현재 세션의 입력값을 유지한다.
- 입력 시점에 외부 AI 처리 범위와 운영 식별값·사용량 기록의 보관 범위를 안내한다.

### REQ-02 — 로딩과 오류

- 유효한 입력 제출 후 명반 계산과 AI 해석 준비 상태를 실제 작업에 맞게 표시한다.
- 임의의 진행률이나 연출을 위한 최소 대기 시간을 두지 않는다.
- 성공하면 간편 결과로 이동하고, 계산·AI·네트워크 오류를 구분해 다음 행동을 제공한다.
- AI 실패 시 명반과 규칙 기반 기본 풀이는 유지한다.
- 일시적 오류에만 명시적 재시도를 제공하며 크레딧·설정·운영 한도 오류는 운영자 확인이 필요하다고 안내한다.
- 재시도 중 중복 요청과 입력 수정을 막고 기존 계산 결과는 계속 표시한다.

### REQ-03 / REQ-05 — 간편 결과

- 보기 모드를 지정하지 않은 첫 진입은 간편 결과다.
- 12궁 관계를 유지한 간소화 명반 다음에 규칙 기반 기본 풀이와 활성화된 AI 해석을 표시한다.
- 간편 명반에는 궁 이름, 14주성, 신궁, 오행국을 우선 표시한다.
- 간편 명반에서도 궁을 선택할 수 있고, 선택한 생활 영역과 그 영역에서 나타나는 기본적인 모습을 명반 바로 아래에서 확인한다.
- 기본 풀이는 명궁 주성의 성향·강점·주의점을 쉬운 문장으로 설명한다. 성찰 질문은 표시하지 않는다.
- AI 결과는 전체 요약, 고정된 일곱 분야, 한 줄 요약 순서로 표시한다.
- 상세 보기로 이동해도 같은 명반과 해석을 재사용하며 AI를 다시 호출하지 않는다.

### REQ-04 — 상세 명반

- 간편 결과와 동일한 계산 결과를 사용한다.
- 12궁, 간지, 주성, 검증 범위의 보조성·사화·밝기와 운한 계산 자료를 제공한다.
- 궁을 선택하면 해당 궁이 다루는 생활 영역, 그 영역에서 나타나는 모습, 일상에서 참고할 점, 별 목록 순서로 표시한다.
- 간편 명반의 짧은 설명은 유지하고, 상세 명반의 생활 영역·주성별 모습·생활 활용 항목은 각각 4문장으로 설명한다.
- 선택한 궁의 실제 주성만 사용하며 선택 동작에서 재계산하거나 AI를 호출하지 않는다.
- 주성이 없거나 여러 개인 경우 지원 범위와 개별 의미를 구분한다. 궁·별 조합을 검증된 전문 풀이처럼 확대하지 않는다.
- 명반 판독 요약은 상세 화면에만 기본 접힘 상태로 표시한다.
- 정보가 많아도 명반 전체를 읽기 어려운 크기로 일괄 축소하지 않는다.

### REQ-06 — 공유

공유는 아직 구현하지 않은 설계안이다.

- 간편·상세 결과에서 모두 공유할 수 있어야 한다.
- 공유 전에 공개되는 명반·해석과 숨겨지는 정보를 확인한다.
- 링크 수신자는 생성 당시 저장된 결과를 조회하며 재계산하거나 재생성하지 않는다.
- 현재 보기 모드를 링크에 반영하고, 보기 모드가 없으면 간편 결과를 연다.
- 출생 정보와 소유자 자격 증명은 공개 응답과 페이지에서 제외한다.
- 공유 토큰과 원본 조회·삭제 권한을 구분하고 공유 해제 후 기존 링크를 차단한다.
- 없는 링크, 해제된 링크, 만료된 결과를 처리하고 공유 페이지는 검색 색인을 허용하지 않는다.

### REQ-07 — 전문용어 설명

- 명반과 해석은 같은 용어집을 사용한다.
- 데스크톱에서는 hover·키보드 focus, 터치 환경에서는 탭으로 설명을 연다.
- 클릭으로 연 설명은 바깥 클릭, Esc 또는 닫기 버튼으로 닫는다.
- 색상만으로 설명 가능 여부를 구분하지 않는다.
- 설명에 링크나 버튼이 있으면 포커스를 지원하는 popover 패턴을 사용한다.

## 4. 계산 정책과 검증

- 초기 계산 엔진은 iztro 2.6.1을 사용하고 필요한 기능은 추후 TypeScript로 직접 구현한다.
- 한국 음력 입력은 실제 양력 생일로 변환한 뒤 iztro 명반을 계산한다.
- 초기 계산 정책 `ziwei-v1`은 iztro의 화성·령성, 壬 사화와 윤달 후반 23시 예외를 따른다. 윤달 늦은 자시 정책을 변경하면 날짜·시각 경계를 다시 검증하고 정책 버전을 올린다.
- 운한 자료 계약은 `iztro-timing-v2`다. 대한, 올해 유년, 올해 전체 유월과 윤달 전·후반, 검증 범위의 유요를 서버에서 계산한다.
- 올해는 Asia/Seoul의 양력 연도로 선택하되 유년 경계와 월·일 구간은 iztro 음력 기준이다. 대한 나이는 만 나이가 아닌 엔진 계산용 나이다.
- 궁간 사화는 본명반 12궁의 48개 관계를 제공하며 출발·도착 궁이 같은 경우에만 자화로 표시한다.
- 격국은 자부동궁·자부협명의 구조 조건 확인으로 한정하고 길흉·성패 판정으로 확대하지 않는다.
- 같은 엔진을 사용하는 서비스와의 일치만으로 독립 검증 완료로 간주하지 않는다. 일반·경계 사례와 서로 독립적인 기준 명반을 계속 대조한다.

## 5. 해석 정책과 품질

### 규칙 기반 기본 풀이

- 명궁과 상세 화면에서 선택한 궁의 주성을 바탕으로 기본 의미를 제공한다.
- 각 별은 뜻을 바로 이해할 수 있는 특징 제목으로 표시한다. 간편 명반은 기본 모습과 균형점을 짧게 설명하고, 상세 명반은 기본 모습·강점·주의점·균형점의 4문장으로 설명한다.
- 궁별 풀이는 전문 용어 중심 제목 대신 ‘어떤 생활 영역인지’, ‘나는 어떤 모습인지’, ‘생활에서 어떻게 활용할지’를 질문형 제목과 쉬운 문장으로 설명한다.
- 주성이 함께 놓이면 개별 의미를 구분하고, 주성이 없으면 지원 범위를 안내한다.
- 사화·밝기·다른 별·삼방사정을 종합한 해석으로 확대하지 않는다.

### AI 명반 해석

- AI는 서버가 제공한 본명반 근거만 사용하며 명반 배치를 다시 계산하지 않는다.
- 응답은 `overview`, 고정 순서의 일곱 `sections`, `closing`으로 구성한다.
- 일곱 분야는 핵심 성향, 일과 커리어, 돈, 관계와 배우자, 내면과 삶의 방향, 건강과 컨디션, 가족·대인관계다.
- 전체 요약은 1~~2문단, 각 분야는 개인화된 제목과 1~~3문단을 기본으로 하고 실제로 도움이 될 때만 짧은 목록을 사용한다.
- 마지막 문단은 ‘한 줄로 정리하면’으로 시작한다.
- 이전 12단계와 `terms`, `interpretation`, `check`, `step`, `monthly` 출력은 사용하지 않는다.
- 대한·유년·유월을 근거로 한 시기별 AI 운세는 제공하지 않는다. 서버 계산 자료는 상세 명반의 판독 요약에서 확인한다.
- 전문 용어는 필요한 경우에만 문장 안에서 쉽게 설명한다. 직업·재물·관계·건강을 예언하거나 숙명적으로 단정하지 않는다.
- 응답 구조, section 순서, 근거 ID, 사화 표현을 서버에서 검증한다. 내부 ID와 시기 근거 ID가 사용자 문장이나 새 AI 결과에 포함되면 거부한다.
- 구조 검증 통과를 의미적 정확성으로 간주하지 않으며 실제 기준 명반으로 별도 품질 평가를 수행한다.

## 6. 운영·개인정보·배포

- 원본 출생 정보와 AI 결과 원문을 운영 사용량 제어 저장소에 저장하지 않는다.
- 원본 IP와 명반 대신 서버 비밀키로 만든 식별값, 처리 상태, 시간, 토큰, 추정 비용을 저장한다. 해시를 완전한 익명 정보로 간주하지 않는다.
- 운영 기록은 30일이 지나면 매일 삭제하므로 실제 최대 보관 기간은 약 31일이다.
- 기본 AI 한도는 IP당 최근 1시간 3회, 서비스 전체 한국 날짜 기준 하루 20회·추정 비용 2달러다. 동일 IP·명반·모델·프롬프트 버전은 10분 동안 중복 차단한다.
- Supabase 설정이나 저장소가 실패하면 한도를 우회하지 않고 AI 호출을 차단한다.
- `AI_EXPLANATION_ENABLED=false`이면 화면과 서버 호출을 모두 비활성화하고 명반·기본 풀이만 제공한다. 운영은 현재 비활성 상태다.
- SDK 요청 제한은 150초, Vercel 함수 제한은 180초이며 SDK 자동 재시도를 사용하지 않는다.
- main push는 GitHub Actions의 포맷·린트·타입·테스트·빌드 성공 후 Vercel production에 배포한다. PR은 검증만 수행한다.
- 서버 키는 클라이언트 번들, URL, 공유 메타데이터, 일반 로그에 포함하지 않는다.
- 모바일을 우선 설계하고 데스크톱·키보드 접근성을 함께 검증한다.

| AI 의미 품질                | 구조 검증 완료. 다양한 명반의 해석 정확성·단정 표현 검토가 필요하다.                   |
| 회원가입·결제·궁합·자유상담 | 첫 출시 제외 설계안이다.                                                               |
| 이미지 다운로드·다국어 UI   | 첫 출시 제외 설계안이다.                                                               |

## 8. 출시 수용 시나리오

1. 유효한 출생 정보를 입력하면 로딩을 거쳐 간편 명반과 해석이 표시된다.
2. 상세 탭으로 이동해도 동일한 결과이며 AI를 다시 호출하지 않는다.
3. 전문용어를 마우스·터치·키보드로 확인하고 닫을 수 있다.
4. AI가 비활성화되거나 실패해도 명반과 기본 풀이를 확인할 수 있다.
5. 운영 AI를 활성화하면 중복·횟수·예산 제한과 비용 기록이 동작한다.
6. 공유 구현 후 두 탭의 링크가 다른 브라우저에서 지정한 보기 모드로 열리고 비공개 정보는 노출되지 않는다.
7. 공유 해제 또는 결과 삭제 후 기존 공유 링크가 결과를 제공하지 않는다.
8. 기준 명반 테스트가 통과하며 채택 정책과 설명되지 않은 불일치가 있는 상태로 출시하지 않는다.

## 9. 문서 갱신 원칙

- 이 문서에는 현재 유효한 요구사항, 수용 기준, 미구현·미결정 상태만 기록한다.
- 새 결정이 기존 내용과 충돌하면 기존 문장을 최신 결정으로 교체한다. 날짜별 변경 절을 추가하거나 폐기된 결정을 함께 남기지 않는다.
- 변경 전 상태, 결정 이유, 검증 결과는 `docs/tasks/`, `docs/decisions/`, Git 커밋에서 확인한다.
- 구현 결과 때문에 요구사항을 임의로 낮추지 않는다. 사용자가 변경을 확정했거나 수행 불가 근거와 대안을 승인한 경우에만 현재 기준을 수정한다.
