# 요구사항 명세

작성일: 2026-09-11

상태: 사용자 확정 요구사항 + 구현 설계안

관련 문서: [화면 흐름](screen-flow.md), [기술 선택 기록](decisions/0001-technology-stack.md)

## 1. 제품 목표

자미두수에 익숙하지 않은 일반 사용자가 자신의 명반과 한국어 해석을 이해하고, 관심이 생기면 상세 명반까지 탐색할 수 있도록 한다. 명반 계산과 자연어 해석의 책임을 분리한다.

첫 방문의 핵심 흐름은 **출생 정보 입력 → 로딩 → 간편 결과 → 상세 명반 → 공유**다. 별도 소개 페이지는 현재 필수 범위에 포함하지 않는다.

## 3. 화면별 수용 기준

### REQ-01 — 출생 정보 입력

설계안: 생년월일, 양력·음력, 음력일 때 윤달 여부, 출생 시각, 계산에 필요한 성별을 입력받는다. 이름·연락처·이메일은 현재 기능에 필요하지 않으므로 수집하지 않는 것을 제안한다.

- 필수 입력과 형식 오류를 해당 필드 주변에 표시한다.
- 클라이언트와 서버 양쪽에서 입력을 검증한다.
- 존재하지 않는 날짜와 지원 범위 밖 입력을 구분해 안내한다.
- 음력 입력은 해당 달력 기준으로 검증하며, 양력 날짜 검증을 그대로 적용하지 않는다.
- 한국 출생자 지원 범위를 입력 화면에 표시한다. 1900년 이후 대한민국 출생을 지원하고 역사적 표준시·서머타임을 반영한다. 진태양시 보정은 적용하지 않으며 모호하거나 존재하지 않는 시각은 임의 계산하지 않는다.
- 출생 시각을 모르는 경우 임의의 시각으로 결과를 만들지 않는다. v1은 시각을 입력하기 전에는 계산을 진행하지 않고 그 이유를 안내한다. 시각 미상 명반은 제공하지 않는다.
- 제출 중 중복 제출을 방지한다.
- 실패 후 입력 수정으로 돌아오면 현재 세션의 입력값을 유지한다.
- 수집 목적, 저장 여부, 외부 해석 처리에 관한 안내를 입력 시점에 제공한다. 보관 기간과 구체적 문구는 정책 확정 후 작성한다.

### REQ-02 — 로딩

- 유효한 입력 제출 후, 결과가 준비되기 전까지 전용 로딩 화면을 표시한다.
- 실제 작업 상태에 따라 계산·해석 생성 진행을 안내한다.
- 임의의 진행률이나 연출을 위한 최소 대기 시간을 두지 않는다.
- 해석까지 준비된 성공 결과는 간편 결과로 이동한다.
- 계산 오류, 생성 오류, 네트워크 오류를 구분해 사용자가 할 수 있는 다음 행동을 제공한다.
- 새로고침이나 중복 요청으로 불필요한 생성이 반복되지 않도록 한다.
- 장시간 처리·중단 상태는 무한 로딩으로 남기지 않는다. 제한 시간은 배포 환경과 실제 측정 후 결정한다.

### REQ-03 / REQ-05 — 간편 결과

- 보기 모드를 지정하지 않은 첫 진입은 간편 결과다.
- 간소화된 명반이 먼저 나오고, 해석은 그 하단에 나온다.
- 간소화 명반은 12궁의 구조를 유지하고 주요 정보를 우선 표시하는 안이다.
- 명궁·신궁, 주성 등 구체적인 표시 목록은 계산 검증 후 확정한다.
- 해석은 요약과 주제별 본문으로 구분하는 안이다. 주제 후보는 성향, 일과 강점, 관계, 재물이다.
- 상세 명반으로 이동해도 동일한 명반·해석을 사용하며 재생성하지 않는다.
- 결과 조회와 탭 전환에는 AI 생성 비용이 발생하지 않는 구조로 만든다.

### REQ-04 — 상세 명반

- 간편 결과와 동일한 계산 결과에 기반한다.
- 지원하기로 확정한 보조성·사화·천간지지 등 세부 정보를 제공한다.
- 정보가 많다는 이유로 명반 전체를 일괄 축소해 내용을 읽기 어렵게 만들지 않는다. 모바일 배치는 와이어프레임에서 검증한다.
- 궁·별의 선택 상태와 설명이 시각적으로 연결된다.
- 두 모드에서 동일한 별·궁의 이름과 의미를 사용한다.
- 상세 명반만의 데이터가 누락된 경우 가상의 값으로 채우지 않는다.

### REQ-06 — 공유

사용자는 간편 결과와 상세 결과에 공유 버튼을 제공하도록 확정했다. 아래는 **결과 링크 공유 설계안**이며, 이미지 공유와 전용 SNS SDK는 이번 범위에 포함하지 않는 안이다.

- 간편·상세 결과에서 모두 공유할 수 있다.
- 공유 전에 공개되는 정보를 확인한다.
- 링크를 받은 사람은 생성 당시 저장된 결과를 조회한다. 조회 시 재계산·재생성하지 않는다.
- 현재 보기 모드를 링크에 반영한다. 보기 모드가 없는 링크는 간편 결과를 연다.
- 출생 정보는 기본적으로 공개 조회 응답과 페이지에서 제외한다. 명반·해석 자체는 링크 보유자에게 공개된다는 점을 안내한다.
- 공유용 식별자는 원본 조회·삭제 등 소유자 권한과 구분한다.
- 링크 복사를 제공하고, 지원되는 환경에서 시스템 공유를 제공하는 안이다.
- 공유 해제 후 기존 링크로 결과를 읽을 수 없어야 한다.
- 없는 링크·해제된 링크·만료된 결과를 처리한다. 구체적인 보관·만료 기간은 미결정이다.
- 공유 페이지는 검색 색인을 허용하지 않는 안이다. 색인 제한을 접근 제어로 간주하지 않는다.

### REQ-07 — 전문용어 설명

- 명반과 해석의 전문용어가 동일한 용어집을 사용한다.
- 데스크톱에서 hover·키보드 focus로, 터치 환경에서 클릭으로 설명에 접근할 수 있다.
- 클릭으로 열린 설명은 바깥 클릭 또는 Esc로 닫는다.
- 색상만으로 설명 가능 여부를 구분하지 않는다.
- 설명은 용어의 뜻과 화면에서의 의미를 짧은 한국어로 제공한다.
- 열린 설명이 화면 밖으로 잘리거나 본문 탐색을 방해하지 않도록 한다.
- 링크 등 상호작용 콘텐츠가 들어가면 포커스를 지원하는 팝오버 패턴을 사용한다.

## 4. 계산과 해석 품질

- 초기 계산 엔진은 iztro를 사용하고, 추후 필요한 명반 기능을 TypeScript로 직접 구현한다(사용자 확정). 한국 음력 입력은 실제 양력 생일로 변환해 초기 엔진의 달력으로 배치한다. [엔진·계산 정책](decisions/0003-engine-and-calculation-policy.md)에 구현 기준과 남은 검증을 기록한다.
- 달력, 출생 시각, 윤달, 자시, 사화 등 계산 정책을 기록한다.
- 일반·경계 사례를 출처와 설정이 있는 기준 명반으로 검증한다.
- 같은 엔진을 사용하는 서비스와의 일치만으로 독립 검증을 완료하지 않는다.
- 검증하는 정확성은 채택한 계산 규칙의 일관성이다.
- AI 개인화 해석은 설계안이다. AI는 명반 배치를 계산하지 않고 계산된 구조와 검토된 해석 근거를 설명한다.
- AI 응답은 서버에서 구조 검증하고, 존재하지 않는 궁·별 인용을 확인한다.
- 구조 검증만으로 해석 내용의 품질이 보장된다고 간주하지 않는다. 별도 사례 평가가 필요하다.
- 생성 실패를 정상적인 개인화 풀이처럼 표시하지 않는다.
- 근거 없는 수치 점수나 미래 사건을 확정하는 표현을 사용하지 않는 방향으로 콘텐츠를 검토한다.
- 개발 중 예시 데이터는 명시적으로 구분하며 실제 생성 경로의 대체 결과로 사용하지 않는다.

## 5. 운영·접근성 기준

- 모바일을 우선 설계하고 데스크톱·키보드 조작을 함께 검증한다.
- 탭, 입력 오류, 로딩 상태, 용어 설명의 접근성을 확인한다.
- 서버 키를 클라이언트 번들에 포함하지 않는다.
- 원본 결과와 공개 공유 데이터의 접근 권한을 분리한다.
- 출생 정보를 URL·공유 메타데이터·분석 이벤트·일반 오류 로그에 넣지 않는다.
- 결과별 데이터가 타인에게 전달되는 캐시 설정을 피한다.
- 생성 요청의 중복 방지, 호출 제한, 비용·실패 관측을 제공한다.
- 생성 완료율, 단계별 실패율, 생성 시간과 생성당 비용을 측정한다. 각 항목의 목표치는 초기 측정 후 정한다.

## 6. 이번 출시에서 제외하는 안

회원가입 화면, 결제, 대운·세운·월운, 궁합, 자유 대화형 상담, 이미지 다운로드, 다국어 UI와 별도 관리자 웹 앱은 이번 출시에서 제외하는 안이다.

로그인 화면이 없어도 비회원 결과 소유권과 삭제·공유 해제 권한은 필요하다. 익명 인증 등 구체적인 구현 방식은 별도 결정한다.

## 8. 출시 수용 시나리오

1. 유효한 출생 정보를 입력하면 로딩을 거쳐 간편 명반과 해석이 표시된다.
2. 상세 탭으로 이동해도 동일한 결과이며 AI를 다시 호출하지 않는다.
3. 전문용어를 마우스·터치·키보드로 확인하고 닫을 수 있다.
4. 두 탭에서 공유한 링크가 다른 브라우저에서 지정한 보기 모드로 열린다.
5. 공유 페이지의 네트워크 응답에 비공개 출생 정보와 소유자 자격 증명이 포함되지 않는다.
6. 실패·재시도·새로고침·중복 제출 시 결과 상태와 생성 비용이 통제된다.
7. 공유 해제 또는 결과 삭제 후 해당 공유 링크가 더 이상 결과를 제공하지 않는다.
8. 기준 명반 테스트가 통과하며 채택 정책과 불일치가 설명되지 않은 상태로 출시하지 않는다.

## 9. 작업 종료 전 점검과 변경 기록

매 작업 종료 전에 관련 요구사항·수용 기준과 실제 변경을 대조한다. 이유 없는 차이는 구현을 요구사항에 맞게 수정한다. 수행 불가로 방향을 바꾼 경우에는 아래에 기존 요구사항, 수행 불가 이유와 근거, 변경 전후 방향, 영향 범위와 결정 상태를 기록한다. 구현에 맞춰 요구사항을 소급 축소하지 않는다. 상세 절차는 루트 `AGENTS.md`를 따른다.

아래 기록은 각 작업이 끝났을 당시의 상태를 보존한다. 뒤의 기록에서 결정이 바뀌었다면 해당 후속 결정을 따른다. 과거의 보류나 미구현 표현을 현재 상태로 해석하지 않는다.

- **사용자 확정 변경**: 첫 출시 지원 범위를 한국 출생자로 정하여 REQ-10과 입력 화면 안내에 반영했다. 지원 연도·시간 보정·명반 계산 달력은 여전히 미결정이다.
- **기술 검토 방향**: iztro 우선 검증에서 달력 적합성 확인 후 운영 채택 보류로 진행했다. 한국·중국의 2012년 음력 4월 8일 변환 날짜가 서로 다른 사례를 재현했다. 이는 한국 음력 기반 계산을 현재 후보에 그대로 맡길 수 없다는 근거이며, 한국 출생자 지원 자체가 불가능하다는 뜻은 아니다.

- **점검 결과**: 이번 변경에서 이유 없이 달라진 제품 구현은 발견하지 못했다. 입력·로딩·결과·용어 설명·공유는 후속 미구현 항목이며 삭제하거나 수용 완료로 처리하지 않는다. 요구사항 수행 불가를 이유로 확정 기능을 변경한 사례는 없다.

REQ-01·10을 유지하면서 한국 음력 입력을 실제 양력 생일로 변환해 iztro로 계산하는 A안과, 한국 음력의 월·일을 배치에 사용하는 B안을 비교했다. A안은 같은 생일의 양력·한국 음력 입력 일관성을 확인했지만 한국 음력 기반 별 배치를 제공하는 안은 아니다. B안은 현재 iztro 공개 API만으로 구현할 수 없어 소스 수정 또는 다른 엔진 검증이 필요하다.

- 관련 항목: 4절, OPEN-02, 출시 시나리오 8. 기존 기준은 독립 명반 검증 및 설명되지 않은 정책 불일치 없이 출시하는 것이다.

### 2026-09-11 — 입력 문구와 간편·상세 명반 구현

REQ-01·03·04·05·07·08·09·10에 따라 입력 안내를 다듬고, 간편·상세 명반 전환과 궁 선택, 공통 용어 설명을 연결한다. 첫 계산 결과는 간편 명반으로 표시하며 탭 전환에는 기존 계산 결과를 재사용한다. 보기 모드만 URL에 기록하고 출생 정보는 포함하지 않는다. 새로고침 후 복원은 저장·소유권 설계 이후의 작업으로 유지한다.

OPEN-04의 이번 구현 범위는 다음과 같이 선정했다. 간편 화면은 12궁의 이름, 14주성, 신궁과 오행국을 표시한다. 상세 화면은 선택한 궁의 간지, 별의 한자 이름, 사화를 추가한다. 표시할 별은 기존 대조 범위인 14주성과 보조성 16개(좌보·우필·문곡·문창·타라·록존·경양·천괴·천월(天鉞)·천관·천복·삼태·팔좌·은광·천귀·천재), 그리고 사용자 결정으로 iztro를 따르는 화성·령성이다. 밝기와 나머지 별은 독립 검증과 설명 검토 후 추가한다. 이 목록은 검증 범위에 맞춘 구현 결정이며, 사용자가 개별 지정한 목록이나 최종 출시 범위로 취급하지 않는다.

용어 설명은 hover·클릭·키보드 포커스로 열고 Esc·바깥 클릭·닫기 버튼으로 닫도록 구현한다. 출처 링크가 있으므로 포커스를 지원하는 팝오버를 사용한다. 명반 아래의 공통 읽는 법은 개인화 해석을 대체하지 않는다. 공유 버튼과 공개 링크, 영속 결과 경로, 장시간 작업 복구, 전체 독립 검증은 미완료 상태로 유지한다. 요구사항 수행 불가에 따른 기능 축소나 계산 정책 변경은 없다. [작업 기록](tasks/2026-09-11-chart-result-ui.md)에 근거와 검증 결과를 기록한다.

### 2026-09-11 — 중국풍 디자인과 피그마 기준 구현

사용자 요청으로 중국 전통의 느낌을 살린 시각 디자인을 적용한다. 지정한 [피그마 파일](https://www.figma.com/design/VyoZh5i11OisRmKGgw06qg/)에서 먼저 입력·로딩·간편·상세 화면의 데스크톱·모바일 디자인을 구성하고, 이를 기준으로 페이지를 수정한다. 종이색·먹색·주홍색과 명조체를 사용하며, 사용자 안내와 입력 라벨은 한국어로 유지한다.

### 2026-09-11 — 규칙 기반 기본 풀이

사용자는 규칙 기반 기본 풀이부터 구현하고, 이후 검토된 근거를 AI가 설명하도록 확장하는 방향을 승인했다. AI 제공자와 모델은 미정이다. [ADR-0004](decisions/0004-rule-based-interpretation.md)에 결정과 후속 조건을 기록한다.

REQ-03·05·07의 첫 풀이 범위로 명궁 주성의 기본 의미를 명반 아래에 제공한다. 기본 풀이의 성찰 질문은 2026-09-12 사용자 요청에 따라 제거했다. 근거가 된 궁의 위치·별과 출처를 확인할 수 있다. 서버에서 한 번 만든 풀이를 명반과 함께 전달하고 탭 전환 시 재사용한다. 저장·외부 AI 전송은 없다.

주성이 함께 놓이면 개별 의미만 표시하고 조합 풀이와 구분한다. 주성이 없는 명궁의 성향 풀이는 이번 범위에서 제공하지 않는다. 다른 궁·보조성·사화·밝기를 종합한 해석과 일·관계·재물의 주제별 풀이는 후속 구현으로 남긴다. 이는 단계별 구현 범위이며 기존 해석 요구사항의 축소나 전체 출시 수용 완료가 아니다. 규칙과 문장의 출처 대조를 독립적인 전문가 품질 검증으로 취급하지 않는다.

계산 정책과 표시 별, 입력·상세·용어 설명 기능은 유지한다. 수행 불가로 요구사항을 변경한 항목은 없다. [작업 기록](tasks/2026-09-11-interpretation-design.md)에 실제 검증 범위와 남은 작업을 기록한다.

### 2026-09-11 — AI 설명 연결

사용자는 규칙 기반에 더해 AI 설명까지 구현하도록 요청했다. REQ-01·02·03·05·07과 OPEN-05의 이번 구현은 OpenAI가 기존 명궁 주성의 기본 의미를 풀어 쓰는 범위다. 새로운 조합·주제별 운세를 생성하도록 범위를 넓히지 않는다.

입력 화면에서 AI 설명을 선택할 수 있고 기본값은 미선택이다. 선택하면 명반·기본 풀이·AI 설명의 준비를 기다린 후 간편 결과를 보여준다. AI 실패 시 기본 풀이와 실패 안내를 표시하고, 일시적 오류는 명시적인 재시도를 제공한다. 키 미설정·인증 오류는 사용자가 반복 재시도해 해결할 수 있는 오류로 표시하지 않는다. 주성이 없는 명궁은 AI 호출 없이 미지원 안내를 제공한다.

OpenAI로 보내는 항목은 서버가 선택한 규칙 ID·주성 이름·기본 의미다. 원본 날짜·시각·성별, 명궁 위치·전체 명반과 자유 입력은 전송하지 않는다. 입력 화면에서 외부 처리와 보관 가능성을 고지한다. 이 서비스는 결과를 저장하지 않는다. 제공자 측 부정 사용 모니터링 보관까지 없다고 안내하지 않는다.

탭 전환에는 같은 결과를 사용한다. 재시도는 브라우저 메모리에 보관한 직전 제출값을 서버에서 다시 검증·계산하고 AI를 재요청하며, 화면의 기존 명반·기본 풀이는 유지한다. 저장된 작업을 복원하는 기능은 아니다. 새로고침 후 복구·공유·전체 풀이 검증은 여전히 후속 항목이다.

실제 API 키가 없어 모델 실호출과 한국어 품질·의미적 근거 충실성 검증은 완료하지 못했다. SDK 전송·응답 검증과 모의 제공자 기반 UI 검증은 실호출 검증과 구분한다. 요구사항을 줄여 완료로 취급하지 않는다. [작업 기록](tasks/2026-09-11-ai-explanation.md)에 제약과 다음 확인 사항을 남긴다.

### 2026-09-11 — 사용자 상세 상담 프롬프트 적용

사용자의 명시적 요청으로 AI를 ‘기본 규칙 문장 재서술’에서 ‘서버 본명반을 근거로 한 12단계 상담 해석’으로 변경한다. 첨부 원문을 보존하고 서비스 입력·출력 규칙만 별도로 덧붙인다. 원문이 캡처본을 전제하는 부분은 실제 이미지가 없는 서비스에서 서버 JSON 근거를 사용하도록 명시한다.

외부 전송 범위는 12궁의 위치·간지, 명궁·신궁·오행국, 기존 표시 범위의 별·생년사화와 궁의 연결 관계로 확대하며 입력 화면에 고지한다. 원본 출생 날짜·시각·성별은 보내지 않는다. 기존 검증 밖의 별·밝기, 대한·유년·유월·자화·비화·격국 판정은 미제공으로 유지한다.

12단계 구성과 문단별 근거·용어·해석·생활 점검을 제공한다. 시기 자료가 없는 평생 흐름·대한·유년은 분석 문단을 만들지 않고 필요한 자료를 명시한다. 다른 단계도 제한된 본명반 분석이며 모델 해석을 검증된 규칙이나 실제 사건으로 확정하지 않는다. 상세 설명을 위해 요청 제한은 90초, 출력 상한은 16,000토큰으로 변경한다.

프롬프트의 모든 분야를 충분히 검증했다고 선언하지 않는다. 시기별 산출·독립 검증과 실제 모델의 의미적 품질 평가는 아직 수행하지 못했다. 기존 요구사항을 줄이는 대신 수행 범위를 명시하며 [작업 문서](tasks/2026-09-11-user-consultation-prompt.md)에 변경 이유와 한계를 기록한다.

### 2026-09-11 — 키 설정 후 실제 호출 확인

키 설정과 서버 반영을 확인했으나 실제 호출은 HTTP 429, `credit_balance_exhausted`로 거부됐다. API 크레딧 충전 전에는 정상 생성과 해석 품질을 검증할 수 없다. 명반·기본 풀이가 유지되는 실패 경로는 실제 브라우저에서 확인했다. 현재 429 안내는 크레딧 부족과 일시적인 호출 제한을 구분하지 않는 한계가 있다. 요구사항은 유지하며 정상 생성 검증을 완료로 취급하지 않는다. [후속 검증 기록](tasks/2026-09-11-user-consultation-prompt.md)에 원인과 남은 확인 사항을 기록했다.

### 2026-09-11 — 실제 호출 검증과 한도 오류 구분

사용자는 실제 생성 검증과 오류 보완을 승인하고 유료 호출을 필요한 경우에만 하도록 요청했다. REQ-02의 원인별 안내에 맞춰 크레딧 부족·조직/프로젝트 지출 제한·조직 사용량 제한과 insufficient_quota 유형을 일시적인 속도 제한과 구분한다. 운영자의 조치가 필요한 경우 재시도 버튼을 제공하지 않고 기본 풀이를 유지한다. 자동 재시도 0회와 기존 입력·계산·해석 범위를 유지한다. [작업 기록](tasks/2026-09-11-ai-live-verification.md)에 실제 검증과 한계를 기록한다.

후속 실호출 2회 중 최초 응답은 근거 중복·미지원 ID와 단계 내용 오류로 거부됐다. 검증 기준을 유지하면서 생성 스키마에 실제 근거 ID enum을 적용하고 단계별 주제를 명시한 user-consultation-v2로 수정했다. 두 번째 응답은 구조 검증을 통과했고 실제 명반 배치와 핵심 위치 서술을 대조했다. 전체 해석의 의미적 품질과 다양한 사례 검증은 완료하지 않았으며, 일부 단정적인 표현과 별의 의미 설명은 추가 검토가 필요하다. 사용자 원문은 보존했다.

### 2026-09-11 — 명반 보충 자료와 올해 유년

사용자는 부족한 해석 자료를 보충하고 유년은 올해부터 제공하며 유월은 후속으로 진행하도록 결정했다. 명주·신주·표시 별의 밝기, 전체 대한의 나이·연도 구간과 진행 방향·12궁 배치·사화, 한국 시간 기준 올해 유년의 명궁·12궁 배치·사화를 추가한다. 기존 iztro 2.6.1 계산 규칙을 사용하며 운한 자료 계약을 iztro-timing-v1로 명시한다.

유년의 올해는 Asia/Seoul의 양력 연도로 선택하고 해당 이름의 iztro 음력 연도 전체를 분석한다. 연도 경계는 iztro 음력 정월 초하루이며 한국 음력이나 양력 1월 1일과 같다고 안내하지 않는다. 대한의 나이는 엔진 음력 연도 차이+1로, 만 나이가 아니다. 대한 시작 이전·마지막 구간 이후는 임의 계산하지 않는다.

기존 3·10·11단계의 자료 부족에 따른 분석 금지는 보충된 대한·올해 유년 ID 검증으로 대체한다. 사용자 프롬프트 원문은 보존한다. 원본 출생 정보와 이미지는 추가 제출 자료가 아니라 외부 전송 제외·서버 JSON 대체 항목으로 구분한다. 대한의 나이·연도 구간으로 출생 연도를 추정할 수 있다는 점을 입력 시 고지한다.

유월은 명시적으로 후속이다. 자화·비화·격국과 추가 성요·유요는 엔진에 기능이 없어서가 아니라 해석 기준·표시·독립 대조가 끝나지 않아 미완료로 유지한다. 이번 보충을 전체 해석 검증이나 출시 수용 완료로 취급하지 않는다. 실제 AI 호출 없이 전송·계산·화면을 검증하며 [작업 기록](tasks/2026-09-11-supplemental-chart-evidence.md)에 세부 근거와 한계를 기록한다.

### 2026-09-12 — 해석 근거 확장

사용자가 포맷 경고 정리·해석 확장·AI 검증을 요청했고, 유월 범위를 올해 전체 월별 흐름(윤달 포함)으로 확정했다. 앞선 유월 보류를 해제한다. 기존 12단계 중 11단계에서 모든 유월 구간을 묶어 해석하고, 사용한 올해 유년 및 모든 유월 ID를 검증한다. 원본 상담 프롬프트는 그대로 유지한다.

운한 자료는 iztro-timing-v2로 확장한다. monthlyList(year, true)의 음력 월·일 구간, 윤달 전반·후반, 명궁·12궁 배치·사화와 운한별 유요를 제공한다. 2026년은 평달 12개이며 윤달이 있는 해는 전반·후반을 별도로 표시한다. 본명반의 23시 처리 정책과 별개로 유월 목록은 엔진이 사용하는 출생 시지와 대표일(1일·16일)의 산출 규칙을 따른다. 한국 음력 월·일이나 양력 날짜로 바꾸어 안내하지 않는다.

본명반 12궁의 궁간 사화 48개 관계를 제공하고 출발·도착 궁이 같은 경우에만 자화로 표시한다. 운한 궁간 비화·연쇄 비화는 구현 범위에 포함하지 않는다. 천마·지공·지겁·홍란·천희·천요·함지를 추가해 표시 성요를 39개로 늘린다. 대한·유월은 각 10개, 유년은 해신을 포함한 11개 유요를 별도 층으로 제공한다.

격국은 학파마다 성립 조건이 다르고 전체 판정 규칙을 검증하지 못했으므로, 자부동궁·자부협명의 명궁 배치 조건 검사로 한정한다. 조건과 출처, 일치·불일치를 보여주며 길흉·성패 판정이나 다른 격국이 없다는 결론으로 확대하지 않는다. 다른 격국·잡요·신살은 미완료로 남긴다. 이는 사용자 요청을 전체 격국 검증 완료로 간주하지 않기 위한 범위 제한이다.

입력 안내와 결과 근거 표·툴팁을 같은 범위로 갱신한다. AI는 명시적으로 선택했을 때만 호출하며, 저장하지 않는 정책·기본 풀이·공유 미구현 상태는 유지한다. 검증과 미검증 범위는 [작업 기록](tasks/2026-09-12-interpretation-expansion.md)에 기록한다.

실호출 2건을 검토한 결과, 첫 응답의 유월 부재 모순·내부 ID 노출은 v5 지침과 회귀 검사를 보완했다. 두 번째 응답은 3월 누락으로 거부됐다. 모든 월의 해석을 제공한다는 기준은 유지하며, 누락된 응답을 정상 결과로 표시하거나 임의 보충하지 않는다. 확장 기능의 연결과 오류 차단은 구현했지만 AI 의미 품질과 출시 수용 기준은 아직 통과하지 못했다.

### 2026-09-12 — AI 품질 개선 1~3단계

사용자 승인에 따라 월별 출력 구조, 서버 표시 책임, 고정 평가 사례를 정비한다. 앞선 자유 문단 안의 유월 설명은 실제 월 구간 ID를 키로 갖는 필수 객체로 변경한다. 평달·윤달 전반·후반마다 용어 설명·해석·생활 점검을 요구하고 서버의 시간 순서로 표시한다. 11단계에는 올해 유년 개요와 각 유월 해석을 함께 배치한다. 월 누락 기준을 낮추거나 임의로 해석을 채우지 않는다.

12단계 중 1단계는 서버가 생성하는 명반 판독 요약으로 확정한다. 명궁·신궁·명주·신주·오행국, 별 배치와 밝기·사화, 운한 구간·궁간 사화·격국 구조 조건, 계산 기준과 제공 범위 및 근거 제목은 서버 계산 자료로 표시한다. AI는 2~12단계의 의미 해석과 점검 내용을 작성한다. 계산 자료는 AI 미선택·실패 시에도 확인할 수 있으며 사용자 원문 프롬프트는 보존한다.

6개 고정 사례와 평가 기준을 마련했다. 자동 구조·참조 검사의 통과를 해석의 정확성으로 간주하지 않는다. v6 실호출 1회에서는 12개월 필수 항목이 모두 생성됐으나 내부 ID 노출로 응답이 거부됐고, 별도 내용 대조에서 대한·유년의 배치 혼동도 확인했다. 따라서 전체 AI 품질 및 출시 수용 기준은 여전히 미통과다. 이번 변경은 계산 사실의 표시와 누락 방지·평가 체계를 개선한 것이며, 의미 오류가 모두 해결됐다고 보고하지 않는다. 모델 비교는 이번 범위에서 제외한다. [작업 기록](tasks/2026-09-12-ai-quality-structure.md)과 [평가 기준](ai-quality-evaluation.md)을 따른다.

### 2026-09-12 — 일반 사용자를 위한 쉬운 해석 문장

사용자 요청에 따라 AI는 전문 용어를 필요한 경우에만 쓰고 처음 등장할 때 문장 안에서 쉬운 말로 설명한다. 기본 풀이도 생활 속 태도를 먼저 보여주며 별 이름은 해석 근거로 구분한다. 주요 별이 없거나 둘인 경우의 안내도 쉬운 문장으로 제공한다. 기존 명궁 주요 별의 기본 의미라는 범위와 근거·출처·용어 설명은 유지하며 예시의 종합 해석으로 범위를 확장하지 않는다. [작업 기록](tasks/2026-09-12-reading-plain-language.md)을 참고한다.

### 2026-09-12 — 기본 풀이 내용 확장과 질문 제거

사용자 요청에 따라 기본 풀이의 14개 별 설명에 성향·강점·주의점을 보충하고 제목을 ‘~하는 사람’ 형태로 표시한다. 명궁 주요 별의 기본 특성을 설명하는 범위는 유지하며, 사화·밝기·다른 별의 조합이 있어야 성립하는 설명은 단일 별의 성향으로 일반화하지 않는다. 제목은 성격을 확정하는 판단이 아님을 안내한다.

기존 성찰 질문은 사용자가 불필요하다고 판단하여 데이터·반환 타입·화면에서 제거한다. 수행 불가에 따른 축소가 아니라 명시적인 요구 변경이다. AI 해석의 생활 점검 항목은 이번 제거 범위가 아니다. 원문은 iztro의 단일 별 특성 절과 대조하고 출처·라이선스를 기록한다. [작업 기록](tasks/2026-09-12-basic-reading-expansion.md)을 참고한다.

### 2026-09-12 — AI 기본 생성과 Vercel 배포

사용자 요청에 따라 AI 선택 체크박스 영역을 제거하고 기본적으로 해석을 생성한다. 기존 includeAi 값은 유지하며 서버의 AI_EXPLANATION_ENABLED=false로 호출을 중단할 수 있다. 서버 플래그가 꺼지면 클라이언트 요청으로 활성화할 수 없다. 외부 전송과 보관 범위 안내는 입력 하단에 유지한다. 이는 기존 선택 정책에 대한 사용자 승인 변경이며 생성 실패를 정상 해석으로 표시하지 않는 요구는 유지한다.

AI 입력에서 본명반·운한 궁의 위치 대응을 서버가 명시하고 사화 문장에 대한 계산값 대조를 추가한다. 모델은 유지하고 low 추론을 사용한다. SDK 제한은 150초, 배포 함수 제한은 180초로 설정하며 자동 재시도는 하지 않는다. Vercel 프로젝트를 GitHub 저장소와 연결해 배포한다. 공유·저장·전체 해석 품질 수용은 이번 배포와 별도로 남긴다. [작업 기록](tasks/2026-09-12-ai-grounding-vercel.md)에 실제 결과와 한계를 기록한다.

보완한 mini v10의 실제 기준 사례에서는 유년 사화 네 쌍과 본명반 궁이 계산값과 일치했다. 다만 대한의 위치 서술과 단정적인 해석 문장이 남아 전체 의미 품질·출시 수용 기준은 미통과로 유지한다. Vercel 연결·배포는 검증용 서비스 공개이며 전체 해석 검증 완료를 뜻하지 않는다. 상세 결과는 해당 작업 기록에 남긴다.

### 2026-09-12 — main 자동 배포

사용자 요청에 따라 main push 시 GitHub Actions의 포맷·린트·타입·테스트·빌드 검증이 모두 성공하면 같은 커밋을 Vercel production에 배포한다. PR은 검증만 수행한다. main의 Vercel Git 자동 배포는 꺼서 Actions와 중복 실행되지 않도록 한다. 배포는 기존 운영 프로젝트와 환경변수를 사용하며 실제 AI 호출은 CI 검증에서 제외한다. GitHub Actions용 VERCEL_TOKEN 등록이 필요하고, 등록·push·첫 실행 검증 전에는 자동 배포 활성화 완료로 보고하지 않는다. [작업 기록](tasks/2026-09-12-main-auto-deployment.md)을 참고한다.
