# 별 설명 편집·검수·발행

관리 위치: Supabase 프로젝트 zi-wei-dou-shu → Table Editor → star_content.

## 저장 항목

- star_key: 엔진 분류와 별 이름. 예: major:자미. 동명이성을 구분한다.
- locale·version: 번역 언어와 설명 버전. 같은 별·언어·버전은 중복할 수 없다.
- source_url·source_version·source_text: 원문 주소, iztro-docs Git 커밋, 번역에 사용한 원문 구간. 최신 원문을 자동으로 덮어쓰지 않는다.
- translation·translation_kind: 한국어 설명과 adaptation(편집 설명) 또는 full_translation(전체 번역)의 구분.
- status: draft → reviewed → published → archived.
- reviewed_by·review_notes·reviewed_at: 실제 검수자, 확인 범위와 한계, 검수 시각.
- published_at: 발행 시각. 서비스는 발행된 행만 읽는다.
- license: 원저작자와 라이선스 고지. THIRD_PARTY_NOTICES.md의 전문도 유지한다.

초기 39개는 Codex가 원문과 대조한 편집 설명이다. 전문가 검수나 원문 전체 직역이 아니다. source_version은 431611d05ef5f910f936c3d4c32aec7de2027d96이다.

## 수정과 검수

1. 새 설명은 draft로 추가한다. 발행된 설명은 직접 수정할 수 없으므로 새 버전으로 복사한다.
2. 원문 버전·해당 구간과 번역문을 함께 확인한다. 수정 후에는 뜻의 누락·과장, 궁·별 적용 범위, 일반인이 읽기 쉬운 문장인지 검토한다.
3. 실제 검수자의 이름과 review_notes를 적고 status를 reviewed로 변경한다. 검수 시각은 DB가 기록한다.
4. 검수 후 내용을 다시 수정하려면 status를 draft로 돌린다. 이전 검수 기록은 초기화되므로 다시 검수한다. 이전 발행본은 새 버전 발행 전까지 계속 제공된다.

## 발행

검수된 행의 id를 확인한 뒤 SQL Editor에서 발행 함수를 호출한다. 아래 42는 실제 대상 id로 바꾼다. 함수가 기존 발행본 보관과 새 버전 발행을 한 트랜잭션으로 수행한다. 없는 id나 미검수 행이면 기존 발행본을 유지한 채 실패한다.

```sql
select public.publish_star_content(42);
```

별·언어당 발행본은 하나이며 검수되지 않은 행은 발행할 수 없다. 발행 당시 내용과 검수 기록은 수정할 수 없다. 잘못된 발행을 되돌리려면 이전 내용을 새 초안으로 복사해 검수·발행한다. 이력 행을 삭제하지 않는다.

## 공개 범위와 반영 시점

일반 사용자와 일반 로그인 사용자는 발행본의 공개 필드만 조회할 수 있고 편집할 수 없다. 원문 구간과 검수자·검수 메모는 공개하지 않는다. 관리 작업은 Supabase 프로젝트에 접근 권한이 있는 운영자가 수행한다.

페이지를 새로 열면 최신 발행본을 읽는다. 이미 열린 결과는 로드한 버전을 유지한다. DB 조회 실패는 별 설명 불러오기 오류로, 해당 별의 발행본이 없으면 검수 중으로 표시한다. 기존 파일 설명으로 대신하지 않는다. 명반 계산과 기존 규칙 기반 풀이에는 영향을 주지 않는다.

AI에는 같은 요청에서 읽은 발행본만 전달하며 해당 설명 버전도 중복 호출 식별에 반영한다. DB에서 임의 프롬프트나 HTML을 실행하지 않는다.
