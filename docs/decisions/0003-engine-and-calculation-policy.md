# ADR-0003 — 초기 엔진과 계산 정책 v1

작성일: 2026-09-11

상태: **초기 iztro 사용·후속 TypeScript 자체 구현 방향 확정 / 계산 규칙 v1 구현 기준 선정 / 1900년 이후 대한민국 출생·역사적 시간 보정 확정**

## 결정

사용자 지시에 따라 초기 명반 엔진은 설치된 iztro 2.6.1을 사용한다. 추후 서비스에 필요한 명반 기능을 TypeScript로 직접 구현한다. ADR-0002의 엔진 채택 보류를 이 결정으로 대체한다. 달력 차이에 대한 평가 결과는 여전히 유효하며, 엔진 선정이 검증 완료를 뜻하지 않는다.

## 초기 계산 기준

아래 규칙은 엔진 선정에 맞춰 이번 작업에서 정한 구현 기준이다. 사용자가 각각을 개별 지정한 것으로 기록하지 않는다. 경계 검증 전에는 출시 승인 상태가 아니다.

| 항목           | v1 기준                                                                | 이유                                                         |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ |
| 입력 달력      | 양력 또는 한국 음력·윤달                                               | 한국 출생자의 실제 생일 식별                                 |
| 날짜 검증·변환 | korean-lunar-calendar 0.4.0을 사용하고 공식 역서 사례로 검증           | 기존 변환기 재사용, iztro의 관대한 입력 처리에 의존하지 않음 |
| 계산 진입점    | 한국 음력을 실제 양력 날짜로 변환한 뒤 시간 정규화를 거쳐 bySolar 사용 | 같은 생일·시각의 입력 달력에 따른 결과 차이 방지             |
| 명반 배치 달력 | iztro 내장 달력                                                        | 초기 엔진 규칙을 일관되게 사용                               |
| 연도 경계      | yearDivide: normal, 엔진 음력 정월 초하루                              | 초기 버전의 단일 규칙, 입춘 방식과 혼합하지 않음             |
| 자시           | dayDivide: forward, 늦은 자시는 엔진의 다음 날 규칙                    | 엔진 기본 규칙 사용, 앱에서 날짜를 한 번 더 더하지 않음      |
| 윤달 배치      | fixLeap: true                                                          | 엔진의 윤달 분할 규칙 사용; 아래 경계 조건 확인 필수         |
| 배치 알고리즘  | algorithm: default                                                     | 초기 기본 배치 사용                                          |
| 사화·밝기      | 2.6.1 기본표, 사용자 정의표 없음                                       | 규칙·버전 재현 가능, 임의 수정 방지                          |
| 나머지 설정    | ageDivide: normal, horoscopeDivide: normal                             | 실행 설정 고정; 운한 UI 범위 확정을 뜻하지 않음              |
| 표시 언어      | ko-KR                                                                  | 한국어 서비스                                                |
| 시각 미상      | 임의 시각을 넣지 않고 계산 제출 차단·이유 안내                         | 기존 요구사항 준수; 시각 미상 명반은 제공하지 않는 v1 기준   |

00시는 timeIndex 0, 01시부터 02시는 1, …, 21시부터 22시는 11, 23시는 12로 매핑한다. 검증한 시각을 util.timeToIndex에 전달한다. 사용자 입력은 시·분을 받으며 날짜·시각을 서버 시간대로 암묵 변환하지 않는다.

fixLeap의 일반 설명은 윤달 15일까지 해당 월, 16일부터 다음 월이다. 다만 설치 소스 utils/index.js의 fixLunarMonthIndex에는 timeIndex 12 예외가 있다. 따라서 늦은 자시와 윤달이 겹칠 때를 단순한 날짜 설명으로 보장하지 않는다. 해당 조합의 실제 배치가 승인할 기준 명반과 맞는지 확인한 후 연결하며 불일치를 숨기지 않는다.

설정과 언어는 서버 계산 모듈의 단일 기준으로 사용한다. 요청마다 다른 전역 설정·플러그인을 주입하는 API는 만들지 않는다. 사화·밝기 표를 코드에 복제할 필요는 없으며 엔진 버전과 기본표 사용 여부를 기록한다.

## 지원 연도·시간 정책

사용자는 **1900년 이후 대한민국 출생 + 역사적 시간 보정**을 선택했다. 양력으로 환산한 1900-01-01부터 현재 출생 순간까지 지원하며 진태양시 보정은 적용하지 않는다. 지역은 현재 대한민국 영역의 출생을 기준으로 하며 Asia/Pyongyang 등 다른 시간 규칙은 첫 출시 범위에 포함하지 않는다.

선택한 범위의 구체적인 계산 시각 구현 기준은 입력한 현지 민간 시각을 Asia/Seoul의 해당 날짜 규칙으로 해석한 뒤, 동일 순간을 고정 UTC+09:00의 날짜·시각으로 정규화하여 엔진에 전달하는 방식이다. 진태양시·경도 보정은 적용하지 않는다. 이는 서비스가 선택하는 계산 시각 기준이며 유파 공통 정답이 아니다. 단순히 DST만 제거하는 방식과도 구분한다.

중복 시각·존재하지 않는 시각은 자동으로 앞뒤 시각에 맞추지 않고 추가 확인 전 계산을 막는다. 음력 변환 → 현지 날짜·시각 해석 → 계산용 UTC+09:00 날짜·시각 → timeIndex → 엔진 순서를 지킨다. 시각 보정으로 날짜가 바뀌면 바뀐 날짜를 사용하고, 자시 다음 날 처리는 엔진이 한 번만 수행한다. 미래 출생 순간은 거부한다.

IANA tz 자료에는 Asia/Seoul의 과거 UTC+08:30 등 표준시 변경과 1987·1988년을 포함한 DST 규칙이 있다. 특히 오래된 시간 자료의 정확성과 엔진·달력 지원 구간은 별도 검증이 필요하다. 1900년부터의 모든 날짜를 검증했다고 주장하지 않는다.

## 표시와 저장 기준

한국 음력 생일과 엔진 내부 계산용 음력을 구분한다. 사용자 생일에는 한국 음력을 표시한다. 계산 방식 안내에는 iztro 기준 배치라는 점을 표시하고, 내부 음력을 노출한다면 계산용임을 명시한다. 공유 데이터에는 출생 정보를 넣지 않는 기존 기준을 유지한다.

원본 결과에는 엔진 이름·버전, 계산 정책 버전, 실제 계산 결과를 기록한다. v1 정책 식별자는 `ziwei-v1`로 정한다. 엔진 버전과 시간대 데이터 버전도 결과에 기록한다. 규칙 변경은 새 정책 버전으로 구분한다. 새로운 엔진이 생겨도 기존 공유 결과를 조회할 때 재계산하지 않는다.

## 후속 TypeScript 구현

UI·AI·저장 코드가 iztro 기능 객체를 직접 사용하지 않도록 계산 모듈이 서비스에 필요한 데이터만 반환한다. 실제 첫 명반 구현에 필요한 함수·타입만 만들며, 지금 다중 엔진 레지스트리나 폴백·호환 레이어를 만들지 않는다.

후속 구현 순서는 계산 규칙·독립 기준 명반 → 12궁·명궁·신궁·오행국·14주성 → 필요한 보조성·사화·밝기다. 한국 음력 기반 배치로 변경하면 새로운 계산 정책으로 명시한다. 자체 구현의 달력·유파까지 이번 엔진 방향 결정으로 자동 확정하지 않는다.

새 구현이 수용 기준을 충족하면 새 생성 경로를 교체하고 사용하지 않는 iztro 실행 경로를 삭제한다. 기존 결과는 저장된 데이터로 조회한다. 별도 패키지·저장소 생성과 전 기능 이식은 현재 결정에 포함되지 않는다.

## 구현 전 검증 기준

- 한국 음력·양력으로 입력한 같은 생일·시각은 같은 결과를 반환한다. 2012·2017년 달력 차이 사례를 포함한다.
- 실제 날짜·윤달·시각 범위, 입력 실패 시 오류를 검증한다.
- 22:59·23:00·23:59·00:00, 월말·연말, 윤달 15·16일과 늦은 자시 조합을 검증한다.
- 채택한 연도 경계·사화·별 배치를 독립 기준 명반과 대조한다.
- 역사적 시간 변경, DST 중복·누락 시각과 날짜 이동을 검증한다.
- 서로 다른 요청이 전역 설정·언어 변경으로 영향을 받지 않는지 확인한다.

현재 완료 범위는 정책 문서 작성과 기존 1차 평가이며, 위 검증 전체를 통과한 상태가 아니다.

## 독립 대조 후속 상태 (2026-09-11)

[독립 명반 대조](../tasks/2026-09-11-independent-chart-verification.md)에서 평달 기준 명반의 기본 배치는 일치했다. 화령·壬 사화의 출처 차이와 윤달 늦은 자시 예외의 타당성은 미해결이다. 선정한 설정은 유지하며, 공개 계산 연결은 이 문제 해결과 추가 독립 검증 전까지 보류한다. 이는 예외 규칙의 정확성 승인 또는 정책 변경 결정이 아니다.
