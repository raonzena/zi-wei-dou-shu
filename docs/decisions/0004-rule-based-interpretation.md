# ADR-0004: 규칙 기반 기본 풀이부터 제공

- 상태: 단계적 도입 방향 채택
- 결정일: 2026-09-11

## 결정

사용자는 규칙 기반 기본 풀이를 먼저 만들고, 추후 AI가 같은 근거를 설명하는 방식을 추가하는 방향을 승인했다. AI 제공자·모델은 이번에 확정하지 않는다.

현재 단계는 명궁의 주성을 바탕으로 기본 의미를 제공한다. 자기 성찰 질문은 2026-09-12 사용자 요청으로 제거했다. 이 범위는 전체 개인화 해석의 첫 구현이며 일·관계·재물의 종합 풀이 완료를 뜻하지 않는다. 출처의 내용과 적용 조건을 확인하고, 독립적인 해석 품질 검토는 별도로 남긴다.

## 근거

규칙 기반은 적용 근거를 추적하고 같은 결과를 반복 검증하기 쉽다. AI는 설명을 유연하게 구성할 수 있지만 근거를 넘어서는 서술, 비용·지연·외부 데이터 처리와 오류 복구를 추가로 다뤄야 한다. 검토한 규칙과 문장은 추후 AI 설명에도 재사용할 수 있다.

## 구현 범위

- 서버의 검증된 Chart에서 명궁 주성만 선택한다. 원본 출생 정보는 풀이 모듈로 전달하지 않는다.
- 기본 의미·서비스 작성 질문·규칙 식별자는 콘텐츠 파일로 관리한다.
- 생성 결과에는 규칙 버전, 출처, 적용한 궁의 위치와 별, 규칙 식별자를 포함한다.
- 명궁에 주성이 하나면 해당 별의 기본 설명을 제공한다. 여러 개면 개별 의미만 표시하고 조합 해석 미지원임을 알린다는 이 시점의 결정은 2026-09-13 [ADR-0006](0006-two-major-star-combinations.md)로 대체됐다. 주성이 없으면 대궁의 별을 임의로 빌리지 않고 현재 범위에서 성향 해석을 제공하지 않는다는 결정은 [ADR-0005](0005-empty-palace-reading.md)로 대체됐다.
- 풀이와 명반을 하나의 서버 응답으로 전달한다. 브라우저는 탭 전환 때 같은 결과를 사용한다.
- 다른 궁·사화·밝기·보조성을 종합한 해석, 외부 AI, 결과 저장과 공유는 이번 단계에 추가하지 않는다.

범용 규칙 엔진이나 미사용 AI 인터페이스는 만들지 않는다. 규칙 버전은 현재 결과의 근거 추적에 사용하며 호환 계층을 뜻하지 않는다.

## 후속 조건

2026-09-12 후속 사용자 요청으로 상세 명반의 선택한 궁에도 기본 풀이를 제공한다. 브라우저에 이미 전달한 검증된 명반에서 해당 궁의 주성만 선택하여 궁의 생활 맥락과 별의 기본 의미를 표시하며 추가 서버 요청은 하지 않는다. 기존 명궁 기본 풀이 생성 경로는 유지한다. 이는 궁·별 조합이나 여러 궁의 종합 풀이가 아니며, 적용 범위와 검증은 [선택한 궁의 설명과 기본 풀이](../tasks/2026-09-12-selected-palace-reading.md)에 기록한다.

조합·주제별 규칙을 추가할 때 적용 조건과 사례를 검토한다. AI 도입 전에는 제공자·모델·데이터 처리 조건과 근거 이탈 평가를 정한다. 단위 테스트 통과는 점술 해석의 정확성이나 독립적인 전문가 검토를 뜻하지 않는다.

## 후속 결정: AI 설명 연결 (2026-09-11)

사용자의 AI 설명 구현 요청에 따라 OpenAI Responses API와 공식 SDK를 연결한다. 모델은 `gpt-5.4-mini-2026-03-17`을 구현 기준으로 선정했다. 공식 문서의 Responses·Structured Outputs 지원을 확인했으며, 실호출 품질 비교를 끝내고 최적 모델로 확정한 것은 아니다. 설명 범위는 기존 명궁 주성의 기본 의미를 풀어 쓰는 것으로 유지한다.

AI 설명은 입력에서 선택하며 기본값은 미선택이다. 선택 시 결과 표시 전에 생성하고, 실패 시 기본 풀이와 별도의 AI 오류·재시도 UI를 제공한다. 기본 풀이를 AI 성공으로 표시하지 않는다. AI 미선택과 주성 없는 명궁은 외부 호출하지 않는다.

생성에는 규칙 ID·주성 이름·기본 의미만 전송한다. 출생 정보·명궁 위치·전체 명반·사용자 자유 입력은 전달하지 않는다. `store: false`는 제공자 측의 모든 보관을 없애는 설정이 아니므로, 입력 화면에 외부 처리 범위와 제공자 데이터 정책을 안내한다.

스키마·길이·근거 ID의 일치와 누락·중복을 검사한다. 이는 내용의 의미적 충실성을 입증하지 않으며, 키 설정 후 실제 사례 평가가 필요하다. 상세한 구현·운영 제한은 [AI 연결 작업](../tasks/2026-09-11-ai-explanation.md)에 기록한다.

## 후속 결정: 사용자 12단계 상담 프롬프트

사용자가 제공한 전체 프롬프트를 AI 호출에 적용하도록 요청했다. 이를 위해 기본 문장 재서술 제한을 해제하고, 서버의 본명반·표시 범위의 별·생년사화와 삼방사정 근거를 전달한다. 사용자 원문은 보존하며 이미지 대신 서버 JSON을 사용한다는 점과 미제공 자료를 별도 적용 규칙으로 명시한다.

이 변경부터 AI의 종합·분야별 설명은 기존 규칙 콘텐츠의 재서술에 한정되지 않는다. 따라서 규칙에 의해 검증된 해석이라고 표시하지 않으며 실제 사례 평가가 필요하다. 시기 데이터는 제공하지 않아 3·10·11단계의 분석 문단을 금지한다. [작업 기록](../tasks/2026-09-11-user-consultation-prompt.md)에 데이터·화면·요청 한도 변경을 기록했다.

## 2026-09-12 후속 결정 — 서버 사실 표시와 AI 출력 계약

품질 개선 1~~3단계 승인에 따라 user-consultation-v6에서는 1단계 명반 판독 요약과 사실 표시를 서버에 맡긴다. 기존 모델과 추론 설정, 재시도 0회 정책은 유지한다. AI 출력은 2~~12단계 문단과 월별 필수 객체로 제한하며 Zod 및 설치된 OpenAI SDK의 Structured Outputs를 사용한다. 이전 응답 구조의 호환 경로는 두지 않는다.

계산 자료의 날짜·배치·범위·근거 이름은 서버가 구성한다. AI 문장 속 의미적 오류는 스키마만으로 검증할 수 없으므로 고정 사례와 별도 내용 평가를 도입한다. 실호출 1회에서 월 구조는 충족했으나 본문 오류는 남았다. 내용 검증 완료 또는 출시 승인으로 취급하지 않는다. 서버 표시 형식과 검증 결과는 [작업 문서](../tasks/2026-09-12-ai-quality-structure.md), 평가 기준은 [평가 문서](../ai-quality-evaluation.md)에 기록한다.

## 2026-09-12 후속 결정 — 기본 풀이 v3

ming-major-v3는 단일 별 특성의 성향·강점·주의점을 세 문단으로 제공한다. question 필드는 데이터와 전달 타입에서 삭제하고 호환 분기를 두지 않는다. meaning은 문단 사이의 빈 줄을 포함하는 문자열을 유지하며 화면에서 문단별로 표시한다. 제목은 사용자가 요청한 ‘~하는 사람’ 형식으로 바꾼다. AI 출력 계약은 바꾸지 않는다. [원문 대조 및 검증 기록](../tasks/2026-09-12-basic-reading-expansion.md)을 참고한다.

## 2026-09-12 후속 결정 — 유년 사화의 적용 범위 검증

궁간 사화의 유효한 참조가 유년 사화의 올바른 해석을 뜻하지 않음을 실제 실패에서 확인했다. user-consultation-v10은 서버가 연결한 궁·별 위치와 올해 사화의 명시적 목록을 전달하고, 유년 단계에서는 궁간 사화 인용을 차단한다. 언급한 사화 쌍은 해당 운한의 계산값과 대조한다. 이 규칙은 모든 자연어 오류를 검출하는 기능은 아니다.

사용자 지시에 따라 모델은 mini를 유지하고 프롬프트를 우선 보완한다. 추론은 low, 자동 재시도는 0회다. AI 기본 활성화와 서버 비활성화 플래그는 사용자가 승인했으며 Vercel 운영 환경에 반영한다. [원인·검증·배포 기록](../tasks/2026-09-12-ai-grounding-vercel.md)을 참고한다.
