# 화면 흐름

최종 갱신일: 2026-09-12

상태: [확정 요구사항](requirements.md)을 구현하기 위한 현재 화면 흐름과 후속 설계

이 문서는 현재 유효한 화면 동작만 설명한다. 변경 전 흐름은 [작업 기록](tasks/README.md)과 Git 이력에서 확인한다.

## 1. 현재 구현 흐름

```text
출생 정보 입력
  ├─ 입력 오류 → 해당 필드 수정
  └─ 유효한 입력 제출
       ↓
명반 계산·해석 준비
  ├─ 계산 실패 → 원인 안내 / 입력 수정
  ├─ AI 실패 → 기본 풀이 유지 / 조건에 따라 재시도
  └─ 완료 → 종합 풀이 (기본)
               ↕ 탭 전환 — 재계산·재생성 없음
             상세 명반
```

계산 결과를 저장한 뒤 /result/[id]로 이동한다. 새로고침과 링크 방문은 저장된 결과를 복원하며 계산·AI를 다시 호출하지 않는다.

## 2. 결과 경로

| 경로                       | 용도           | 접근 조건                      |
| -------------------------- | -------------- | ------------------------------ |
| `/`                        | 출생 정보 입력 | 원본 입력은 저장하지 않음      |
| `/result/[id]`             | 종합 풀이      | 링크를 아는 누구나 30일간 조회 |
| `/result/[id]?view=detail` | 상세 명반      | 동일한 저장 결과의 보기 전환   |

UUID는 공개 조회 링크의 식별자다. URL에 출생 정보나 소유 자격 증명을 넣지 않는다. AI 재시도는 생성한 브라우저의 소유 쿠키를 확인한다. 쿠키를 지우면 AI 재시도 권한을 복구할 수 없다.

## 3. 출생 정보 입력

입력 화면에는 다음 순서로 정보를 표시한다.

1. 서비스 제목과 1900년 이후 대한민국 출생 지원 안내
2. 생년월일 및 양력·한국 음력 선택
3. 음력 선택 시 윤달 여부
4. 출생 시각과 당시 기록된 현지 시각 입력 안내
5. 계산에 필요한 성별
6. 개인정보, 외부 AI 처리, 운영 기록 보관 안내
7. 결과 보기 버튼

날짜와 시각은 목록 선택과 직접 입력을 지원한다. 성별은 남성이 기본값이며 출생 시각에는 기본값이 없다. 제출 시 클라이언트와 서버 검증을 거쳐 같은 요청에서 명반·기본 풀이·활성화된 AI 해석을 준비한다.

`AI_EXPLANATION_ENABLED=false`이면 외부 AI 호출을 하지 않고 관련 전송 안내를 숨기며 명반과 기본 풀이만 준비한다. 운영은 현재 이 상태다.

## 4. 로딩과 오류

| 상태         | 표시                                     | 다음 상태             |
| ------------ | ---------------------------------------- | --------------------- |
| 명반 계산 중 | 명반을 계산하고 있습니다                 | 해석 준비 / 계산 실패 |
| 해석 준비 중 | 명반을 바탕으로 해석을 작성하고 있습니다 | 완료 / 생성 실패      |
| 완료         | 결과로 이동                              | 종합 풀이             |
| 실패         | 원인에 맞는 안내                         | 재시도 / 입력 수정    |

- 임의 진행률이나 연출을 위한 최소 대기 시간을 표시하지 않는다.
- AI 실패 시 계산한 명반과 기본 풀이는 유지한다.
- 일시적 제공자 오류에만 재시도 버튼을 표시한다. 크레딧·설정·운영 한도 오류에는 반복 재시도를 제공하지 않는다.
- 재시도 중에는 중복 재시도와 입력 수정을 막고 탭 전환은 허용한다.
- 완료된 결과는 URL로 복원한다. 계산 진행 중인 작업과 입력값의 새로고침 복원은 지원하지 않는다.

## 5. 결과 공통 레이아웃

```text
결과 제목
[간편 풀이] [상세 명반]
────────────────────────
선택한 탭의 내용
```

- 첫 결과는 간편 풀이가 선택된다.
- 탭은 선택 상태와 패널 관계를 표현하고 키보드 탐색을 지원한다.
- 보기 모드는 `?view=detail`로 표현하며 없거나 유효하지 않은 값은 종합 풀이로 정규화한다.
- 탭 전환과 브라우저 뒤로·앞으로 이동에는 기존 계산 결과를 사용한다.
- 새 계산 결과는 종합 풀이로 시작하고, 선택한 궁은 탭 전환 시 유지한다.

## 6. 간편 풀이

화면은 다음 순서로 표시한다.

1. 12궁 관계를 유지한 간소화 명반
2. 명궁 주성의 규칙 기반 기본 풀이
3. 열두 궁을 일곱 생활 분야로 구분하되 명궁과 같은 성향 문장은 반복하지 않는 종합 기본 풀이
4. 활성화된 경우 AI 명반 해석
5. 읽기 안내·새 입력으로 이동하는 버튼·공통 계산 기준 안내

간소화 명반은 궁 이름, 주요 별, 명궁·신궁과 오행국을 우선 표시한다. 기본 풀이는 ‘~하는 사람’ 제목과 성향·강점·주의점 세 문단으로 구성하며 성찰 질문은 표시하지 않는다. 주요 별이 없거나 둘인 경우에는 적용 범위를 구분해 안내한다.

종합 풀이의 명반은 궁과 주성의 배치를 표시하며 궁 선택 기능과 선택한 궁의 풀이 영역은 제공하지 않는다. 명궁 주성의 기본 풀이, 일곱 분야 종합 풀이와 활성화된 AI 해석은 유지한다. 일곱 분야의 각 궁은 일반 사용자가 궁금해하는 질문을 제목으로 표시하고, 별 또는 두 별 조합의 실제 성향과 구체적인 생활 장면을 이어서 설명한다. 화면 구조를 해설하는 `이 영역에서는`과 별도의 실천 지시를 본문마다 반복하지 않는다. 명궁 주성의 성향은 기본 풀이에서 한 번만 설명하고, 일곱 분야의 명궁과 명궁을 맞은편 참고 궁으로 쓰는 영역에서는 같은 문장을 다시 표시하지 않는다.

### AI 명반 해석

```text
나의 명반 해석
  전체 요약 1~2문단
  핵심 성향
  일과 커리어
  돈
  관계와 배우자
  내면과 삶의 방향
  건강과 컨디션
  가족·대인관계
  한 줄로 정리하면
```

각 분야는 개인화된 제목과 두 문단, 전체 7~8문장으로 표시하며 필요한 경우에만 짧은 목록을 덧붙인다. 본문에는 명반 근거에서 자연스럽게 이어지는 일상 예시를 최소 한 문장 포함하되 사용자가 실제로 겪은 일처럼 단정하지 않는다. 본문은 전문 용어 없이 성향·생활의 모습을 설명하고 행동 조언은 별도 목록에 모은다. 각 블록 아래 기본으로 접힌 ‘풀이 근거’를 펼치면 제목·문단·조언·마무리별로 사용한 궁·별과 연결 이유를 볼 수 있다. 궁·별 근거에는 ‘이 주제와의 관련성’과 ‘어떻게 해석했나요?’를 표시한다. 조언에는 같은 분야의 어느 문단에서 이어졌는지와 이유를 표시한다. 연결 이유는 본문의 인용문이 아니라 별도 설명이다. 내부 근거 ID는 사용자 문장에 노출하지 않는다.

12단계 펼치기, 용어·해석·생활 점검의 반복 블록, AI가 작성한 대한·유년·유월 해석은 표시하지 않는다.

## 7. 상세 명반

‘○○의 주성 풀이’는 접기 없이 항상 표시한다. 주성이 둘이면 각 별의 의미, 두 별이 함께 만드는 특징, 해당 궁의 생활 영역에서 나타나는 모습 순서로 표시한다. 개별 별 설명의 접기·펴기는 유지한다.

상세 탭에는 다음 내용을 표시한다.

1. 상세 명반
2. 기본적으로 접힌 ‘명반 판독 요약’
3. 선택한 궁의 설명과 기본 풀이
4. 선택한 궁의 간지, 별, 사화 등 검증된 세부 정보
5. 명반을 읽는 방법
6. 구분선 아래 생성 브라우저의 ‘명반 다시 보기’ 또는 방문자의 ‘나도 확인해보기’ 버튼 (둘 다 `/`로 이동)
7. 버튼과 구분선·여백으로 나눈 계산 기준 안내

명반 판독 요약은 서버 계산 자료이며 명궁·신궁·명주·신주·오행국, 궁·별·밝기·사화, 대한·유년·유월과 검증 범위의 확장 근거를 보여준다. AI 해석과 섞거나 종합 풀이 화면에 중복 표시하지 않는다.

궁을 선택하면 ‘이 영역에서 나는 어떤 모습인가요?’ 아래에 `각 별의 의미 → 두 별이 함께 만드는 특징 → 이 조합이 해당 궁에서 나타나는 모습 → 생활에서 활용하는 방법 → 별 목록` 순서로 갱신한다. 주성별 의미, 두 주성 조합, 생활 영역의 모습과 생활 활용은 각각 7~8문장으로 자세히 표시하며 구체적인 생활 예시를 포함한다. 기본 선택은 왼쪽 상단의 궁이다. 주성이 있으면 실제 놓인 주성의 의미만 사용하고, 주성이 없으면 iztro 2.6.1의 대궁 계산 방식으로 찾은 맞은편 궁의 주성을 참고 풀이로 표시한다. 이때 맞은편 궁 이름과 참고한 별을 밝히고 본궁 주성이나 확정적인 종합 해석이 아님을 안내한다. 같은 원칙은 종합 풀이의 명궁 기본 풀이와 일곱 생활 분야에도 적용한다. 종합 풀이에서 주성이 둘이면 하나만 고르거나 개별 의미를 나열하지 않고 두 별 조합의 핵심 특징을 쉬운 말로 간결하게 요약한다. 주성 풀이는 항상 표시하고 개별 별 설명은 기본으로 접혀 있으며 펼치면 내용을 읽을 수 있다. 주성과 보조성은 Supabase의 발행된 한국어 편집 설명·버전·출처를 제공한다. 미발행 설명은 검수 중, 조회 실패는 오류로 표시한다. 이 동작에는 재계산이나 AI 호출이 없다.

## 8. 용어와 근거 상호작용

| 입력 방식 | 열기                         | 닫기                              |
| --------- | ---------------------------- | --------------------------------- |
| 마우스    | 용어 hover 또는 클릭         | hover 영역 이탈 / 바깥 클릭 / Esc |
| 키보드    | 용어 focus, Enter 또는 Space | Esc 또는 focus 이동               |
| 터치      | 용어 탭                      | 바깥 영역 탭 또는 트리거 재선택   |

- 링크나 버튼이 있는 설명은 포커스를 지원하는 popover를 사용한다.
- 명반 근거 목록은 개수를 표시한 접힌 영역으로 제공하고 키보드로 펼칠 수 있다.
- 계산 근거와 사화 나열 같은 보조 문구는 10px로 표시하되 본문과 용어 팝업의 글자 크기는 유지한다.
- 계산 기준 안내는 결과 페이지 하단에 한 번만 표시한다.

## 9. 결과 링크와 보관

1. 입력 전에 공개 범위와 30일 보관을 확인한다.
2. 계산 결과를 저장하고 UUID 경로로 이동한다.
3. 주소를 보관하거나 전달하면 다른 브라우저에서도 같은 결과를 열 수 있다. 상세 탭은 view=detail을 사용한다.
4. 30일이 지나면 조회를 차단하고 정기 작업으로 만료 결과를 삭제한다. 사용자 수동 삭제 기능과 결과 하단 보관 안내는 제공하지 않는다.
5. 만료·없는 결과는 결과 없음 화면을 표시한다. 저장소 장애는 재시도 화면을 표시한다.

두 보기의 공통 하단에는 ‘결과 공유’ 버튼 하나를 표시한다. 다시 보기 버튼과 같은 크기로 맞추고, 태블릿·데스크탑에서는 한 줄에, 모바일(640px 이하)에서는 두 줄에 배치한다. 데스크탑에서는 링크를 바로 복사한다. 태블릿·모바일 및 해당 기기의 앱 내 브라우저에서는 기기 공유를 열고, 미지원 기기에서는 링크를 복사한다. 복사 완료 문구는 4초 동안 토스트로 표시한다. 반복 복사는 같은 토스트를 갱신하고 닫기 버튼을 제공한다. 상세 탭은 view=detail을 포함하고 종합 풀이는 기본 URL을 사용한다. 취소는 조용히 종료하고, 권한 오류나 미지원 복사는 직접 선택할 링크를 표시한다. 별도 공유 해제는 후속 범위다.

## 11. 문서 갱신 원칙

- 이 문서에는 현재 유효한 화면과 상태 전이만 기록한다.
- 새 결정이 기존 흐름과 충돌하면 기존 절을 직접 수정하고 날짜별 후속 절을 추가하지 않는다.
- 변경 전 화면, 결정 이유, 검증 결과는 작업 문서와 Git 이력에서 확인한다.

### 출생 정보 입력 조작

- Brand는 `/`로 이동해 입력 화면을 새로 연다.
- 연도·월·일·시·분 입력 영역을 누르면 선택 목록이 열린다. 직접 입력도 가능하며 연도는 최대 4자리, 나머지는 최대 2자리다.
- 시·분을 입력해야 명반을 계산할 수 있다. 시각 모름 선택은 제공하지 않으며, 출생 시각에 따라 궁과 별의 배치가 달라진다고 안내한다.

### 궁의 최초 선택

- 상세 명반을 처음 열면 명반 도식의 왼쪽 상단(지지 사)에 있는 궁을 선택한다. 이 자리의 궁 이름은 출생 정보에 따라 달라지므로 복덕궁으로 고정하지 않는다. 상세 명반에서 선택한 궁은 탭을 오가도 유지한다.

## 결과 재요청

입력 화면을 열 때 소유 쿠키를 준비한다. 같은 브라우저에서 같은 출생 정보·계산 및 풀이 조건으로 요청하면 아직 유효한 기존 결과 ID로 이동한다. 이름은 입력받지 않는다. 결과 재사용 시 AI를 호출하지 않고 만료일도 연장하지 않는다. 조건이 바뀌거나 결과가 만료됐으면 새 ID를 만든다. 쿠키가 없거나 저장소·HMAC 설정을 사용할 수 없으면 저장 오류를 표시한다.
